# 艾略特波浪指标化方案

## 一、现状分析

### 1.1 ta4j 0.22.6 Elliott Wave 指标套件

ta4j 0.22.6 已提供完整的 Elliott Wave 分析工具链，位于 `org.ta4j.core.indicators.elliott` 包，核心组件包括：

| 类/接口 | 用途 | 是否每 Bar 输出 |
|---------|------|:---:|
| `ElliottPhaseIndicator` | 识别相位：WAVE1~5, WAVE_A~C | 每 Bar 返回枚举 |
| `ElliottChannelIndicator` | 计算价格通道边界 | 每 Bar 返回 `ElliottChannel{upper,lower,median}` |
| `ElliottRatioIndicator` | 斐波那契比率 | 每 Bar 返回 numeric |
| `ElliottConfluenceIndicator` | 聚合得分（支撑/阻力强度） | 每 Bar 返回 numeric |
| `ElliottSwingIndicator` | 摆动点检测 | 每 Bar 返回 swing high/low/ignore |
| `ElliottWaveCountIndicator` | 已识别波浪计数 | 每 Bar 返回 int |
| `ElliottInvalidationIndicator` | 失效信号 | 每 Bar 返回 boolean |
| `ElliottScenarioIndicator` | 基础 + 替代场景 | 每 Bar 返回 `ElliottScenarioSet` |
| `ElliottWaveFacade` | 统一入口，构建上述所有 indicator | - |

关键特点：**所有 Indicator 都实现了 `getValue(int index)`，可遍历每个 Bar 位置获取值**，天然适合作为时间序列指标输出。

### 1.2 我方系统现有实现

**后端 (ai-quant)：**
- `ElliottWaveAnalysisService` -- 调用 `ElliottWaveFacade`，但仅获取 endIndex 的快照值
- `ElliottWaveAnalysisDTO` -- 仅包含当前最新状态的摘要：
  - `currentPhase`、`invalidation`、`confluenceScore`、`waveCount`（均为 endIndex 值）
  - `channel`（endIndex 通道上下轨）
  - `baseScenario` / `alternativeScenarios`（当前场景信息）
- API 路径：`GET /api/member/elliott-wave-analysis`
- 缓存策略：Redis 30s TTL
- **未提供每 Bar 指标序列** 导致前端无法画图

**前端 (ai-frontend-web)：**
- 右侧面板已有 "elliott" 标签（`rightPanelActiveTab`）
- `loadElliottAnalysis()` 调用后端 API，数据存于 `elliottAnalysisData`
- **模板中未渲染任何内容** -- 标签栏有 tab，但无对应展示区域

### 1.3 现有指标渲染模式

前端主图使用 `lightweight-charts` 库，指标渲染分两类：

| 渲染方式 | 适用场景 | 示例 |
|---------|---------|------|
| **Overlay（叠加）** | 价格量级一致的指标画在主图 | SMA, EMA, Bollinger, SMC, LogReg 通道 |
| **Subchart（副图）** | 独立量纲的指标画在下方面板 | RSI, MACD, Volume |

右侧面板渲染分类：

| 面板 | 内容类型 | 渲染方式 |
|------|---------|---------|
| trend | 文本分析 + mini 趋势图 | ECharts 小图 + HTML 详情 |
| elliott | 当前为空 | - |

## 二、目标：艾略特波浪"指标化"

将艾略特波浪从"仅查看 endIndex 快照分析"升级为"可绘制在 K 线图上的指标序列"，具体包括：

### 2.1 可绘制到主图（Overlay）的要素

| 要素 | 数据来源（ta4j Indicator） | 渲染方式 |
|------|--------------------------|---------|
| **通道（Channel）** | `ElliottChannelIndicator` -> `upper/lower/median` | 三条线，上下轨之间半透明填充 |
| **摆动标记（Swing Pivots）** | `ElliottSwingIndicator` -> 识别到的 swing 点 | 在指定 Bar 上标记箭头/圆点 |
| **波浪标签（Wave Labels）** | 基于 `ElliottPhaseIndicator` 在相位切换点标记 | 在对应 Bar 上方/下方标注数字字母 |
| **失效价位（Invalidation）** | `ElliottInvalidationIndicator` + 场景价格 | 水平虚线标注失效价位 |

### 2.2 可绘制到副图（Subchart）的要素

| 要素 | 数据来源 | 渲染方式 |
|------|---------|---------|
| **波浪相位（Phase）** | `ElliottPhaseIndicator` -> 枚举转 numeric（1~5, -1~-3） | 柱状图/色块图 |
| **聚合得分（Confluence）** | `ElliottConfluenceIndicator` | 折线图 + 阈值水平线 |
| **比率（Ratio）** | `ElliottRatioIndicator` | 折线图 + 黄金分割水平线 |
| **波浪计数（Wave Count）** | `ElliottWaveCountIndicator` | 折线/柱状图 |

### 2.3 右侧面板保留（不变）

现有的 `ElliottWaveAnalysisDTO` 快照分析继续保留，展示在右侧 elliott 面板，显示：
- 当前相位 & 场景信息
- 通道价位
- 聚合得分
- 多周期分析概览

## 三、后端设计方案

### 3.1 新增 API：每 Bar 指标序列

```
POST /api/v1/kline/indicator
Request: {
    "symbol": "BTCUSDT",
    "interval": "OKX4HOUR",
    "limit": 500,
    "indicatorType": "ELLIOTT_WAVE",
    "params": {
        "degree": "PRIMARY",
        "fibTolerance": 0.25,
        "includePhase": true,
        "includeChannel": true,
        "includeConfluence": true,
        "includeRatio": true,
        "includeLabels": true,
        "includeSwing": true
    }
}

Response: {
    "indicatorType": "ELLIOTT_WAVE",
    "data": [
        {
            "time": 1700000000000,
            "open": 42000,
            "high": 42500,
            "low": 41800,
            "close": 42300,
            "ewPhase": 1,
            "ewChannelUpper": 43500,
            "ewChannelLower": 41000,
            "ewChannelMedian": 42250,
            "ewConfluence": 2.5,
            "ewRatio": 0.618,
            "ewSwing": 1,
            "ewWaveCount": 3,
            "ewFilteredWaveCount": 3,
            "ewLabel": null
        }
    ],
    "signals": [
        { "barIndex": 30, "label": "1", "price": 41800, "type": "WAVE_LABEL" },
        { "barIndex": 55, "label": "2", "price": 42200, "type": "WAVE_LABEL" },
        { "barIndex": 80, "label": "3", "price": 44800, "type": "WAVE_LABEL" },
        { "barIndex": 80, "label": "invalidation", "price": 41000, "type": "INVALIDATION" }
    ],
    "metadata": {
        "degree": "PRIMARY",
        "currentPhase": "di 3 lang",
        "invalidation": false,
        "baseScenario": {},
        "alternativeScenarios": []
    }
}
```

### 3.2 后端核心实现逻辑

```
KLineV1ServiceImpl.calculateElliottWaveIndicator()
  |
  +-- 1. 从 ICandlestickService 获取 K 线数据
  +-- 2. 构建 BarSeries（复用 IndicatorWrapHelper）
  +-- 3. 构建 ElliottWaveFacade（复用现有代码）
  |     +-- facade = ElliottWaveFacade.zigZag(series, degree, tolerance, compressor)
  +-- 4. 遍历 0..endIndex，逐 Bar 提取指标值：
  |     +-- facade.phase().getValue(i)          -> ewPhase
  |     +-- facade.channel().getValue(i)         -> ewChannelUpper/ewChannelLower/ewChannelMedian
  |     +-- facade.confluence().getValue(i)      -> ewConfluence
  |     +-- facade.ratio().getValue(i)           -> ewRatio
  |     +-- facade.swing().getValue(i)           -> ewSwing
  |     +-- facade.waveCount().getValue(i)       -> ewWaveCount
  |     +-- facade.filteredWaveCount().getValue(i) -> ewFilteredWaveCount
  +-- 5. 提取波浪标签（相位切换点）：
  |     +-- 遍历 i=1..endIndex，检测 phase[i] != phase[i-1]
  |     +-- 在切换点生成 WaveLabelSignal
  +-- 6. 提取失效价位信号
  +-- 7. 构建 metadata（复用现有 DTO）
  +-- 8. 返回统一 Response
```

### 3.3 缓存策略

- **原有快照缓存**：Redis 30s（不变）
- **每 Bar 指标缓存**：
  - key 设计：`elliott:indicator:{symbol}:{interval}:{limit}:{degree}:{tolerance}`
  - TTL 30s（与快照一致）
  - 请求命中时直接返回

### 3.4 复用关系

```
ElliottWaveAnalysisService (现有，仅 endIndex 快照)
  |
  +-> ElliottWaveFacade (ta4j 0.22.6，被两处共享)
        |
        +-> KLineV1ServiceImpl.calculateIndicator() (新增，遍历全量 Bar)
```

## 四、前端设计方案

### 4.1 主图渲染（lightweight-charts）

#### 4.1.1 通道叠加（Channel Overlay）

渲染方式：
- 上轨线 `ewChannelUpper` -> `addLineSeries()` 虚线半透明
- 中轨线 `ewChannelMedian` -> `addLineSeries()` 虚线更淡
- 下轨线 `ewChannelLower` -> `addLineSeries()` 虚线半透明
- 上下轨之间使用 `fill` 机制做半透明填充

颜色统一使用海蓝色系（类似 ta4j 示例的青色），参考通道颜色：#40BFFF。

#### 4.1.2 波浪标签（Wave Labels）

从 `signals` 中取出 `type="WAVE_LABEL"` 的项，使用 lightweight-charts 的 `createTextMark()` 或 `SeriesMarkers` 在对应 K 线位置标注文字标签。

标签规则：

| 相位 | 标签 | 颜色 | 位置 |
|------|------|------|------|
| WAVE1 | "1" | #2196F3 蓝 | K 线上方 |
| WAVE2 | "2" | #F44336 红 | K 线下方 |
| WAVE3 | "3" | #4CAF50 绿 | K 线上方 |
| WAVE4 | "4" | #FF9800 橙 | K 线下方 |
| WAVE5 | "5" | #9C27B0 紫 | K 线上方 |
| WAVE_A | "A" | #E91E63 粉 | K 线下方 |
| WAVE_B | "B" | #9E9E9E 灰 | K 线上方 |
| WAVE_C | "C" | #B71C1C 深红 | K 线下方 |

#### 4.1.3 摆动点标记（Swing Pivots）

- `ewSwing = 1` (swing high) -> K 线上方标记下箭头
- `ewSwing = -1` (swing low) -> K 线下方标记上箭头

#### 4.1.4 失效价位线（Invalidation Level）

从 `signals` 中取出 `type="INVALIDATION"` 的项，使用 `addLineSeries()` 添加一条水平虚线，在图表右侧显示价位标签。

### 4.2 副图指标（Optional Pane）

#### Pane 1：波浪相位图

- 数据源：每 Bar 的 `ewPhase`
- 渲染：柱状图，正值（1~5 推动浪）用绿/蓝色系，负值（-1~-3 调整浪）用红/橙色系

#### Pane 2：聚合得分

- 数据源：每 Bar 的 `ewConfluence`
- 渲染：折线图 + 水平参考线（如 2.0 阈值线）

#### Pane 3：比率图

- 数据源：每 Bar 的 `ewRatio`
- 渲染：折线图 + 黄金分割水平参考线（0.382, 0.500, 0.618, 1.000, 1.272, 1.618）

#### Pane 4：波浪计数

- 数据源：每 Bar 的 `ewWaveCount` / `ewFilteredWaveCount`
- 渲染：两条折线对比（原始 vs 过滤后）

### 4.3 右侧面板填充

## 五、实施步骤

### 步骤 1：后端 DTO 扩展

新增 `ElliottWaveIndicatorDTO` 类，包含：
- `ElliottWaveBarData` -- 每 Bar 指标值（ewPhase, ewChannelUpper 等）
- `ElliottWaveSignal` -- 非每 Bar 信号（波浪标签、失效价）
- 响应结构：`{ data: [], signals: [], metadata: {} }`

### 步骤 2：后端 Indicator 计算逻辑

在 `KLineV1ServiceImpl` 中新增 `calculateElliottWaveIndicator()` 方法：
- 复用 `IndicatorWrapHelper.buildSeries()` 构建 BarSeries
- 复用 `ElliottWaveFacade.zigZag()` 构建 facade
- 遍历 0..endIndex 提取每 Bar 值
- 二次遍历提取波浪标签切换点
- 构建 metadata（可复用现有 `ElliottWaveAnalysisService` 的部分逻辑）

### 步骤 3：后端 Controller 集成

确保 `POST /api/v1/kline/indicator` 处理 `indicatorType = "ELLIOTT_WAVE"` 时路由到上述方法。

### 步骤 4：前端数据层

在 `api/member.ts` 或 `api/index.ts` 中确认指标请求方法可以覆盖 ELLIOTT_WAVE 类型。

### 步骤 5：前端主图 overlay 渲染

在 `MarketKlineV1.vue` 中：
- 解析 `response.data` 构建 channel 三条 line series
- 解析 `response.signals` 构建 wave labels + invalidation 线
- 解析 `response.data` 中的 `ewSwing` 构建 swing 标记

### 步骤 6：前端副图渲染

添加可选副图 pane：
- 相位柱状图（ewPhase）
- 聚合得分（ewConfluence）

### 步骤 7：右侧面板填充

完善 elliott tab 模板内容，使用 `response.metadata` 渲染场景详情。

## 六、与 K 线图优化.md 的关联

`K线图优化.md` 中规划的指标重构包含两阶段：

| 阶段 | 内容 | 艾略特波浪的对应 |
|------|------|-----------------|
| 一期 | 普通指标后移（SMA, EMA, MACD, RSI, Bollinger 等） | 不涉及 |
| 二期 | 复杂逻辑指标后移 | 艾略特波浪属于此阶段 |

本方案即为二期复杂指标"艾略特波浪"的具体实现设计。

### 后端文件变更清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `KLineV1ServiceImpl.java` | 新增方法 | `calculateElliottWaveIndicator()` |
| `ElliottWaveAnalysisService.java` | 不变或微调 | 继续保留供快照 API 使用 |
| `ElliottWaveAnalysisDTO.java` | 不变或新增 | 新增 `ElliottWaveIndicatorDTO` 子类 |

### 前端文件变更清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `MarketKlineV1.vue` | 新增逻辑 | 解析响应、构建 overlay/subchart、填充右面板 |
| `api/member.ts` | 不变 | 复用 `getElliottWaveAnalysis()`（快照）+ 新指标 API |

## 七、注意事项

1. **性能**：500 根 K 线遍历 `ElliottPhaseIndicator.getValue()` 可能有缓存预热问题。ta4j 的 `RecursiveCachedIndicator` 机制在遍历过程中会自动缓存中间结果，首次遍历后后续访问为 O(1)。建议在 facade 构建后先调用一次 `facade.phase().getValue(endIndex)` 触发全量计算。

2. **通道有效性**：`ElliottChannel` 有 `isValid()` 方法，只有在有效时才绘制通道线。前端应做渐变处理（有效时显示，无效时隐藏或淡出）。

3. **波浪标签不重叠**：当多个标签位置过近时，前端需要做防重叠处理（智能偏移或跳过一个）。

4. **副图数量**：默认不展开所有副图，建议仅显示相位图作默认 pane，用户可选择展开其他 pane 避免界面过于拥挤。

5. **参数联动**：右侧面板可能修改 degree/fibTolerance 参数，修改后应重新触发指标计算。可考虑 debounce。
