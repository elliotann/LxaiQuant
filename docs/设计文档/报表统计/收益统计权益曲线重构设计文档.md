## 1. 背景与问题

### 1.1 当前现状

市场行情菜单 → 收益统计 tab 中展示：
- **收益柱状图**（每个周期净利润 + 订单数）
- **权益曲线**（折线图）
- **回撤曲线**（折线图）

### 1.2 当前实现方式

前端 `BotPerformanceReport.vue` 调用 `getRobotOrderReport` 接口：

```
GET /api/order/report/by-robot?robotId=xxx&startTime=xxx&endTime=xxx&granularity=day
```

返回数据：`items[].netProfit`（每周期净利润）

**权益曲线计算逻辑**（纯前端，有缺陷）：

```js
getStartEquity() {
    // 机器人当前总权益 - 区间净利润总和
    return currentCapital - rangeNetProfit;
}

buildEquityAndDrawdownPoints(rows) {
    let equity = getStartEquity();   // ← 反推起点
    let peak = equity;
    rows.forEach(r => {
        equity += r.netProfit;       // ← 累加已实现净利润
        const dd = (equity - peak) / peak;
        drawdownPoints.push([time, dd]);
        equityPoints.push([time, equity]);
    });
}
```

### 1.3 存在的问题

| # | 问题 | 严重程度 | 说明 |
|---|------|---------|------|
| 1 | **起点反推不准确** | 高 | `currentCapital` 含浮动盈亏，`netProfit` 只是已实现盈亏，口径不一致；且区间结束到"现在"之间有额外盈亏变化 |
| 2 | **不含浮动盈亏** | 高 | 整条权益曲线只累加已平仓净利润，持仓浮动盈亏完全没体现，曲线中间值是"已实现累计"，不是真实权益 |
| 3 | **与系统已有权益数据脱节** | 中 | 系统中已有 `ai_equity_curve` 表存储每日权益快照（日频），但未复用 |

## 2. 现有权益数据链路分析（详细业务流程）

系统中存在 **4 条权益数据采集/计算链路**，下面逐条细化其完整业务流程、代码路径和数据口径。

### 2.1 链路①：实盘权益采样（RobotEquityJob → ai_equity_curve 表）

**文件**：[`RobotEquityJob.java`](file:///f:/project/lenzeto/ai-task/src/main/java/com/chain/ai/trade/engine/task/jobhandler/RobotEquityJob.java)

#### 2.1.1 触发方式

- XXL-Job 定时任务，bean 名 `robotEquityCollectJob`
- 默认 cron 表达式为每 4 小时执行一次（可通过 XXL-Job 控制台动态调整）
- 继承自 `IJobHandler`，入口方法 `execute()`

#### 2.1.2 完整执行流程（伪代码）

```
execute()
│
├─ 1. 查询所有在线机器人
│   └─ List<TradingBot> bots = tradingBotMapper.selectList(null)
│   └─ 遍历每个 TradingBot bot
│
├─ 2. 查重校验（防止任务重试产生重复数据）
│   └─ int count = equityCurveMapper.countByRobotIdAndDate(
│       bot.getRobotId(), LocalDate.now())
│   └─ if (count > 0) → 跳过（该日期已有记录）
│
├─ 3. 读取权益值
│   └─ BigDecimal equity = bot.getCurrentCapital()
│   └─ currentCapital = 可用余额 + 持仓市值（含浮动盈亏）
│
├─ 4. 处理峰值和盈利计算
│   └─ BigDecimal peakCapital = bot.getPeakCapital()
│   └─ if (equity.compareTo(peakCapital) > 0)
│   │   bot.setPeakCapital(equity)
│   └─ BigDecimal profit = equity.subtract(bot.getAllocatedCapital())
│
├─ 5. 写入 ai_equity_curve 表
│   └─ BacktestEquityCurve entity = new BacktestEquityCurve()
│   │   entity.setRobotId(bot.getRobotId())
│   │   entity.setRobotName(bot.getName())
│   │   entity.setTime(todayStart)     // 当前日期 00:00:00
│   │   entity.setEquity(currentCapital)
│   │   entity.setCreateTime(new Date())
│   └─ equityCurveMapper.insert(entity)
│
├─ 6. 更新 trading_bot 表的峰值权益
│   └─ tradingBotMapper.updateById(bot)
│
└─ 7. 返回 SUCCESS
```

#### 2.1.3 数据口径

| 口径 | 值 |
|------|-----|
| equity 来源 | `trading_bot.current_capital`（账户可用资金 + 持仓浮动盈亏） |
| time 取值 | 当前日期 `00:00:00`（每天一条，非每4小时一条） |
| robot_id | 真实机器人 ID（非空） |
| task_id | `NULL`（实盘数据无回测任务） |
| 重复保护 | `countByRobotIdAndDate(robotId, today)` > 0 则跳过 |
| 峰值记录 | 同时更新 `trading_bot.peak_capital` |

#### 2.1.4 当前时序示例

| 时间 | 动作 | equity |
|------|------|--------|
| 04-23 04:00:00 | Job触发 → 写入04-23记录 | 1050.00 |
| 04-23 08:00:00 | 跳过（当天已有记录） | — |
| 04-23 12:00:00 | 跳过 | — |
| 04-23 16:00:00 | 跳过 | — |
| 04-24 04:00:00 | Job触发 → 写入04-24记录 | 1070.50 |
| 04-25 04:00:00 | Job触发 → 写入04-25记录 | 1065.20 |

> **注意**：当前实现写入 time 为 `2025-04-23 00:00:00` 即每天一条，粒度是日而非4小时。若需改为每4小时一条，需修改 time 赋值逻辑为 `getTimeRoundedTo4Hour()`。

### 2.2 链路②：实时权益采样（sampleAndEnqueueEquityPoint → Redis）

**文件**：[`IDealStrategyBasic.java`](file:///f:/project/lenzeto/ai-engine/src/main/java/com/chain/ai/trade/engine/core/IDealStrategyBasic.java)

#### 2.2.1 方法定义

```java
default void sampleAndEnqueueEquityPoint(
    BarSeries series,
    TradingStrategyParams params,
    boolean isTestMode
)
```

- 定义为 `IDealStrategyBasic` 接口中的 `default` 方法（隐式 `public`）
- 可被接口实现类（如 `DefaultDealStrategyTrade`）直接调用
- 内部通过 `resolveTaskId(params, ts, isTestMode)` 生成隔离的 taskId

#### 2.2.2 完整执行流程（伪代码）

```
sampleAndEnqueueEquityPoint(series, params, isTestMode)
│
├─ 1. 获取当前K线结束时间
│   └─ Bar lastBar = series.getLastBar()
│   └─ long ts = lastBar.getEndTime()
│       .toInstant().toEpochMilli()
│   └─ Instant barEndTime = lastBar.getEndTime()
│
├─ 2. 解析 taskId（数据隔离核心）
│   └─ resolveTaskId(params, ts, isTestMode)
│       ├─ if isTestMode:
│       │   // 回测：返回纯 ID（不含前缀）
│       │   └─ params.getTestReportId()
│       │       或 symbol:interval:yyyyMMdd
│       └─ else:
│           // 实盘：LIVE:{robotId}:{symbol}:{interval}
│           └─ "LIVE:" + params.getRobotId() + ":" +
│               params.getSymbol() + ":" + params.getInterval()
│
├─ 3. 计算权益 equity
│   ├─ 优先判断 tradingRecord instanceof MultiPositionTradingRecord
│   │   ├─ 多持仓合约模式（回测 engine 持有，接口实现类传入）
│   │   ├─ BigDecimal realizedPnl = 遍历已平仓持仓的已实现盈亏
│   │   ├─ BigDecimal unrealizedPnl = 遍历未平仓持仓的浮动盈亏
│   │   └─ BigDecimal equity = params.getAmount().doubleValue()
│   │                            + realizedPnl + unrealizedPnl
│   │
│   ├─ 非 MultiPositionTradingRecord 模式
│   │   ├─ if (isTestMode) {
│   │   │   // 测试模式无真实账户，使用起始资金
│   │   │   equity = params.getAmount()
│   │   │ } else {
│   │   │   // 实盘：调用账户服务获取
│   │   │   available = orderSvc.getAvailableBalance(accLong)
│   │   │   positionsIncome = 累加持仓浮动盈亏
│   │   │   equity = available + positionsIncome
│   │   │ }
│   │
│   └─ equity 为 BigDecimal 类型
│
├─ 4. 计算 drawdown / returnRate（通过 Redis 维护中间状态）
│   │
│   ├─ 4a. 读取或初始化峰值权益
│   │   └─ String peakKey = "equity:peak:" + taskId
│   │   └─ BigDecimal peak = redisCache.getString(peakKey)
│   │   └─ if (peak == null) peak = equity
│   │   └─ if (equity > peak) peak = equity
│   │   └─ redisCache.put(peakKey, peak, 3, TimeUnit.DAYS)
│   │
│   ├─ 4b. 计算回撤率
│   │   └─ BigDecimal drawdown = (equity - peak) / peak
│   │   └─ drawdown ≤ 0，负值表示相对峰值的下跌比例
│   │   └─ 如 -0.052 表示回撤 5.2%
│   │
│   ├─ 4c. 读取上一次权益
│   │   └─ String lastKey = "equity:last:" + taskId
│   │   └─ BigDecimal lastEquity = redisCache.getString(lastKey)
│   │   └─ if (lastEquity == null) {
│   │   │   returnRate = 0  // 首次采样，收益率为 0
│   │   │ } else {
│   │   │   returnRate = (equity - lastEquity) / lastEquity
│   │   │ }
│   │   └─ redisCache.put(lastKey, equity, 3, TimeUnit.DAYS)
│   │
│   └─ 更新峰值权益到 Redis（已在上文完成）
│
├─ 5. 构建权益数据 JSON
│   └─ JSONObject equityData = new JSONObject()
│   │   equityData.put("ts", ts)
│   │   equityData.put("equity", equity)
│   │   equityData.put("drawdown", drawdown)
│   │   equityData.put("returnRate", returnRate)
│   │   equityData.put("available", available)       // 实盘模式
│   │   equityData.put("positionsIncome", positionsIncome) // 实盘模式
│   │   equityData.put("source", "strategy")          // 固定值（见设计约定）
│   │   equityData.put("scope", "account")            // 固定值（见设计约定）
│   │   equityData.put("interval",
│   │       series.getLastBar().getTimePeriod().toString())
│   │   equityData.put("symbol", symbol)
│   └─ JSON.toJSONString(equityData)
│
└─ 6. 写入 Redis
    └─ String key = "equity:curve:" + taskId
    └─ redisCache.getHash(key)          // Redis Hash 结构
    └─ redisCache.putHash(key, ts, json) // field=时间戳, value=JSON
    └─ redisCache.expire(key, 3, TimeUnit.DAYS)  // 3天TTL
```

#### 2.2.3 数据口径

| 口径 | 值 |
|------|------|
| equity 来源 | 多持仓模式：`initialAmount + 已实现盈亏 + 未实现盈亏`（优先）；非多持仓：测试模式 `params.getAmount()`，实盘 `可用余额 + 持仓浮动盈亏` |
| drawdown | 通过 Redis `equity:peak:{taskId}` 维护历史峰值，`(current - peak) / peak`，≤ 0 |
| returnRate | 通过 Redis `equity:last:{taskId}` 维护上次权益，`(current - last) / last`，首次为 0 |
| time 取值 | K线结束时间（毫秒时间戳） |
| 存储 | Redis Hash，key=`equity:curve:{taskId}`，field=ts（毫秒），value=JSON（含 equity/drawdown/returnRate 全字段） |
| Redis TTL | 3 天 |
| source | `"strategy"`（固定值） |
| scope | `"account"`（固定值） |
| interval | `series.getLastBar().getTimePeriod().toString()`（Duration 格式，如 `PT4H`） |
| 持久化 | 由 `RiskEquityCurveFlushJob` 每30秒增量同步到 `ai_equity_curve` 表（详见 2.2.5） |
| 当前状态 | ✅ **已激活**—被 `DefaultDealStrategyTrade.processExitSignals()` 在每个 K 线末尾调用 |

#### 2.2.4 调用链路

`sampleAndEnqueueEquityPoint` 由 `DefaultDealStrategyTrade.processExitSignals()` 在每个 K 线末尾调用：

```
DefaultDealStrategyTrade.processExitSignals(series, index, ...)
│
├─ 策略逻辑执行完毕，准备处理信号
│
└─ 在每个 K 线末尾调用（含回测和实盘）：
    └─ IDealStrategyBasic.sampleAndEnqueueEquityPoint(
           series, params, isTestMode)
       │
       ├─ 实盘（isTestMode=false）：
       │   ├─ 通过 orderSvc 获取账户可用余额、持仓浮动盈亏
       │   ├─ 或通过 MultiPositionTradingRecord 分支直接计算
       │   └─ 计算 drawdown/returnRate → 写入 Redis
       │
       ├─ 回测（isTestMode=true）：
       │   ├─ 优先 MultiPositionTradingRecord 分支（初始资金 + pnl）
       │   ├─ 否则使用 params.getAmount()
       │   └─ 计算 drawdown/returnRate → 写入 Redis
       │
       └─ taskId 隔离
           ├─ 回测：纯 ID（参数 testReportId）
           └─ 实盘：LIVE:{robotId}:{symbol}:{interval}
```

**调用关系说明**：
- `IDealStrategyBasic` 接口定义中持有一个 `default` 方法 + `resolveTaskId` helper
- `DefaultDealStrategyTrade` 作为接口实现类，在 `processExitSignals` 末尾调用
- 回测和实盘均走相同通路，通过 `isTestMode` 和 `resolveTaskId` 实现数据隔离
- `MultiPositionTradingRecord` 分支优先使用，提供精确的逐 K 线权益计算

#### 2.2.5 Redis → DB 落库机制（RiskEquityCurveFlushJob）

**文件**：[`RiskEquityCurveFlushJob.java`](file:///f:/project/lenzeto/ai-quant/src/main/java/com/chain/ai/trade/engine/jobhandler/RiskEquityCurveFlushJob.java)

链路②采样到 Redis 的数据为临时存储（3天 TTL），需要定时同步到 `ai_equity_curve` 表实现持久化。

##### 触发方式

- Spring `@Scheduled` 定时任务，`fixedDelay = 30000ms`，`initialDelay = 15000ms`
- 每30秒执行一次增量同步

##### 完整执行流程（伪代码）

```
flush()
│
├─ 1. 扫描所有 Redis key 匹配模式
│   └─ redisCache.keys("equity:curve:*")
│   └─ 遍历每个 key
│
├─ 2. 解析 taskId
│   └─ key = "equity:curve:{taskId}"
│   └─ taskId = key.substring("equity:curve:".length)
│
├─ 3. 读取增量同步偏移
│   └─ lastSyncStr = redisCache.getString("equity:last_sync:" + taskId)
│   └─ long lastSync = parseLong(lastSyncStr, 0L)
│   └─ 只处理 ts > lastSync 的数据点（增量同步）
│
├─ 4. 读取 Redis Hash 全量数据
│   └─ Map<Object, Object> map = redisCache.getHash(key)
│   └─ 遍历每个 entry（field=ts, value=JSON）
│
├─ 5. 解析 JSON 提取全字段
│   └─ JSONObject obj = new JSONObject(json)
│   └─ Long ts = obj.getLong("ts")
│   └─ BigDecimal equity = obj.getBigDecimal("equity")
│   └─ BigDecimal returnRate = obj.getBigDecimal("returnRate")
│   └─ BigDecimal drawdown = obj.getBigDecimal("drawdown")
│   └─ if (ts == null || ts <= lastSync) → 跳过（已同步）
│
├─ 6. 构建 BacktestEquityCurve 实体
│   └─ time = LocalDateTime.ofInstant(Instant.ofEpochMilli(ts), ZoneId.systemDefault())
│   └─ equity / returnRate / drawdown 直接从 JSON 提取
│   └─ 解析 taskId 区分实盘/回测并设置 robot_id / task_id：
│       ├─ if (taskId.startsWith("LIVE:")) {
│       │   // 实盘：LIVE:{robotId}:{symbol}:{interval}
│       │   String[] parts = taskId.split(":", 3);
│       │   curve.setRobotId(parts[1]);  // 提取 robotId
│       │   curve.setTaskId(null);       // 回测维度置空
│       │ } else {
│       │   // 回测：taskId 就是纯 ID
│       │   curve.setTaskId(taskId);
│       │   curve.setRobotId(null);
│       │ }
│
├─ 7. 批量 upsert 到数据库
│   └─ equityCurveService.batchInsertOrUpdate(list)
│   └─ INSERT ... ON DUPLICATE KEY UPDATE
│   └─ 唯一约束：(task_id, time) 或 (robot_id, time)
│
└─ 8. 更新增量同步偏移
    └─ redisCache.put("equity:last_sync:" + taskId,
                       maxTs, 30, TimeUnit.DAYS)
```

##### 批量 upsert SQL

```xml
<insert id="batchInsertOrUpdate" parameterType="java.util.List">
    INSERT INTO ai_equity_curve (task_id, robot_id, robot_name, time, equity, return_rate, drawdown)
    VALUES
    <foreach collection="list" item="item" separator=",">
        (#{item.taskId}, #{item.robotId}, #{item.robotName}, #{item.time},
         #{item.equity}, #{item.returnRate}, #{item.drawdown})
    </foreach>
    ON DUPLICATE KEY UPDATE
    equity = VALUES(equity),
    return_rate = VALUES(return_rate),
    drawdown = VALUES(drawdown)
</insert>
```

##### 数据隔离规则

| taskId 前缀 | 解析结果 | robot_id | task_id | 所属链路 |
|-------------|---------|----------|---------|---------|
| `LIVE:{robotId}:{symbol}:{interval}` | 实盘 | 真实机器人 ID | `NULL` | 链路②→FlushJob |
| 纯 ID（无前缀） | 回测 | `NULL` | 回测任务 ID | 链路②→FlushJob |
| `NULL`（链路①直接写入） | 实盘日频采样 | 真实机器人 ID | `NULL` | 链路① RobotEquityJob |

> **约定**：`robotId` 中不得包含冒号 `:`，以保证 `split(":", 3)` 解析正确。

##### 性能与异常处理

| 机制 | 说明 |
|------|------|
| 增量同步 | `equity:last_sync:{taskId}` 记录上次同步时间戳，避免全量重复写入 |
| 单点异常隔离 | 每个 key 处理有独立 try-catch，单个 key 解析失败不影响其他 key |
| 批量操作 | 每次同步批量 upsert，减少数据库连接开销 |
| Redis TTL | `equity:curve:*` 3天 / `equity:last_sync:*` 30天 / `equity:peak:*` 3天 / `equity:last:*` 3天 |

##### Redis Key 汇总

| Key 模式 | 用途 | TTL | 写入方 |
|----------|------|-----|--------|
| `equity:curve:{taskId}` | 权益曲线数据（Hash） | 3天 | `sampleAndEnqueueEquityPoint` |
| `equity:peak:{taskId}` | 峰值权益（String） | 3天 | `sampleAndEnqueueEquityPoint` |
| `equity:last:{taskId}` | 上次权益（String） | 3天 | `sampleAndEnqueueEquityPoint` |
| `equity:last_sync:{taskId}` | 增量同步偏移（String） | 30天 | `RiskEquityCurveFlushJob` |

### 2.3 链路③：回测权益曲线计算（BacktestEngine → ai_equity_curve 表）

**核心计算**：[`BacktestEngine.java`](file:///f:/project/lenzeto/ai-engine/src/main/java/com/chain/ai/trade/engine/backtest/BacktestEngine.java) — `calculateEquityCurveAndDrawdown()`

#### 2.3.1 两条回测入口路径

```
┌─────────────────────────────────────────────────────────────────┐
│ 入口 A：快速回测（Enhanced Backtest）                           │
│                                                                 │
│ BacktestService.runEnhancedBacktest(params)                     │
│   │                                                             │
│   ├─ 1. BacktestEngine.runBacktest(series, strategy, record,    │
│   │                                , config)                    │
│   │   └─ 逐K线执行策略                                          │

│   │                                                             │

#### 2.3.2 核心权益计算方法（BacktestEngine.java）

```
calculateEquityCurveAndDrawdown(
    BarSeries series,                  // 回测K线
    TradingRecord tradingRecord,       // 持仓记录
    Number initialAmount,              // 初始资金
    BacktestConfig config              // 回测配置
) → String[] { equityCurveJson, drawdownSeriesJson }
│
├─ 1. 判断持仓模式
│   ├─ if (tradingRecord instanceof MultiPositionTradingRecord)
│   │   → 多持仓合约模式（可同时持有多个同方向持仓）
│   └─ else
│       → 普通模式（单持仓）
│
├─ 2. 遍历每根K线（for int i = 0; i < series.getBarCount(); i++）
│   │
│   ├─ 2a. 多持仓合约模式（MultiPositionTradingRecord）
│   │   │
│   │   ├─ 收盘价 = series.getBar(i).getClosePrice().doubleValue()
│   │   │
│   │   ├─ 计算已实现盈亏 realizedPnl
│   │   │   └─ 遍历所有在本K线平仓的交易（从 tradingRecord 获取）
│   │   │   └─ realizedPnl += (exitPrice - entryPrice) × 数量（多头）
│   │   │   └─ realizedPnl += (entryPrice - exitPrice) × 数量（空头）
│   │   │
│   │   ├─ 计算未实现盈亏 unrealizedPnl
│   │   │   └─ 遍历当前所有未平仓持仓
│   │   │   └─ unrealizedPnl += (closePrice - entryPrice) × 数量（多头）
│   │   │   └─ unrealizedPnl += (entryPrice - closePrice) × 数量（空头）
│   │   │
│   │   └─ equity = initialAmount.doubleValue() + realizedPnl + unrealizedPnl
│   │
│   ├─ 2b. 普通模式（单持仓，使用 ta4j CumulativePnL）
│   │   │
│   │   ├─ CumulativePnL pnl = new CumulativePnL(series, tradingRecord)
│   │   │   └─ ta4j 内置指标，逐笔计算已平仓累计盈亏
│   │   │   └─ 注：CumulativePnL 只计算已实现盈亏
│   │   │   └─ 对于仍在持仓期间的K线，CumulativePnL 值不变
│   │   │
│   │   └─ equity = initialAmount.doubleValue() + pnl.getValue(i)
│   │
│   ├─ 3. 计算回撤率 drawdown
│   │   └─ peak = max(peak, equity)
│   │   └─ drawdown = (equity - peak) / peak
│   │   └─ drawdown 为 ≤ 0 的值（如 -0.052 表示回撤 5.2%）
│   │
│   └─ 4. 记录权益点
│       └─ time = series.getBar(i).getEndTime()
│       └─ equityPoints.add({ time, equity, drawdown })
│       └─ drawdownPoints.add({ time, drawdown })
│
├─ 5. 序列化
│   └─ equityCurveJson = JSON.toJSONString(equityPoints)
│   └─ drawdownSeriesJson = JSON.toJSONString(drawdownPoints)
│
└─ 6. 返回 String[] { equityCurveJson, drawdownSeriesJson }
```

#### 2.3.3 数据写入表方法（BacktestResultServiceImpl.parseEquityCurveToTable）

```
parseEquityCurveToTable(equityCurveJson, drawdownSeriesJson)

├─ 1. 解析 JSON 数组

│
├─ 2. 构建 drawdown 映射（按时间建立索引）
│   └─ Map<Date, BigDecimal> drawdownMap = new HashMap<>()

│       JSONObject dd = drawdownSeries.getJSONObject(i)
│       drawdownMap.put(dd.getDate("time"), dd.getBigDecimal("value"))
│   }
│
├─ 3. 遍历 equity 点列表
│   └─ BigDecimal previousEquity = null
│   └─ for (int i = 0; i < equityPoints.size(); i++) {
│       │
│       ├─ 获取 equity 值
│       │   BigDecimal equity = point.getBigDecimal("value")
│       │
│       ├─ 计算 returnRate（环比收益率）
│       │   if (previousEquity != null) {
│       │       returnRate = equity.subtract(previousEquity)
│       │           .divide(previousEquity, 8, RoundingMode.HALF_UP)
│       │   } else {
│       │       returnRate = null
│       │   }
│       │
│       ├─ 从 drawdownMap 获取对应时间点的回撤值
│       │
│       ├─ 构建 BacktestEquityCurve 实体
│       │   ├─ time = point.getDate("time")
│       │   ├─ equity = point.getBigDecimal("value")
│       │   ├─ returnRate = dailyReturn（环比收益率）
│       │   ├─ drawdown = drawdownMap.get(time)
│       │   ├─ benchmarkValue = 基准值（如有）
│       │   ├─ benchmarkReturnRate = 基准收益率
│       │   ├─ taskId = 当前回测任务 ID（非空）

│
└─ 4. 写入完成

#### 2.3.4 数据口径

| 口径 | 值 |
|------|-----|
| equity 来源 | 多持仓模式：`initialAmount + 已实现盈亏 + 未实现盈亏`；普通模式：`initialAmount + CumulativePnL` |
| time 取值 | K线结束时间（每根K线一个点） |
| 写入粒度 | 每根K线一条 |

| task_id | 回测任务 ID（非空） |
| returnRate | `(equity_n - equity_{n-1}) / equity_{n-1}`，K线级别环比收益率 |

## 3. 问题详析

### 3.1 权益曲线起点反推为什么不准

示例场景：

```
查区间：2025-04-01 ~ 2025-04-30
  → 区间净利润 = +500（已平仓订单）
  → 机器人当前 currentCapital = 2000（2025-06-04 时的权益）
  → getStartEquity() = 2000 - 500 = 1500

但实际 04-01 的权益是 1200（因为 05 月又赚了 300）
  → 曲线起点 1500 就是错的，整条曲线整体上偏 300
```

### 3.2 不含浮动盈亏的影响

```
假设 04-01 ~ 04-30:
  - 04-15 开多单，持仓到 04-25
  - 04-15 ~ 04-25 期间价格涨了 10%，浮动盈利 +100
  - 04-25 平仓，实现利润 +100

链路④（当前）：
  → 04-15 ~ 04-25 期间无净利润（未平仓）
  → 权益曲线显示这段时间权益平线，实际权益是上升的

链路①（正确）：
  → 采样 equity 含浮动盈亏
  → 权益曲线真实反映每日实际权益
```

### 3.3 总结对比

| 对比维度 | 当前（前端反推，链路④） | 正确方案（复用日终快照 + 回测权益，链路①+③） |
|---------|---------------|----------------------|
| 数据源 | 已平仓订单净利润 | `ai_equity_curve` 表 |
| 含浮动盈亏 | ❌ | ✅ |
| 起点准确 | ❌（反推） | ✅（实际快照） |
| 回撤曲线 | ❌（基于不准确的权益） | ✅（基于真实权益） |
| 维护成本 | 前端独立计算 | 复用已有数据链路 |

## 4. 改造方案

### 4.1 核心思路

**收益统计 tab 的权益曲线和回撤曲线改为从 `ai_equity_curve` 表读取**，与"多机器人权益对比图"使用同一数据源。

- **实盘机器人**：权益数据来自链路①（`RobotEquityJob` 每4小时采样）
- **回测结果**：权益数据来自链路③（`BacktestController` 回测完成后由 `BacktestResultServiceImpl.saveResult()` 写入）

> **采样频率说明**：实盘权益采样默认每4小时一次（通过 `RobotEquityJob` 的 XXL-Job cron 表达式配置），支持动态调整。采样数据按整点时间写入 `ai_equity_curve` 表，查询时可按天/月聚合。

### 4.2 数据隔离规则

**核心原则**：实盘数据与回测数据通过 `robot_id` / `task_id` 互斥维度严格隔离，两种数据互不干扰。

| 数据来源 | robot_id | task_id | 唯一约束 | 说明 |
|---------|----------|---------|---------|------|
| 链路①-实盘权益采样 | 真实机器人ID | `NULL` | `(robot_id, time)` | 每个机器人每个采样时间点一条 |
| 链路③-回测曲线数据 | `NULL` | 非空回测任务ID | `(task_id, time)` | 每个回测任务每根K线一条 |

**代码层强制约定**（在写入入口落实）：

- **实盘写入**（`RobotEquityJob`）：`robot_id = 真实ID`, `task_id = NULL`
- **回测写入**（`BacktestResultServiceImpl.saveResult` → `parseEquityCurveToTable`）：`robot_id = NULL`, `task_id = 非空`

### 4.3 表结构设计

`ai_equity_curve` 表保持现有结构不变，**不新增 `type`/`source` 字段**。4小时级和K线级只是时间粒度不同，查询时按维度聚合即可。

**唯一约束保留**：保留 `uk_robot_time(robot_id, time)` 唯一约束，确保实盘数据每个机器人每个时间点只有一条，避免采样任务重试/并发产生重复数据。

**新增回测维度唯一约束**：为回测数据增加 `uk_task_time(task_id, time)` 唯一约束，确保每个回测任务每根K线只有一条权益记录。

```sql
-- 保留实盘唯一约束（不变）
-- uk_robot_time(robot_id, time)

-- 新增回测维度唯一约束
ALTER TABLE ai_equity_curve ADD CONSTRAINT uk_task_time UNIQUE (task_id, time);
```

**重要说明**：
- 不去除 `uk_robot_time` 的唯一约束，避免因去除后同一 `(robot_id, time)` 可插入多条导致权益值错误
- 回测数据写入时 `robot_id` 统一置为 `NULL`，不会与实盘数据冲突
- 两种数据维度键不同，自然互不干扰

**查询维度**：

| 场景 | 查询条件 | 隔离保证 |
|------|---------|---------|
| 收益统计权益曲线 | `WHERE robot_id=? AND time BETWEEN ? AND ? AND task_id IS NULL` | `task_id IS NULL` 过滤回测数据 |
| 回测详情权益曲线 | `WHERE task_id=?`（已有，不变） | 按 task_id 查询天然隔离 |
| 多机器人权益对比 | `WHERE robot_id IN (?) AND time BETWEEN ? AND ? AND task_id IS NULL` | 同上 |
| 账户总览权益曲线 | `WHERE robot_id IS NOT NULL AND task_id IS NULL` + 时间范围 | 同上 |

### 4.4 方案选择

**方案 A（推荐）**：在 `getRobotOrderReport` 接口中增加权益数据。在已有的 `RobotOrderReportVO` 中增加权益曲线字段，前端一次查询拿到所有数据。

理由：收益统计 tab 需要保证订单数据和权益数据的时间范围一致，放在同一个接口更方便对齐。前端改动最小，无需新增独立接口。

### 5.2 回撤计算（后端做）

回撤在**后端统一计算**，返回**绝对值（正数）** 表示回撤幅度，前端直接展示：

```java
BigDecimal peak = null;
for (EquityCurvePoint point : equityCurve) {
    if (point.getEquity() == null) continue;
    if (peak == null || point.getEquity().compareTo(peak) > 0) {
        peak = point.getEquity();
    }
    if (peak != null && peak.compareTo(BigDecimal.ZERO) > 0) {
        // 返回绝对值，如 5.2 表示回撤 5.2%，前端无需取 abs
        BigDecimal drawdown = peak.subtract(point.getEquity())  // peak - equity = 正数
                .divide(peak, 6, RoundingMode.HALF_UP)
                .multiply(new BigDecimal("100"));
        point.setDrawdown(drawdown);
    } else {
        point.setDrawdown(BigDecimal.ZERO);  // peak 为 0 或 null 时回撤为 0
    }
}
```

### 5.5 权益曲线时间戳语义说明

`ai_equity_curve.time` 为整点时间戳，表示该时刻的权益快照。

例如（4小时采样）：
| time | equity | 含义 |
|------|--------|------|
| 2025-04-01 04:00:00 | 1000.00 | 04-01 04:00 时的权益快照 |
| 2025-04-01 08:00:00 | 1010.00 | 04-01 08:00 时的权益快照 |
| 2025-04-01 12:00:00 | 1005.00 | 04-01 12:00 时的权益快照 |

**聚合说明**：
- 按**月**聚合：取该月一合值采样值（16或数据）
：按 `sellT权益记录e日 聚合，权益曲线按整点采样时间聚合
- 两者时间线不完全对齐，但以用户选择的日期范围为准，数据在时间范围内的部分参与展示
### 5.6 曲线不连续处理

采样只在有权益变动的时刻写入。若某些时段没有记录（如采样间隔内无变化、数据缺失），查询结果会直接跳过，前端连线会形成跨越缺失时段的直线，造成误导。

**后端处理方案**：在返回 `equityCurve` 之前，对时间范围内的每个时间粒度进行填充（按天粒度填充缺失日期，按月粒度填充缺失月份）。

```java
// 伪代码：缺失日期填充
List<EquityCurvePoint> fillMissingDates(List<EquityCurvePoint> rawPoints,
                                         LocalDate startDate, LocalDate endDate) {
    List<EquityCurvePoint> result = new ArrayList<>();
    BigDecimal lastEquity = null;
    Map<LocalDate, EquityCurvePoint> pointMap = rawPoints.stream()
        .collect(Collectors.toMap(p -> parseDate(p.getDate()), Function.identity()));

    for (LocalDate date = startDate; !date.isAfter(endDate); date = date.plusDays(1)) {
        if (pointMap.containsKey(date)) {
            EquityCurvePoint p = pointMap.get(date);
            lastEquity = p.getEquity();
            result.add(p);  // 有数据：正常添加
        } else if (lastEquity != null) {
            // 无数据：equity 取前值，drawdown 置为 null
            EquityCurvePoint filled = new EquityCurvePoint();
            filled.setDate(date.toString());
            filled.setEquity(lastEquity);
            filled.setDrawdown(null);  // 缺失日不计算回撤
            result.add(filled);
        }
    }
    return result;
}
```

**前端要求**：
- 对于 `drawdown = null` 的数据点，跳过连线（只画点或不画），避免跨越缺失日期的直线
- 可在 tooltip 中展示"数据缺失"标记

**更简单方案（可选）**：在 SQL 中用 `RIGHT JOIN` 日期维表补全，但这会增加复杂度。建议采用后端填充方案。
