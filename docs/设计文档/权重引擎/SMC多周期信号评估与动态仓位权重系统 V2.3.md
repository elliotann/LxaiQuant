1. 策略概述
1.1 策略定位
本系统是一个信号质量评估与仓位权重计算引擎，而非信号发生器。

信号来源：任意交易信号（突破、均线交叉、形态识别、RSI超买超卖、AI信号等），由上游策略模块生成。

核心职责：对候选信号进行多周期SMC结构评估，输出：

是否值得入场（VETO否决 / SCORING通过）

仓位权重乘数（决定最终开仓大小）

交易执行参数（入场价格、止损位、止盈目标）

移动止损触发条件

1.2 核心思想
本系统完全摒弃传统滞后指标（MACD、KDJ、RSI），仅基于价格行为与市场结构对候选信号进行评估。通过识别4小时、1小时、15分钟、3分钟四个时间框架内的HH/HL/LL/LH结构，判定当前价格所处的趋势阶段（波次）与空间位置（位置比），并据此计算信号的综合评分与仓位乘数。

“信号告诉我‘什么位置入场’，SMC告诉我‘这单值不值得做、做多少’。”

1.3 策略哲学
做多时： “混沌看盈亏比，试盘不重仓，确认~加速重仓出击，赶顶只出不进。”

做空时（镜像对称）： “混沌看盈亏比，试盘不重仓，确认~加速重仓出击，赶底只出不进。”

2. 数据结构与核心定义
2.1 Swing Point（摆动点）结构
基于SMC指标（SmartMoneyConceptsIndicator），每个周期实时识别以下结构点：

结构点	定义	标记	适用方向
HH	更高的高点（Higher High）	上升趋势延续	做多
HL	更高的低点（Higher Low）	上升趋势中的回调低点	做多
LH	更低的高点（Lower High）	下降趋势中的反弹高点	做空
LL	更低的低点（Lower Low）	下降趋势延续	做空
2.2 双轨制结构定义（Swing vs Internal）
维度	Swing BOS（摆动结构）	Internal BOS（内部结构）
参数来源	基于 swingsLength=50 的大级别结构	基于内部 length=5 的小级别结构
代表含义	主力资金的方向性选择（真正的趋势延续）	短期噪音/微观惯性（局部动能释放）
稳定性	极稳，一旦形成，短期不会轻易改变	极敏，在横盘期会频繁出现假信号
策略职责	决定“开不开仓”（战略闸门）	决定“加多少仓”（战术微调因子）
2.3 波次定义（Wave Index）—— 五阶段命名
波次（Wave Index）是衡量当前趋势年龄的核心变量。做多与做空采用完全镜像的计数规则，五阶段命名对称。

2.3.1 波次计数的双重条件（HH + HL 双验证）
核心原则：上升趋势 = 更高的高点（HH）+ 更高的低点（HL）。波次推进必须同时满足HH创新高和HL持续抬升两个条件。

条件	说明
HH条件	价格必须创出比前一个HH更高的高点（即出现 Swing Bullish BOS）
HL条件	回调低点必须高于前一个HL（即HL持续抬升），且回踩幅度不得过深
仅满足HH不满足HL时：波次不递增，信号被标记为“假突破”或“衰竭突破”，通过SCORING减分体现风险。

2.3.2 做多波次（正向，关注 HH + HL）
波次	阶段名称	触发条件（必须同时满足）	基础仓位系数
Wave 0	混沌	无明确方向，HL持续降低	× 0
Wave 1	试盘	CHOCH发生（突破前高），HL尚未形成	× 0.3
Wave 2	确认	①出现有效HL（回调低点 > 前一个HL）②后续出现新的HH（BOS）	× 1.0
Wave 3	加速	①HL持续抬高（HL > 前HL）②连续出现新的HH（BOS）	× 1.5
Wave 4+	赶顶	HH还在创，但HL开始走平或降低（预警信号）	× 0
2.3.3 做空波次（负向，关注 LH + LL）
波次	阶段名称	触发条件（必须同时满足）	基础仓位系数
Wave 0	混沌	无明确方向，LH持续抬高	× 0
Wave -1	试盘	CHOCH发生（跌破前低），LH尚未形成	× 0.3
Wave -2	确认	①出现有效LH（反弹高点 < 前一个LH）②后续出现新的LL（BOS）	× 1.0
Wave -3	加速	①LH持续降低（LH < 前LH）②连续出现新的LL（BOS）	× 1.5
Wave -4+	赶底	LL还在创，但LH开始走平或抬高（预警信号）	× 0

2.3.5 说明：基础仓位系数与最终乘数的关系
§2.3 定义的是各波次阶段的“基础仓位系数”，§9.3 定义的是综合评分后的“最终仓位乘数”。两者为乘法关系，共同决定最终开仓大小。实际执行以 §9.3 的评分映射为准。

2.4 有效结构点定义
一个HH或HL要被称为“有效”，必须同时满足以下三个维度的条件：

维度	第一道/第二道止损	第三道（终极）止损	说明
时间（年龄）	≤ 15根K线	≤ 30根K线	4H周期跨度大，年龄放宽到30根
空间（幅度）	≥ 前一段波幅的 5%	≥ 前一段波幅的 5%	ETH短线最低门槛
状态	未被价格打破	未被价格打破	一旦打破立即失效
毛刺过滤	年龄≤3根且幅度<5% 视为毛刺	—	不采用毛刺作为有效结构
2.5 熔断机制（混沌熔断）
熔断是ETH短线策略的第一道风控闸门，基于过去20根4H K线的价格振幅和翻转频率综合判断。

振幅范围	翻转频率	动作	说明
< 3%	任意	✅ 熔断	极窄幅横盘，无法交易
3% ~ 8%	< 3次	❌ 不熔断	中等震荡，趋势尚可
3% ~ 8%	≥ 3次	✅ 熔断	中等震荡且频繁翻转，混沌
≥ 8%	任意	❌ 不熔断	宽幅震荡，高低点明确，位置好可操作

5. 入场与风控执行细则
5.1 入场触发条件
评估通过：最终仓位乘数 > 0（未被 VETO 否决）

方向一致：信号方向与 4H Swing 趋势方向一致（方向背离已从VETO降级为SCORING -1.0分）

3M形态确认：

做多：收盘价 > 前一根K线最高价

做空：收盘价 < 前一根K线最低价

实体占比 > 65%

滑点控制：入场价 - 信号价 ≤ 0.15%（做多）/ 信号价 - 入场价 ≤ 0.15%（做空）

时间过滤：北京时间 08:00 ~ 14:00（亚洲早盘）的信号，一律作废

5.4 以损定量仓位管理
5.4.1 核心公式
text
固定风险 = 账户净值 × 单笔风险比例
仓位（名义价值）= 固定风险 / 止损距离

9.4 PC前端配置方案

9.4.1 配置路径
PC前端配置路径为：**SignalServiceManagement（信号服务管理）→ WeightRuleEngine（权重规则引擎）**。

操作流程如下：
1. 登录PC前端（ai-frontend-web），进入「市场」→「信号服务管理」页面
2. 在左侧表单中选择或创建信号服务配置（选择服务类、填写配置名称、设置参数）
3. 在「配置列表」表格中，每行右侧显示该配置的权重规则状态（已启用/已关闭/未配置）及规则数
4. 点击「管理」按钮跳转到WeightRuleEngine页面，或直接在左侧表单底部的「权重规则引擎」摘要区点击进入
5. 在WeightRuleEngine页面完成规则编辑后点击「保存全部」，前端自动将规则序列化为WeightRuleConfig JSON写入数据库

9.4.2 规则编辑器功能
WeightRuleEngine页面分为以下区域：

**规则列表（左侧面板，约30%宽度）**：显示当前信号配置下的所有规则，每条规则展示名称、类型标签（VETO红色/SCORING蓝色）、条件数量、评分/否决权值、独立启用开关和删除按钮。点击选中某条规则进入编辑器。

**规则编辑器（右侧上半部分）**：
- 规则名称：文本输入
- 规则类型：下拉选择 VETO（否决）或 SCORING（评分）
- 评分值（SCORING）：数字输入（-10~10，步长0.5）
- 否决权重（VETO）：数字输入（0~1，步长0.1）
- 条件匹配模式：下拉选择 AND（全部满足）或 OR（任一满足）
- 条件列表：动态行编辑器，每行包含：
  - 指标选择器：从 `/api/rule-engine/indicators` 动态获取可用指标列表（如 SMC_RANGE_PERCENT_20H、SIGNAL_DIRECTION、SMC_4H_WAVE 等）
  - 方向选择：BOTH（双向）/ LONG（多头）/ SHORT（空头）
  - 运算符：根据所选指标动态展示（EQ/NEQ/GT/GTE/LT/LTE/BETWEEN/IN/NOT_IN）
  - 值输入：根据valueType切换组件（NUMERIC→数字输入框，ENUM→下拉选择，BOOLEAN→开关，STATE→可输入下拉）
  - 参数配置：支持 dataPeriod、timeframe 等动态参数
  - 特殊条件渲染：SMC_MARKET_TREND 显示复合趋势状态下拉，PATTERN_TYPE 支持多选K线形态，MACD 支持金叉死叉等特殊选择
  - 添加/删除条件按钮

**引擎控制（页面顶部）**：
- 信号配置切换下拉框（选择要编辑的配置）
- 引擎启用/关闭总开关
- 版本历史按钮（查看和恢复历史版本）
- 保存全部按钮
- 评分设置按钮（弹出设置窗口：vetoContributeScore 是否参与评分、mappingMode 阶梯/线性切换、线性映射斜率/最小最大乘数参数）

9.4.3 默认规则模板
创建新的信号服务配置并首次进入WeightRuleEngine时，系统不预加载默认规则。交易员需手动添加§9.1和§9.2定义的规则。

建议的操作顺序：
1. 先添加11条VETO规则（订单0~10），确保硬性过滤先到位
2. 再添加18条SCORING规则（订单10~27），按波次加分→位置评分→环境调优→HL/LH健康度→年龄评分→混沌特例的顺序依次添加
3. 点击「保存全部」写入数据库

每条规则的条件详情参照§9.1和§9.2的规则定义表，在条件编辑器中依次选择对应的指标、运算符和阈值。

9.4.4 测试沙盒
WeightRuleEngine页面右侧下半部分为内嵌测试面板，功能描述如下：

**输入参数**：
- 方向（BUY/SELL）
- 交易对（如 BTC-USDT-SWAP）
- 当前价格
- 市场趋势（BULLISH/BEARISH/NEUTRAL，选填）
- SMC上下文（选填，折叠面板）：
  - 评分字段：趋势评分（0~5）、位置评分（0~5）、盈亏比（0~10）、15m位置评分（0~5）、风险百分比（0~10）
  - 状态字段：在OB内、方向一致、在供应区、在需求区、摆动突破、星期、摆动盘整、OB盘整

**测试结果输出**：
- VETO裁决：若被否决则显示警告提示及否决原因
- 最终权重值（颜色标识：绿色≥1.5重仓、黄色≥1.0正常、灰色<1.0轻仓）
- 总评分
- 规则执行数
- 迹线明细表格：每条规则的执行记录（规则名、类型标签、匹配状态图标、贡献分、原因说明、「查看条件详情」按钮）
- 条件详情弹框：每个条件的指标/运算符/方向/预期值/实际值/匹配状态
- 指标快照标签列表：显示所有指标的计算值

9.4.5 保存与版本管理
保存流程：
1. 点击「保存全部」按钮
2. 前端收集当前规则列表、scoringConfig、enabled状态，组装为WeightRuleConfig对象
3. 调用后端API `PUT /api/signal-service/configs/{id}/weight-rules`，将WeightRuleConfig作为请求体
4. 后端使用Jackson将WeightRuleConfig序列化为JSON字符串，写入 `signal_service_config.weight_rules_json` TEXT列
5. 后端同步调用 WeightRuleVersionService.createSnapshot() 创建当前规则的版本快照（含完整JSON和操作时间戳）
6. 前端显示保存成功提示

版本管理：
- 每次「保存全部」自动创建版本快照（非手动触发），存储于版本表
- 点击「版本历史」可查看所有历史版本列表及创建时间
- 支持选择历史版本恢复（将回滚到该版本的规则配置）

9.4.6 运行时执行流程
权重规则引擎在运行时从数据库加载配置的流程：
1. `SignalServiceConfigService.getWeightRules(serviceKey)` 从DB加载 `weight_rules_json`
2. Jackson反序列化为 `WeightRuleConfig` 对象
3. `WeightRuleEngine.evaluate()` 分两轮执行：
   - 第1轮：VETO检查（11条规则按序执行，任一匹配则否决，输出否决权重）
   - 第2轮：SCORING评分（18条规则按序执行，累计评分后调用 scoreToWeight() 映射为最终乘数）
4. 返回评估结果（是否否决、最终权重、总评分、迹线明细）

12.2 核心设计原则
原则	说明
波次 = HH + HL 双验证	只创新高但HL降低，波次不递增
熔断 = 振幅 + 翻转频率	窄幅直接熔断；中幅+翻转≥3熔断；宽幅不熔断
年龄不作为VETO	年龄只做SCORING加减分
VETO只留给硬指标	熔断、追高追空、波次不合格、衰竭衰老、HL/LH破位、盈亏比<1.2、仓位>2%
日常止损看15M/1H	止损距离 0.5%~1.0%
终极止损看4H	趋势结构被破坏才触发
阶梯式移动止损	只在新的有效结构点形成时调整
TP1触发保本	价格达到TP1后止损移至入场价
以损定量	固定风险 ÷ 止损距离 = 仓位
