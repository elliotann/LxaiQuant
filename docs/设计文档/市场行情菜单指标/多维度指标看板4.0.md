灵猞AI·多维引擎 — 行情看板指标完整设计文档（v4.0 最终归档版）
1. 概述
   1.1 项目背景
   本指标基于 Smart Money Concepts (SMC) 订单流理论，结合多时间框架结构分析，为交易者提供市场趋势状态识别、多周期方向监控、关键点位输出及风控数据。后端采用 Java + ta4j 0.22.6 实现 SMC 核心逻辑，前端基于 Vue3 + Element Plus + Vite + Lightweight Charts 展示浮动面板。

1.2 核心功能
多周期（3M、15M、1H、4H、1D）方向实时监控

7 种细化趋势状态自动识别（基于 4H 结构）

精细化复合市场状态（21 种），用于策略精细化决策

核心风控数据：机构共振（4/5 阈值）、市场基因

关键点位输出：按入场/止损/止盈分类的订单块、流动性池、FVG

距离百分比：每个点位距离当前价格的偏离百分比

三种可执行的交易模式（顺势交易、回调/回踩交易、回调波段交易）

SMC 结构跟踪移动止损（支持自动/手动模式）

初始止损偏移（避免毛刺扫损）

1.3 适用场景
趋势跟踪交易

回调/反弹入场时机筛选

多周期方向一致性验证

短线波段与中长线趋势结合

2. SMC 核心逻辑
   2.1 基本概念
   术语	含义
   BOS (Break of Structure)	突破前一个摆动高点（HH）或低点（LL），趋势延续
   CHoCH (Change of Character)	突破最后一个更高的低点（HL）或更低的高点（LH），趋势可能反转
   订单块 (Order Block)	机构启动趋势前的最后一根反向K线，提供支撑/阻力
   流动性池	前期高点/低点（EQH/EQL），机构常在此触发止损单
   FVG (公允价值缺口)	三根K线中间未重叠的价格真空区，大概率回补
   2.2 多时间框架分工
   周期	角色	主要用途
   1D	超长期趋势定调	识别大级别 Swing BOS/CHoCH
   4H	主趋势定调	识别 Swing BOS/CHoCH，输出 7 种趋势状态
   1H	关键位置	提供 Swing 订单块、前高/前低作为支撑/阻力
   15M	内部结构与精确入场	提供 内部订单块、检测回调/反弹结束信号（Internal BOS）
   3M	超短结构确认	不独立生成订单块，仅用于价格回踩确认和拒绝 K 线识别
   重要：1H 周期 只输出 Swing 订单块，不参与内部订单块的生成；15M 周期 只输出内部订单块，不参与 Swing 订单块的生成。3M 周期不输出独立订单块。

2.3 7 种细化趋势状态（简表）
状态代码	中文名称	4H 结构特征	操作含义
STRONG_BULLISH	强上升	连续 Swing BOS ↑，HH+HL 序列	持仓，移动止损
BULLISH_PULLBACK	上升回调	主趋势向上，价格回落未破最后一个 HL	等待回调结束
BULLISH_ENDING	上升末端	出现向下的 CHoCH（跌破 HL）	多单离场，警惕转势
STRONG_BEARISH	强下降	连续 Swing BOS ↓，LH+LL 序列	持仓空单，移动止损
BEARISH_PULLBACK	下降反弹	主趋势向下，价格反弹未破最后一个 LH	等待反弹结束
BEARISH_ENDING	下降末端	出现向上的 CHoCH（涨破 LH）	空单离场，警惕转势
RANGING	完全震荡	无清晰 BOS，价格区间运行	停止趋势策略
2.4 主趋势状态底层逻辑（最终算法）
利用 4H 周期的 swingTrend、摆动点和趋势生命线（lastHigherLow / lastLowerHigh）判定：

java
if (trend == 1) {                     // 上升趋势
if (close < lastSwingLow) {
if (close > lastHigherLow) -> "上升回调"
else -> "上升末端"
} else -> "强上升"
}
else if (trend == -1) {               // 下降趋势
if (close > lastSwingHigh) {
if (close < lastLowerHigh) -> "下降反弹"
else -> "下降末端"
} else -> "强下降"
}
else -> "完全震荡"

### 2.4.1 各状态的脚本可视化详解

**强上升**
- 图表标签：最近一次 Swing BOS 为绿色实线（bullishBOS）。
- 摆动点：依次出现 HH、HL，且 HL 不断抬高。
- 价格位置：始终运行在最后一个 HL 之上。
- 订单块：下方存在至少一个未破坏的看涨订单块（绿色半透明矩形）。
- 内部结构：15M 周期的 Internal BOS 以绿色虚线为主。
- 无红色 CHoCH 虚线。

**上升回调**
- 图表标签：可能出现红色虚线 CHoCH（警告）。
- 价格行为：从近期高点回落，跌破最近的一个摆动低点（lastSwingLow），但未跌破更高的低点（lastHigherLow）。
- 订单块：看涨订单块可能被部分穿透（中度穿透），但未完全失效。

**上升末端**
- 图表标签：已出现红色虚线 CHoCH。
- 价格行为：跌破最后一个更高的低点（lastHigherLow），上升生命线失守。
- 订单块：看涨订单块可能已被实体击穿（消失）。

**强下降**
- 图表标签：最近一次 Swing BOS 为红色实线（bearishBOS）。
- 摆动点：依次出现 LL、LH，且 LH 不断降低。
- 价格位置：始终运行在最后一个 LH 之下。
- 订单块：上方存在至少一个未破坏的看跌订单块（红色半透明矩形）。
- 内部结构：15M 周期的 Internal BOS 以红色虚线为主。
- 无绿色 CHoCH 虚线。

**下降反弹**
- 图表标签：可能出现绿色虚线 CHoCH（警告）。
- 价格行为：从低点反弹，涨破最近的一个摆动高点（lastSwingHigh），但未突破更低的高点（lastLowerHigh）。
- 订单块：看跌订单块可能被部分穿透（中度穿透），但未完全失效。

**下降末端**
- 图表标签：已出现绿色虚线 CHoCH。
- 价格行为：突破最后一个更低的高点（lastLowerHigh），下降生命线失守。
- 订单块：看跌订单块可能已被实体击穿（消失）。

**完全震荡**
- 图表标签：无清晰 BOS 或 CHoCH 实线/虚线。
- 价格行为：在明显的水平区间内运行，出现多个 EQH（等高点）和 EQL（等低点）。
- 订单块：频繁形成并被快速击穿。
- 内部结构：15M 的 Internal BOS 方向快速切换。

### 2.4.2 状态转换典型路径

- 上升趋势完整周期：强上升 → 上升回调 → 上升末端 → 强下降（趋势反转）
- 回调后重新走强：强上升 → 上升回调 → 价格重新站上 lastSwingLow → 回到强上升（注意 lastHigherLow 可能已更新）
- 震荡状态进入：当 swingTrend == 0 或价格在区间内无明确方向时，进入完全震荡。

2.7 事件类型持久化（SmartMoneyConceptsIndicator 增强）
为保证复合状态判断的稳定性和重启一致性，在 Result 类中增加了持久化字段：

java
private int lastInternalEventType; // 0=无, 1=BOS, 2=CHoCH
private int lastSwingEventType;
在 calculate() 中，先复制上一根 K 线的值，然后在 detectStructureBreaks() 事件发生时覆盖为对应值。

利用 CachedIndicator 的缓存机制，保证事件类型随 K 线传递。

外部调用通过 getLastInternalEventType() / getLastSwingEventType() 获取最近事件类型。

3. 交易模式与多时间框架协同
   3.1 三种交易模式定义
   模式	方向依据	持仓目标	适用场景
   顺势交易	顺 4H 趋势，顺 1H 小趋势	4H 前高/低	趋势流畅，浅回调
   回调/回踩交易（顺大势逆小势）	顺 4H 趋势，等 1H 回调结束	4H 前高/低	4H 趋势健康，1H 深度回调
   回调波段交易（顺小势逆大势）	顺 1H 趋势（逆 4H 方向）	1H 前高/低	4H 趋势未变，但 1H 出现明显反向波段
   3.2 订单块类型与使用规则（无歧义）
   3.2.1 两种订单块的定义
   类型	英文	形成基础	可靠性	典型距离
   内部订单块	Internal Order Block	最近 5 根 K 线的内部结构	中等（易失效）	近（当前价格附近）
   摆动订单块	Swing Order Block	最近 50 根 K 线的摆动高低点	高（不易失效）	远（有较大空间）
   3.2.2 各交易模式强制使用的订单块类型
   交易模式	入场订单块类型（主）	辅助/止盈订单块类型
   顺势交易	内部订单块（来自 15M 或 1H）	摆动订单块（作为止盈）
   回调/回踩交易（顺大势逆小势）	摆动订单块（来自 1H）	内部订单块（15M 辅助确认）
   回调波段交易（顺小势逆大势）	摆动订单块（来自 1H）	摆动订单块或流动性池（止盈）
   规则不可交叉：例如顺势交易 不得 使用 Swing 订单块入场，反之亦然。若 1H 没有有效摆动订单块，则放弃回调/回踩交易和回调波段交易，不降级使用内部订单块。

3.2.3 入场订单块的周期优先级（距离优先）
在同一个交易模式下，若存在多个相同类型的订单块，选择 距离当前价格最近 的那个。周期优先级如下：

顺势交易：15M 内部订单块 > 1H 内部订单块

回调/回踩交易：1H 摆动订单块 唯一，不考虑其他周期

回调波段交易：1H 摆动订单块 唯一，不考虑其他周期

3.3 订单块有效性判定（量化规则）
3.3.1 有效条件（入场前检查）
订单块类型	方向	有效条件
看涨内部订单块 / 看涨摆动订单块	支撑	当前价格 > 订单块低点
看跌内部订单块 / 看跌摆动订单块	阻力	当前价格 < 订单块高点
3.3.2 失效条件（移除不再使用）
条件	判定标准
实体穿透（严格）	收盘价彻底越过订单块边界（看涨块：收盘价 ≤ 低点；看跌块：收盘价 ≥ 高点）
中度穿透（削弱）	价格影线刺破边界超过 订单块高度的 30% 或 0.3% 当前价格。此时该订单块 不再作为入场区，但仍可作为止盈参考。
所有订单块在每根新 K 线收盘后重新评估有效性，失效的立即从关键点位列表中移除。

3.3.3 “附近”的量化定义（用于判断价格是否回踩）
严格回踩：价格的最低价（做多）或最高价（做空） 进入订单块内部（即 ≤ 块高点 且 ≥ 块低点）。

可接受回踩：价格距离订单块边界 ≤ 0.2 × ATR(14) 或 ≤ 0.1% 当前价格。
入场信号要求 至少满足可接受回踩，并出现拒绝 K 线。

3.4 三种交易模式的完整执行流程
3.4.1 顺势交易（做多示例）
步骤	周期	动作	信号 / 规则
1	4H	确认状态	强上升
2	1H	找到入场订单块	内部订单块（看涨），且当前价格 > 块低点
3	15M	等待内部结构转换	出现 向上的绿色虚线 BOS（回调结束）
4	3M	精确入场	价格回踩 1H 内部订单块（满足 3.3.3），出现长下影线或看涨吞没 → 做多
5	1H	止损	订单块最低点下方 1-2 点
6	1H	止盈	第一目标：1H 前高；第二目标：4H 前高（或摆动订单块）
做空：对称操作，使用看跌内部订单块，等待 15M 向下的红色虚线 BOS。

3.4.2 回调/回踩交易（顺大势逆小势）（做多示例）
步骤	周期	动作	信号 / 规则
1	4H	确认状态	上升回调（最后一个 HL 未破）
2	1H	找到入场订单块	摆动订单块（看涨），当前价格 > 块低点
3	15M	等待回调结束信号	先出现向下红色虚线（回调进行），后出现 向上绿色虚线（回调结束）
4	3M	精确入场	价格回踩 1H 摆动订单块内部，出现长下影线 → 做多
5	1H	止损	订单块最低点下方
6	1H	止盈	第一目标：1H 前高；第二目标：4H 前高
做空：对称操作，使用看跌摆动订单块，15M 先向上绿色虚线后向下红色虚线。

4.4 Java 实现提示
使用 ScheduledExecutorService 每 30 秒计算一次最新数据并缓存。

5 个周期分别维护 BarSeries 和 SmartMoneyConceptsIndicator 实例。

周期数据对齐：以最新时间为基准，取每个周期当前未完成 K 线或已收盘 K 线。

订单块有效性检查：价格已穿过订单块区间的过滤掉。

止损价计算：做多时 stopLoss = orderBlockLow * (1 - stopLossFactor)；做空时 stopLoss = orderBlockHigh * (1 + stopLossFactor)。stopLossFactor 可由初始止损偏移配置覆盖。

distancePercent：止损点位取负值，止盈点位取正值。绝对值公式：Math.abs(price - currentPrice) / currentPrice * 100。

复合状态判定：调用 SmcTrendUtils.getDetailedTrendState() 获取 CompositeState。

核心要点：

7.4 算法逻辑
开仓时，根据交易模式和复合状态确定入场订单块，然后计算初始止损价格：

java
public double calculateInitialStopLoss(OrderBlock entryOb,
boolean isLong,
InitialStopOffsetConfig config) {
double baseStop = isLong ? entryOb.barLow : entryOb.barHigh;
if (!config.isEnabled()) return baseStop;
double offset = "percent".equals(config.getMode())
? baseStop * config.getValue() / 100.0
: config.getValue();
return isLong ? baseStop - offset : baseStop + offset;
}
订单块选择规则：

若 fixed15mOrderBlock 为 true → 使用 15M 内部订单块。

否则，若 stopLossObSameAsTarget 为 true → 使用与止盈目标周期相同的订单块。

其他情况 → 使用默认入场订单块（由复合状态和交易模式决定）。

9. 使用流程示例
   后端启动：加载历史 K 线，初始化各周期 SMC 指标。

定时计算（每30秒）：

获取 4H、1H、15M 最新 Result 对象。

调用 SmcTrendUtils.getDetailedTrendState() 得到 CompositeState。

调用 SmcCriticalLevelCalculator.calculateForState() 得到关键点位（应用初始止损偏移）。

填充 CoreData（包含 trendState 和 compositeState）和 criticalLevels 并缓存。

前端轮询：每30秒请求 API，更新面板显示。

策略决策：

根据 compositeState 执行开仓、加仓、减仓等操作。

开仓时使用配置的初始止损偏移。

每根新 K 线调用 SmcTrailingStopManager.updateStopLoss 更新持仓止损（结构跟踪）。

移动止损：自动模式下根据复合状态自动调整参数；手动模式下使用用户预设挡位。

10. 注意事项
    数据延迟：后端每 30 秒缓存刷新。

订单块失效：价格实体穿过订单块后自动从关键点位中剔除。

止损点位的动态性：移动止损根据结构点实时更新；初始止损基于订单块加偏移。

震荡市识别：当 4H 无清晰 BOS 且 1H 频繁 CHoCH 时，判定为震荡。

多周期对齐：以 4H 时间戳为基准。

性能：后端缓存计算结果，避免全量重算；调度器已正确关闭。
