# 关键点位策略模块设计文档

## 1. 背景与目标

当前关键点位计算逻辑（`SmcCriticalLevelsCalculator.buildByDirection()`）是静态方法，**所有机器人共享同一套算法**。后续需要支持不同机器人有不同的计算逻辑（如入场距离容忍度、止损偏移系数、止盈优先级等差异化策略），因此需要将关键点位计算抽象为**可扩展的策略体系**。

> **当前状态**：策略接口体系已搭建完成（阶段 1~4 ✅），`DefaultIndicatorCriticalLevelsStrategy` 和 `DefaultSignalCriticalLevelsStrategy` 已投入使用，行为与改造前一致。
>
> **后续规划**：机器人差异化扩展（参见[待办清单](../执行清单/关键点位策略模块-执行清单.md#待办后续优化项当前保持旧逻辑后续改造)）为下一阶段目标，当前所有机器人仍使用默认策略。

## 2. 模块定位

策略接口定义和核心数据对象放在 **`ai-extension`** 模块。

理由：

- `ai-extension` 是 TA4J 生态扩展库，`SmcCriticalLevelsCalculator` 已在此模块，策略接口定义在核心计算引擎旁边，语义合理
- `ai-extension` 无 Spring 框架依赖，适合放纯接口和 POJO
- `ai-signal` 和 `ai-quant` 均已依赖 `ai-extension`，无循环依赖问题
- 策略的具体实现和路由放在各自的消费方模块（`ai-quant` / `ai-signal`），互不干扰

## 3. 模块依赖关系

```
ai-extension (纯接口 + 核心计算引擎)
    ↑                ↑
ai-signal        ai-quant
(信号驱动策略实现)   (指标驱动策略实现)
    ↑                ↑
ai-strategy ─────────┘
```

## 4. 总体架构

采用**策略模式**，核心计算接口定义在 `ai-extension`，两个子接口分别对应两种驱动方式，具体实现分别在 `ai-quant`（指标驱动）和 `ai-signal`（信号驱动）。

## 5. 接口定义

### 5.1 核心计算接口

```java
public interface CriticalLevelsStrategy {
    List<CriticalLevel> calculate(
        Map<String, SmartMoneyConceptsIndicator.Result> results,
        String direction,
        double currentPrice
    );
}
```

只做一件事：给定 SMC 多周期计算结果 + 方向 + 当前价格，返回关键点位列表。不关心方向和过滤条件从哪来。

### 5.2 指标驱动子接口（行情看板用）

```java
public interface IndicatorCriticalLevelsStrategy extends CriticalLevelsStrategy {
    String resolveDirection(
        Map<String, SmartMoneyConceptsIndicator.Result> results,
        String trendState
    );

    String resolveEntryObFilter(
        Map<String, SmartMoneyConceptsIndicator.Result> results,
        String trendState
    );
}
```

在 `calculate` 之外额外提供两个方法，用于行情看板场景下推导方向和入场 OB 过滤条件。不同机器人可覆盖这两个方法实现差异化。

### 5.3 信号驱动子接口（信号生成用）

```java
public interface SignalCriticalLevelsStrategy extends CriticalLevelsStrategy {
    CriticalLevelsConfig getConfig();
}
```

方向由信号自身提供，过滤固定为 `"ALL"`，差异化体现在参数配置上。

### 5.4 参数配置 POJO

```java
@Data
@Builder
public class CriticalLevelsConfig {
    private String entryObTypeFilter = "ALL";
    private BigDecimal maxEntryDistancePct = BigDecimal.valueOf(3.0);
    private BigDecimal stopLossFactor = BigDecimal.valueOf(0.002);
    private BigDecimal dedupPriceTolerance = BigDecimal.valueOf(0.0001);
    private boolean tp1PreferSwing = true;
    private boolean tp2PreferLiquidity = true;
    private List<String> enabledPeriods = List.of("15M", "1H", "4H", "1D");
}
```

> **当前状态**：POJO 已定义，但 `SmcCriticalLevelsCalculator` 和默认策略实现中暂未读取该配置（仍使用硬编码参数）。此为后续优化项（见[待办 T3](../执行清单/关键点位策略模块-执行清单.md#t3关键点位策略可配置化criticallevelsconfig-扩展)）。

## 6. 策略实现与路由

### 6.1 指标驱动侧（ai-quant）

```java
// 默认实现（当前逻辑）
@Component
public class DefaultIndicatorCriticalLevelsStrategy implements IndicatorCriticalLevelsStrategy {
    public String resolveDirection(results, trendState) {
        // 默认方向推导逻辑
    }
    public String resolveEntryObFilter(results, trendState) {
        // 默认 OB 过滤推导逻辑
    }
    public List<CriticalLevel> calculate(results, direction, price) {
        String filter = resolveEntryObFilter(results, trendState);
        return SmcCriticalLevelsCalculator.buildByDirection(results, direction, price, filter);
    }
}

// 路由
@Component
public class IndicatorStrategyRouter {
    public IndicatorCriticalLevelsStrategy resolve(String robotId) {
        // 按 robotId 匹配策略，未匹配返回默认
    }
}
```

**关键点位展示差异**：指标驱动侧（行情看板）为挂单场景，入场显示 OB 价；止损 `distancePercent` 取负值（低于市价方向），止盈取正值。

**调用方**：`SmcMultiPeriodService` 注入 `IndicatorStrategyRouter`，替代当前直接调 `SmcCriticalLevelsCalculator.buildByDirection()` 的方式。

### 6.2 信号驱动侧（ai-signal）

信号驱动场景（信号悬浮框）使用**市价入场**，入场 key level 的 price 需覆盖为 `currentPrice`。

```java
// 默认实现（当前逻辑）
@Component
public class DefaultSignalCriticalLevelsStrategy implements SignalCriticalLevelsStrategy {
    public CriticalLevelsConfig getConfig() {
        return CriticalLevelsConfig.builder().build(); // 默认参数
    }
    public List<CriticalLevel> calculate(results, direction, price) {
        List<CriticalLevel> levels = SmcCriticalLevelsCalculator.buildByDirection(results, direction, price, "ALL");
        for (CriticalLevel level : levels) {
            if ("入场".equals(level.getAction())) {
                level.setPrice(price);            // 市价覆盖OB价
                level.setDistancePercent(0.0);    // 入场距离为0
            }
        }
        return levels;
    }
}

// 路由
@Component
public class SignalStrategyRouter {
    public SignalCriticalLevelsStrategy resolve(String robotId) {
        // 按 robotId 匹配策略，未匹配返回默认
    }
}
```

**调用方**：`DefaultSignService` 注入 `SignalStrategyRouter`，替代当前直接调 `SmcCriticalLevelsCalculator.buildByDirection()` 的方式。

## 8. 向后兼容

### 8.1 行为变化

重构后存在以下行为变化（均为优化修正，不改变核心开仓逻辑）：

| 变化项 | 改造前 | 改造后 | 影响范围 | 状态 |
|-------|--------|--------|---------|------|
| 信号驱动入场价 | OB 价 | **市价**（`currentPrice`） | 信号悬浮框 | ✅ 已实施 |
| 止损 distancePercent | 始终为正 | **负号**（SL 低于市价） | 行情看板 + 信号悬浮框 | ✅ 已实施 |
| 入场 distancePercent | 基于 OB 价计算 | **0**（市价入场） | 信号悬浮框 | ✅ 已实施 |

### 8.2 策略回退

- 新机器人在不注册策略的情况下自动使用默认实现
- 路由按 `robotId` 匹配，匹配不到就 fallback 到默认
