# 关键点位策略 — 复合状态(CompositeState)计算方案

## 1. 背景

当前 `DefaultIndicatorCriticalLevelsStrategy` 使用 7 种旧 `trendState`（强上升/上升回调/上升末端/强下降/下降反弹/下降末端/完全震荡）做方向推导和 OB 过滤，精确度有限。

**阶段 5** 已在看板展示层新增 21 种 `compositeState` 复合状态，但关键点位计算仍沿用旧 7 种状态。本方案基于 21 种 `CompositeState` 实现更精细化的关键点位计算。

## 2. 核心思路

将 21 种 `CompositeState` 映射为三类决策要素：

| 决策要素 | 取值 | 依据 |
|---------|------|------|
| **方向** | buy / sell / null | 状态的宏观方向归属 |
| **OB过滤** | INTERNAL_ONLY / SWING_ONLY / ALL | 趋势健康度 + 回调深度 |
| **入场策略** | 市价/挂单/等待 | 状态分类 |

## 3. 方向映射表

### 多头方向（返回 "buy"）

| 复合状态 | 含义 | 逻辑 |
|---------|------|------|
| STRONG_BULLISH_HEALTHY | 强上升·健康 | 多头趋势明朗 |
| STRONG_BULLISH_SHALLOW_PULLBACK | 强上升·浅回调 | 多头短期回调 |
| STRONG_BULLISH_WARNING_1H | 强上升·预警回调(1H) | 多头预警 |
| STRONG_BULLISH_WARNING_4H | 强上升·预警回调(4H) | 多头预警 |
| STRONG_BULLISH_CONFIRMED_PULLBACK | 强上升·确认回调 | 多头回调确认 |
| BULLISH_PULLBACK_ONGOING | 上升回调·进行中 | 多头回调未结束 |
| BULLISH_PULLBACK_BOTTOMING | 上升回调·筑底 | 多头回调筑底 |
| BULLISH_PULLBACK_FAILURE | 上升回调·失败 | 回调失败，延续多头 |
| BULLISH_ENDING_CONTINUE_DOWN | 上升末端·延续下跌 | ⚠️ 转空方向 |
| BULLISH_ENDING_CONFIRM | 上升末端·转势确认 | ⚠️ 转空方向 |

| 复合状态 | 含义 | 逻辑 |
|---------|------|------|
| STRONG_BEARISH_HEALTHY | 强下降·健康 | 空头趋势明朗 |
| STRONG_BEARISH_SHALLOW_BOUNCE | 强下降·浅反弹 | 空头短期反弹 |
| STRONG_BEARISH_WARNING_1H | 强下降·预警反弹(1H) | 空头预警 |

| 复合状态 | 含义 |
|---------|------|

## 4. OB 过滤映射表

OB 过滤决定了关键点位入场时使用哪类订单块：

| 过滤级别 | 含义 | 适用复合状态 |
|---------|------|-------------|
| **INTERNAL_ONLY** | 只取内部OB（严格） | 健康趋势、浅回调/反弹 |
| **SWING_ONLY** | 只取Swing OB（放宽） | 预警回调、回调进行中、回调失败 |
| **ALL** | 全部OB（最宽松） | 筑底/筑顶、末端阶段 |

### INTERNAL_ONLY（严格 — 健康趋势）

```
STRONG_BULLISH_HEALTHY        → 强上升·健康
STRONG_BEARISH_HEALTHY        → 强下降·健康
STRONG_BULLISH_SHALLOW_PULLBACK  → 强上升·浅回调
STRONG_BEARISH_SHALLOW_BOUNCE    → 强下降·浅反弹
```

逻辑：趋势健康，价格在有利方向推进，只需最接近的内部OB作为入场挂单价。

### SWING_ONLY（放宽 — 回调/预警）

```
STRONG_BULLISH_WARNING_1H     → 强上升·预警回调(1H)
STRONG_BULLISH_WARNING_4H     → 强上升·预警回调(4H)
STRONG_BULLISH_CONFIRMED_PULLBACK → 强上升·确认回调
STRONG_BEARISH_WARNING_1H     → 强下降·预警反弹(1H)
STRONG_BEARISH_WARNING_4H     → 强下降·预警反弹(4H)
STRONG_BEARISH_CONFIRMED_BOUNCE  → 强下降·确认反弹
BULLISH_PULLBACK_ONGOING      → 上升回调·进行中
BEARISH_PULLBACK_ONGOING      → 下降反弹·进行中
BULLISH_PULLBACK_FAILURE      → 上升回调·失败
BEARISH_PULLBACK_FAILURE      → 下降反弹·失败
```

逻辑：价格回调/反弹阶段，内部OB可能已被突破，需查看Swing OB寻找更宽的入场区间。

### ALL（最宽松 — 筑底/末端）

```
BULLISH_PULLBACK_BOTTOMING    → 上升回调·筑底
BEARISH_PULLBACK_TOPPING      → 下降反弹·筑顶
BULLISH_ENDING_CONTINUE_DOWN  → 上升末端·延续下跌
BULLISH_ENDING_CONFIRM        → 上升末端·转势确认
BEARISH_ENDING_CONTINUE_UP    → 下降末端·延续反弹
BEARISH_ENDING_CONFIRM        → 下降末端·转势确认
```

逻辑：趋势末端或筑底/筑顶阶段，市场结构不稳定，需尽可能多的OB信息来辅助判断。

## 6. 切换方案

### 当前（保留旧策略）

- `DefaultIndicatorCriticalLevelsStrategy` + `DefaultSignalCriticalLevelsStrategy`: 稳定运行
- `CompositeIndicatorCriticalLevelsStrategy` + `CompositeSignalCriticalLevelsStrategy`: 新增，未被路由命中

### 后续切换

**方式一：修改路由默认策略**

```java
// IndicatorStrategyRouter.init() 中
// 将 defaultStrategy 从 Default → Composite
defaultStrategy = applicationContext.getBean(CompositeIndicatorCriticalLevelsStrategy.class);
```

**方式二：按 robotId 灰度**

```java
// IndicatorStrategyRouter.resolve() 中
// 指定机器人走复合策略，其余走旧策略
if ("robot_xxx".equals(robotId)) {
    return compositeStrategy;
}
return defaultStrategy;
```

**方式三：A/B 对比测试**

在 `SmcMultiPeriodService` 中同时计算两种策略的结果，写入日志对比差异，确认无异常后切换。

## 7. 信号驱动侧差异（Signal）

信号驱动的 `CompositeSignalCriticalLevelsStrategy` 额外处理：

| 场景 | 处理 |
|------|------|
| 入场价 | 覆盖为 `currentPrice`（市价入场） |
| 入场 distancePercent | 设为 0.0 |
| OB过滤 | 同指标驱动侧规则，但方向由信号自身提供 |
