# 社区市场 (Community Market) 开发设计文档

## 1. 背景与目标

### 1.1 背景
目前系统已支持用户**自行创建**交易机器人（手动配置、AI 智能创建、指标驱动型），以及使用各种技术指标，但缺少一个**社区市场**让用户发现、购买、分享优秀的交易策略资产。

### 1.2 目标
- 搭建一个统一的**社区市场**，支持多种商品类型：交易机器人、技术指标、策略模板、交易信号等
- 支持**积分购买**商品，购买后可基于模板创建自己的实例
- 支持**发布自己的策略资产**到市场（可设置价格/免费），经审核后上架
- 按商品类型提供差异化的**表现数据**辅助用户决策
- 统一的浏览、搜索、筛选、评论、评分体验

### 1.3 参考系统
参考 QuantDinger-Vue-main `/indicator-community` 指标社区市场的完整流程：
- 市场首页：商品网格展示、搜索、筛选（免费/付费/类型）、排序（最新/热门/评分/价格）
- 详情页：概览信息、表现数据、评论区、购买/同步/使用按钮
- 购买流程：`POST /api/community-market/listings/{id}/purchase` → 成功回调
- 我的购买：已购列表 → 同步更新 → 使用
- 管理员审核：上架审核流程

## 2. 功能需求

### 2.1 市场首页 (浏览发现)
| 功能 | 描述 |
|------|------|
| 商品卡片网格 | 展示封面、名称、商品类型标签、价格标签、作者、评分、购买数 |
| 商品类型 Tab 切换 | 全部 / 机器人 / 指标 / 策略模板 / 信号 |
| 搜索 | 按关键字搜索商品名称/描述 |
| 价格筛选 | 全部 / 免费 / 付费 |
| 排序 | 综合排序 / 最新发布 / 最热门 / 评分最高 / 价格从低到高 / 价格从高到低 |
| 标签筛选 | 按商品标签（如"网格"、"缠论"、"趋势跟踪"等）筛选 |
| 分页 | 支持分页加载 |

### 2.2 商品详情
| 功能 | 说明 |
|------|------|
| 通用信息 | 名称、描述、作者、发布时间、价格、商品类型标签 |
| 差异化配置区 | 按商品类型展示不同内容（详见 5.2.2） |
| 表现数据 | 按商品类型展示不同维度的表现指标 |
| 标签 | 策略类型标签、风险等级标签等 |
| 操作按钮 | 免费获取 / 购买 / 已购-创建实例 / 已购-同步更新 / 我的商品(不可操作) |

### 2.3 购买流程
1. 用户点击"购买"按钮
2. 系统检查积分余额是否充足
3. 弹窗确认："确认花费 X 积分购买该[商品类型]？"
4. 确认后调用购买接口
5. 成功：提示购买成功，按钮变为"创建实例"
6. 失败：提示具体原因（积分不足、已购买等）

### 2.4 已购管理
| 功能 | 描述 |
|------|------|
| 我的已购列表 | 展示已购买的所有商品（含类型标识） |
| 创建实例 | 基于已购商品模板创建自己的实例 |
| 同步更新 | 当发布者更新商品后，已购用户可同步最新配置 |

### 2.5 发布商品
| 功能 | 描述 |
|------|------|
| 选择商品类型 | 第一步选择要发布的类型：机器人 / 指标 / 策略模板 |
| 选择源商品 | 从自己拥有的该类商品中选择要发布的（如从我的机器人列表选一个） |
| 定价设置 | 设置价格（0 为免费发布）或选择仅 VIP 免费 |
| 发布信息 | 编辑名称、描述、封面图、标签等 |
| 配置快照 | 系统自动生成当前配置快照，购买者基于此创建实例 |
| 提交审核 | 发布后进入审核状态 |

### 2.6 管理后台
| 功能 | 描述 |
|------|------|
| 审核列表 | 查看待审核/已通过/已拒绝的发布申请，可按商品类型筛选 |
| 审核操作 | 通过（上架）/ 拒绝（填写原因）/ 下架 |
| 审核统计 | 待审核数量、已通过数量、已拒绝数量（按类型统计） |

## 3. 数据模型设计

### 3.1 核心表 - `community_market_listings`（市场商品表）

引入 `product_type` 区分商品类型，`source_id` 替代原 `source_bot_id`，`config_snapshot` 存储配置快照 JSON，`tags` 存储标签数组。

```sql
CREATE TABLE `community_market_listings` (
    `id`             BIGINT       NOT NULL AUTO_INCREMENT,
    `product_type`   VARCHAR(16)  NOT NULL COMMENT '商品类型: bot/indicator/strategy/signal',
    `source_id`      VARCHAR(64)  NOT NULL COMMENT '源商品ID（机器人ID/指标ID/策略ID等）',
    `name`           VARCHAR(128) NOT NULL COMMENT '展示名称',
    `description`    TEXT                  COMMENT '描述',
    `preview_image`  VARCHAR(512)          COMMENT '预览图URL',
    `config_snapshot` TEXT                 COMMENT '配置快照(JSON)，购买时基于此模板创建实例',
    `pricing_type`   VARCHAR(16)  NOT NULL DEFAULT 'free'
                     COMMENT '定价类型: free/paid',
    `price`          DECIMAL(18,4)         DEFAULT 0 COMMENT '价格（积分）',
    `vip_free`       TINYINT(1)   NOT NULL DEFAULT 0 COMMENT 'VIP是否免费',
    `author_id`      VARCHAR(64)  NOT NULL COMMENT '发布者用户ID',
    `status`         VARCHAR(16)  NOT NULL DEFAULT 'pending'
                     COMMENT '状态: pending/approved/rejected/offline',
    `review_note`    TEXT                  COMMENT '审核备注',
    `reviewer_id`    VARCHAR(64)           COMMENT '审核人ID',
    `reviewed_at`    DATETIME              COMMENT '审核时间',
    `view_count`     INT          NOT NULL DEFAULT 0 COMMENT '浏览次数',
    `purchase_count` INT          NOT NULL DEFAULT 0 COMMENT '购买次数',
    `avg_rating`     DECIMAL(3,2)          DEFAULT 0 COMMENT '平均评分',
    `rating_count`   INT          NOT NULL DEFAULT 0 COMMENT '评分人数',
    `has_update`     TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '是否有更新',
    `tags`           VARCHAR(512)          COMMENT '标签(JSON数组)',
    `created_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_type_status` (`product_type`, `status`),
    KEY `idx_author` (`author_id`),
    KEY `idx_pricing` (`pricing_type`),
    KEY `idx_score` (`avg_rating`, `purchase_count`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='社区市场商品表';
```

### 3.2 `community_purchases` - 购买记录表

```sql
CREATE TABLE `community_purchases` (
    `id`               BIGINT       NOT NULL AUTO_INCREMENT,
    `listing_id`       BIGINT       NOT NULL COMMENT '市场商品ID',
    `user_id`          VARCHAR(64)  NOT NULL COMMENT '购买用户ID',
    `purchase_time`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `credits_spent`    DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '花费积分',
    `last_sync_time`   DATETIME     COMMENT '最后同步时间',
    `created_at`       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_user_listing` (`user_id`, `listing_id`),
    KEY `idx_user` (`user_id`),
    KEY `idx_listing` (`listing_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='社区市场购买记录表';
```

### 3.3 `community_performance` - 表现数据表

采用 JSON 字段存储不同商品类型的差异化表现指标，避免为每种类型建独立字段。

```sql
CREATE TABLE `community_performance` (
    `id`               BIGINT        NOT NULL AUTO_INCREMENT,
    `listing_id`       BIGINT        NOT NULL COMMENT '市场商品ID',
    `usage_count`      INT           NOT NULL DEFAULT 0 COMMENT '被使用次数',
    `performance_data` JSON                    COMMENT '表现数据(JSON, 按商品类型不同)',
    `updated_at`       DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_listing` (`listing_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品表现数据表';
```

**performance_data 不同商品类型的 JSON 结构示例**：

```json

  "trade_count": 100,
  "win_rate": 65.5,

// indicator（技术指标）
{
  "signal_count": 200,
  "accuracy": 72.3,
  "avg_response_time": 1.2,
  "hit_rate": 68.5
}

// strategy（策略模板）
{
  "backtest_ror": 35.6,
  "max_drawdown": 8.5,
  "sharpe_ratio": 2.1,
  "trade_count": 50,
  "profit_factor": 2.3

```

### 3.4 `community_comments` - 评论表

```sql
CREATE TABLE `community_comments` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT,
    `listing_id`  BIGINT       NOT NULL COMMENT '市场商品ID',
    `user_id`     VARCHAR(64)  NOT NULL COMMENT '评论用户ID',
    `rating`      TINYINT               COMMENT '评分 1-5',
    `content`     TEXT         NOT NULL COMMENT '评论内容',
    `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_listing` (`listing_id`),
    KEY `idx_user_listing` (`user_id`, `listing_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='社区市场评论表';
```

### 3.5 数据模型关系图

```
community_market_listings (核心商品表)
  ├── product_type: bot / indicator / strategy / signal
  ├── source_id → 关联各自业务表（机器人表 / 指标表 / 策略表等）
  ├── config_snapshot: 购买时复制此配置到用户实例
  └── tags: 通用标签体系

community_purchases → listing_id → community_market_listings.id
community_performance → listing_id → community_market_listings.id
community_comments → listing_id → community_market_listings.id
```

## 6. 购买与积分流程

### 6.1 购买流程

```
用户点击"购买"
  → 前端弹窗确认："确认花费 X 积分购买该[商品类型]？"
  → 确认 → POST /api/community-market/listings/{id}/purchase
  → 后端：
    1. 检查 listing 是否存在且已上架
    2. 检查用户是否已购买（已购买则直接返回成功）
    3. 如果是免费商品，直接创建购买记录
    4. 如果是付费商品：
       a. 检查用户积分余额 >= price
       b. 扣减用户积分
       c. 创建积分流水记录（类型：market_purchase）
       d. 给发布者增加积分（扣除平台手续费）
       e. 创建购买记录
    5. 返回购买成功
  → 前端：提示成功，刷新详情，刷新列表
```

### 6.2 创建实例流程（购买后）

```
用户点击"创建实例"
  → 根据 product_type 跳转至对应的创建页面
  → 携带 listing_id 参数
  → 创建页面从后端获取 config_snapshot（配置快照）
  → 预填配置，用户可修改参数
  → 提交 → 创建新的商品实例
```

**不同商品类型的创建目标**：
| 商品类型 | 创建实例跳转 |
|---------|-------------|
| bot | BotForm.vue（创建机器人表单） |
| indicator | 自动应用到指标配置 |
| strategy | EditStrategy.vue（策略编辑） |

### 6.3 同步更新流程

```
用户点击"同步更新"
  → POST /api/community-market/listings/{id}/sync
  → 后端：将发布者的最新配置快照复制到用户已有的实例中
  → 返回同步结果
```

### 6.4 积分流转
| 步骤 | 操作 | 说明 |
|------|------|------|
| 购买时 | 买家积分 -price | 扣除买家积分 |
| 结算时 | 卖家积分 +price × (1 - fee_rate) | 给发布者结算，扣除平台手续费 |
| 免费时 | 无积分变动 | 仅记录购买 |

### 7.2 策略模式处理不同商品类型

引入 `ProductMarketHandler` 接口，各商品类型各自实现差异化逻辑：

```java
public interface ProductMarketHandler {
    /** 返回处理的商品类型 */
    ProductType getType();

    /** 验证源商品是否可发布 */
    void validateSource(String sourceId, Long userId);

    /** 获取配置快照 */
    String getConfigSnapshot(String sourceId);

    /** 购买后的业务逻辑（如创建关联记录） */
    void onPurchaseComplete(Long userId, Long listingId);

    /** 同步更新 */
    void syncUpdate(Long userId, Long listingId);
}
```

| 实现类 | 说明 |
|--------|------|
| `BotProductHandler` | 机器人商品的发布验证、配置快照生成、购买后处理 |
| `IndicatorProductHandler` | 指标商品的发布验证、配置快照生成 |
| `StrategyProductHandler` | 策略模板的发布验证、配置快照生成 |

**说明**：在 `ai-member` 模块中开发，利用已有的积分系统 (`ICreditsService`)、用户系统 (`IUserService`) 和 RBAC 权限体系。

## 10. 注意事项

1. **权限控制**：只有已上架的商品对所有用户可见；未登录用户只能浏览不能购买
2. **配置安全**：发布到市场的商品需要脱敏处理（不包含交易所 API Key、私钥等敏感信息）
3. **版本管理**：发布者更新商品后需手动触发"同步到市场"，已购用户会看到"有更新"标记
4. **防刷机制**：同一天内同一用户对同一商品的浏览次数去重；购买次数真实统计
5. **审核流程**：审核期间商品不可见，审核通过后自动上架
6. **退款策略**：暂不支持退款，后续可根据运营需求补充
7. **类型扩展**：新增商品类型只需：① 加枚举值 ② 实现 ProductMarketHandler ③ 前端加详情组件，无需改表结构
