# 交易机器人做单方向与风控参数改造设计文档

## 1. 背景与目标

### 1.1 当前问题

**问题一：缺少做单方向控制**

- `TradingBot` 实体没有"做单方向"字段
- 交易引擎收到信号即执行，无法限制机器人**只做多 / 只做空 / 双向**
- 用户在机器人层面无法表达方向偏好

**问题二：风控参数体系不完善**

- 机器人现有的 `dailyProfitTarget` / `dailyLossTarget` 等风控参数存于 `bot.configuration` JSON 字段中
- 交易引擎 [`LiveTradingServiceImpl.startLiveTrading()`](file:///f:/project/lenzeto/ai-quant/src/main/java/com/chain/ai/trade/engine/service/impl/LiveTradingServiceImpl.java) 读取配置时**只读了加仓配置**（`allowAddPosition` / `addPosOnProfitPct` 等），未读取 `dailyProfitTarget` / `dailyLossTarget`
- 日内风控走 `MemberRiskConfig`（会员级别），无法按机器人维度精细控制
- `bot.configuration` 作为 JSON 大字段，不利于 SQL 查询强类型校验

### 1.2 改造目标

1. 支持机器人做单方向控制：LONG（只做多）、SHORT（只做空）、BOTH（双向）
2. 建立机器人级别的风控参数体系，优先级高于策略风控
3. 交易引擎运行时，风控参数优先级：**机器人参数 > 策略风控 > 会员级默认风控**

## 2. 总体验收标准

| # | 验收项 | 说明 |
|---|--------|------|
| 1 | 创建/编辑机器人可选择做单方向 | LONG/SHORT/BOTH 三选一 |
| 2 | 机器人列表展示方向字段 | 列表列展示 |
| 3 | 引擎执行信号时按方向过滤 | LONG 忽略空信号，SHORT 忽略多信号，BOTH 不过滤 |
| 4 | 风控参数改为 `bot_parameter` 表存储 | 不再存入 `bot.configuration` JSON |
| 5 | 前端表单输入的风控参数提交到 `bot_parameter` 接口 | 日盈利目标、日亏损目标等 |
| 6 | 引擎运行时按优先级读取风控参数 | bot > strategy.riskControl > StrategyParameter |
| 7 | 旧数据向前兼容 | 已存的 `bot.configuration` 中的风控参数在启动时被识别 |
| 8 | API 文档与接口清单完整 | 后端新增接口已定义 |

## 3. 数据库设计

### 3.1 TradingBot 表新增字段

```sql
ALTER TABLE `trading_bot`
  ADD COLUMN `direction` VARCHAR(16) NOT NULL DEFAULT 'BOTH' COMMENT '做单方向: LONG-只做多, SHORT-只做空, BOTH-双向',
  ADD INDEX `idx_direction` (`direction`);
```

### 3.2 新建 bot_parameter 表

```sql
CREATE TABLE `bot_parameter` (
  `id`          bigint       AUTO_INCREMENT,
  `bot_id`      varchar(32)  NOT NULL COMMENT '机器人ID',
  `group_name`  varchar(64)  NOT NULL COMMENT '分组名，如 risk_control, add_position_config',
  `name`        varchar(128) NOT NULL COMMENT '参数名',
  `value`       json         DEFAULT NULL COMMENT '参数值（完整JSON对象）',
  `created_at`  datetime     DEFAULT CURRENT_TIMESTAMP,
  `updated_at`  datetime     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_bot_param` (`bot_id`, `group_name`, `name`),
  KEY `idx_bot_group` (`bot_id`, `group_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='机器人参数表';
```

### 3.3 参数分组与命名规范

每个分组仅存 **一条记录**，`name` 与 `group_name` 同名，`value` 存储完整 JSON 对象（与策略存储方式一致）。

| group_name | name | value 结构示例 | 说明 |
|---|---|---|---|
| `config` | `config` | `{"daily_profit_target_pct":5, "daily_loss_limit_pct":10}` | 机器人特有参数（策略中无对应） |
| `positionRisk` | `positionRisk` | `{"maxPosition":80, "maxPositionPerTrade":100, "minPosition":10, "positionManagementEnabled":true, "allowAddPosition":false, "addPosOnProfitPct":1, "addPosOnLossPct":2, "addPosOnProfitGapPct":0.5, "addPosOnLossGapPct":0.5}` | 仓位控制参数，与策略 `positionRisk` JSON 内 key 同名 |
| `exitRules` | `exitRules` | `{"stopLoss":{...}, "takeProfit":{"enabled":true, "type":"fix", "percent":5}, "signalReversalExitEnabled":false, "smcExit":{...}, "batchTakeProfitEnabled":false, "batchTakeProfitCount":3, "batchTakeProfitPlans":[], "batchStopLossEnabled":false, "batchStopLossCount":3, "batchStopLossPlans":[], "batchTrailingGainEnabled":false, "batchTrailingGainCount":3, "batchTrailingGainPlans":[], "batchTrailingLossEnabled":false, "batchTrailingLossCount":3, "batchTrailingLossPlans":[]}` | 出场规则参数，与策略 `exitRules` JSON 内 key 同名 |

### 4.7 引擎风控优先级改造

**当前流程**（[`LiveTradingServiceImpl.startLiveTrading()`](file:///f:/project/lenzeto/ai-quant/src/main/java/com/chain/ai/trade/engine/service/impl/LiveTradingServiceImpl.java#L280-L349)）：

```
1. StrategyParameter 表 (add_position_config 组)
2. strategy.riskControl JSON 字段 (优先级更高)
3. bot.configuration JSON 字段 (最高优先级，但只读了加仓配置)
```

**改为**：

```
读取阶段 — 参数合并流程（在 startLiveTrading 中）：

1. 读取 StrategyParameter 表，得到 strategy 级别的 exit_rules_config 和 add_position_config
2. 读取 strategy.riskControl JSON，覆盖步骤1中的同名参数
3. 读取 bot_parameter 表（risk_control 组 + add_position_config 组），覆盖步骤2中的同名参数
4. 将最终合并后的参数传入 DefaultDealStrategyTrade.additionalParams

方向过滤（在 DefaultDealStrategyTrade 执行信号前）：

方向过滤逻辑: bot.direction
  - LONG:  忽略 SELL/SHORT 信号，只执行 BUY/LONG 信号
  - SHORT: 忽略 BUY/LONG 信号，只执行 SELL/SHORT 信号
  - BOTH:  不过滤，按信号原样执行
```

#### 风控参数提交改造

当前：`buildConfiguration()` 将 `dailyProfitTarget` / `dailyLossTarget` 写入 `bot.configuration` JSON。

改为：
- `dailyProfitTarget` / `dailyLossTarget` 等风控参数**不再写入 `bot.configuration`**
- 在 `handleSubmit()` 中，保存机器人成功后，**串行调用 3 次 API** 将参数提交到 `bot_parameter` 表（串行避免 MySQL 死锁）
- 每个分组仅存 **一条完整 JSON 记录**，`name` 与 `group_name` 同名，而非展开为多条记录
- 编辑回显时，先从新格式（单条 JSON）读取，找不到则降级兼容旧格式（多条展开记录），再找不到则从 `exit_rules_config` 组读取（最旧格式）

**保存逻辑伪代码：**
```typescript
// 串行保存三个分组（避免并发事务导致死锁）
await saveBotParameters(botId, 'config', {
  config: JSON.stringify({ daily_profit_target_pct, daily_loss_limit_pct })
});
await saveBotParameters(botId, 'positionRisk', {
  positionRisk: JSON.stringify({ maxPosition, maxPositionPerTrade, ... })
});
await saveBotParameters(botId, 'exitRules', {
  exitRules: JSON.stringify({ stopLoss, takeProfit, smcExit, batchPlans, ... })
});
```

**加载逻辑伪代码：**
```typescript
// 读取三个分组
const [configRes, posRes, exitRes] = await Promise.all([
  getBotParameters(botId, 'config'),
  getBotParameters(botId, 'positionRisk'),
  getBotParameters(botId, 'exitRules')
]);

// 优先读新格式：查找 name='config'/'positionRisk'/'exitRules' 的记录，JSON.parse value
// 兼容旧格式：查找各独立字段（maxPosition, stopLoss 等）的多条展开记录
// 兼容最旧格式：从 'exit_rules_config' 组读取 riskControl JSON
```

### 5.3 robot.ts 新增 API

```typescript
// ==================== 机器人参数接口 ====================

/** 保存机器人分组参数 */
export const saveBotParameters = async (
  botId: string,
  group: string,
  params: Record<string, string>,
) => {
  return await put(`/trading-bots/${botId}/parameters/${group}`, params);
};

/** 查询机器人分组参数 */
export const getBotParameters = async (
  botId: string,
  group: string,
) => {
  return await get(`/trading-bots/${botId}/parameters/${group}`);
};
```

## 6. 数据迁移方案

### 6.1 旧数据兼容

已有机器人数据的 `bot.configuration` JSON 中可能包含 `dailyProfitTarget` / `dailyLossTarget` 等风控参数。

迁移策略：
1. **不批量迁移** — 避免影响线上运行
2. 在 [`LiveTradingServiceImpl.startLiveTrading()`](file:///f:/project/lenzeto/ai-quant/src/main/java/com/chain/ai/trade/engine/service/impl/LiveTradingServiceImpl.java) 中做**向前兼容**：
   - 先读 `bot_parameter` 表
   - 若无数据，降级读 `bot.configuration` JSON 中的旧字段
3. 用户编辑机器人保存后，自然迁移到新表
