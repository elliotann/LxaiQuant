## 1. 概述

加仓/补仓功能允许交易机器人在已有持仓的基础上，根据价格变化幅度和趋势方向，追加仓位以放大盈利或摊薄成本。该功能通过 `shouldTriggerSupplementaryOrder` 方法实现，采用 **幅度驱动 + 趋势过滤 + 间隔控制** 的三层决策模型。

### 功能目标

- **盈利加仓**：持仓盈利达到一定比例后追加仓位，顺势扩大盈利
- **亏损补仓**：持仓亏损达到一定比例后追加仓位，摊薄平均成本
- **EMA趋势补仓**：持仓亏损但EMA趋势仍然顺势时追加仓位

### 关键设计原则

- 幅度是触发前提，价格从持仓以来需达到阈值
- 趋势过滤防止逆势加仓
- 间隔控制防止密集加仓
- 补仓项可设置独立止盈价，支持部分出场

## 2. 前置条件

在 `createLongOrder`（多头开仓）和 `createShortOrder`（空头开仓）中，开仓流程区分**首次开仓**和**加仓**两种入口：

1. 先查询当前方向是否已有持仓（`queryPositionOrders`）
2. 如果没有持仓 → 走首次开仓流程
3. 如果有持仓 →
   - 若 `AllowAddPosition` 不为 `true` → 直接返回，不加仓
   - 若为 `true` → 调用 `shouldTriggerSupplementaryOrder` 判断是否执行加仓

### 基础强校验

`shouldTriggerSupplementaryOrder` 方法执行以下前置判断：

- `AllowAddPosition` 必须为 `true`
- 必须存在已开仓的持仓（对方方向不为空）
- 同一K线时间不存在重复加仓（防重放）
- 首次开仓时未记录`firstEntryPrice`的，以当前持仓均价作为首次开仓价
- 仓位不能超出上限

## 3. 三种触发场景

### 3.1 盈利加仓

| 条件 | 说明 |
|------|------|
| 幅度 | `pnlFromFirst >= addPosOnProfitPct`（相对于首次开仓价的盈利比例≥阈值） |
| 间隔 | `pnlFromLast >= addPosOnProfitGapPct`（相对于最后一次加仓价的盈利差距≥阈值） |
| 趋势 | 可选EMA趋势过滤（见4.4） |

**适用场景**：行情朝持仓方向突破关键价位，确认趋势延续后加仓。

### 3.2 亏损补仓

| 条件 | 说明 |
|------|------|
| 幅度 | `pnlFromFirst <= -addPosOnLossPct`（相对于首次开仓价的亏损比例≥阈值） |
| 间隔 | `pnlFromLast <= -addPosOnLossGapPct`（相对于最后一次加仓价的亏损差距≥阈值） |
| 趋势 | 不检查EMA趋势（亏损补仓无趋势过滤） |

**适用场景**：行情回调/反弹至关键支撑/阻力位，认为当前价格偏离合理价值，追加仓位摊薄成本。

**注意**：亏损补仓不检查EMA趋势方向，仅由价格幅度触发。风险由其他风控机制（如止损、仓位管理）控制。

### 3.3 EMA趋势补仓

| 条件 | 说明 |
|------|------|
| 幅度1 | `pnlFromFirst < 0`（总体处于亏损状态） |
| 幅度2 | `pnlFromLast >= addPosOnProfitGapPct`（相对于最后一次加仓价的盈利差距≥阈值） |
| 趋势 | 必须通过EMA趋势检查（见4.4） |

**适用场景**：持仓整体亏损但最近价格反弹/回调且EMA趋势仍顺势，确认趋势未改变后追加仓位。

## 4. 核心判断流程

### 4.1 整体流程图

```
入口：createLongOrder / createShortOrder
         │
         ▼
    已有持仓？
         │
    ┌────┴────┐
    │ 是      │ 否
    │         ▼
    ▼     首次开仓流程
AllowAddPosition=true?
    │
    ├─否→ 返回（不加仓）
    │
    ├─是→ 计算 pnlFromFirst / pnlFromLast
    │
    ▼
┌─────────────────────────────────────────┐
│    shouldTriggerSupplementaryOrder 判断  │
│                                         │
│  ┌──────────┐  ┌──────────┐  ┌───────┐ │
│  │ 盈利加仓  │  │ 亏损补仓  │  │EMA趋势│ │
│  │ pnl>=阈值 │  │ pnl<=阈值 │  │补仓   │ │
│  │          │  │          │  │       │ │
│  │+Gap检查  │  │+Gap检查  │  │+Gap检查│ │
│  │+EMA检查  │  │(无EMA检查)│  │+EMA检查│ │
│  └────┬─────┘  └────┬─────┘  └───┬───┘ │
│       │              │            │      │
│       └──────┬───────┴─────┬──────┘      │
│              ▼             ▼              │
│          任一成立 = 触发加仓              │
└─────────────────────────────────────────┘
         │
         ▼
    补仓执行流程（下单、设置止盈等）
```

### 4.2 幅度计算

```
// 相对于首次开仓价的盈亏比例
pnlFromFirst = (currentPrice - firstEntryPrice) / firstEntryPrice  (多头)
pnlFromFirst = (firstEntryPrice - currentPrice) / firstEntryPrice  (空头)

// 相对于最后一次开仓价的盈亏比例
pnlFromLast = (currentPrice - lastEntryPrice) / lastEntryPrice      (多头)
pnlFromLast = (lastEntryPrice - currentPrice) / lastEntryPrice      (空头)
```

- `firstEntryPrice`：首次开仓均价
- `lastEntryPrice`：最近一次加仓的开仓价
- `currentPrice`：当前判断时的最新价格

### 4.3 间隔限制（Gap检查）

当已有加仓记录（`openItems.size() > 1`），即至少加过一次仓后，需要满足间隔比例约束，防止在窄幅区间内频繁加仓：

| 场景 | 间隔条件 | 说明 |
|------|----------|------|
| 盈利加仓 | `pnlFromLast >= addPosOnProfitGapPct` | 最近一次加仓到当前价格差足够大 |
| 亏损补仓 | `pnlFromLast <= -addPosOnLossGapPct` | 最近一次补仓到当前价格差足够大 |
| EMA趋势补仓 | `pnlFromLast >= addPosOnProfitGapPct` | 同盈利加仓的间隔条件 |

**设计意图**：Gap检查使用 `pnlFromLast` 而非 `pnlFromFirst`，确保每次加仓之间都有足够的价差，不会短时间内重叠加仓。

### 4.4 EMA趋势过滤

EMA趋势过滤应用于**盈利加仓**和**EMA趋势补仓**两个场景，用于确认当前趋势方向是否支持继续加仓。

#### 为什么不检查亏损补仓的方向

亏损补仓本质上属于"逆势补仓"——价格往不利方向运动时加仓摊薄成本。如果强制要求EMA趋势同向，则亏损补仓永远不会触发（因为价格反向运动时EMA方向一定相反）。因此亏损补仓不检查趋势，仅由价格幅度和间隔控制触发，其风险通过止损和仓位管理来控制。

#### EMA趋势检查方法

```
isEmaAligned(series, endIndex, barCount, isBuy, minConsecutiveBars)
```

- **EMA计算**：使用9周期EMA和21周期EMA
- **时间周期**：默认使用1小时K线（除非特别指定）
- **判定规则**：
  - **多头**（`isBuy=true`）：连续 `minConsecutiveBars` 根K线满足 `EMA9 > EMA21`
  - **空头**（`isBuy=false`）：连续 `minConsecutiveBars` 根K线满足 `EMA9 < EMA21`
- **判定顺序**：从当前K线向前逐根检查，需连续N根K线均满足条件

#### 配置参数

```yaml
supplementary-order:
  ema-trend:
    enabled: true                          # 盈利加仓是否启用EMA趋势过滤
    period: "1h"                           # EMA计算的K线周期（快速回测时自动切换为指定周期）
    min-consecutive-bars: 10               # 最少连续N根K线方向一致
```

#### 缓存机制

EMA趋势判断结果缓存60秒，避免同一K线内重复计算。缓存key包含 `symbol + period + isBuy`。

### 4.5 仓位上限控制

加仓次数不能超过配置上限：

| 方向 | 默认上限 | 配置路径 |
|------|----------|----------|
| 多头 | 20 | `maxLongLots` |
| 空头 | 10 | `maxShortLots` |

判断方式：`openItems.size() >= maxLots` 时不触发加仓。

## 5. 补仓执行流程

当 `shouldTriggerSupplementaryOrder` 返回 `true` 后，执行以下流程：

### 5.1 补仓项单独止盈设置

`applyLossSupplementItemTakeProfit` 为每个补仓项设置独立的止盈价（`gainPrice`），优先级从高到低：

| 优先级 | 来源 | 条件 |
|--------|------|------|
| 1（最高） | TechnicalSignal 中的 `priceTargetsInfo.optimalTakeProfit` | 存在于当前信号中 |
| 2 | EMA144 作为参考止盈价 | 当前价格在EMA144的另一侧，且与EMA144差距≥0.5% |
| 3（最低） | 固定百分比止盈 | 读取配置文件中的固定止盈比例 |

**设计意图**：补仓项独立止盈允许部分出场，即在整体持仓仍持有的情况下，某个补仓项达到止盈价时可以单独平仓该部分，锁定该笔利润。

### 5.2 仓位计算

`calculateOrderAmount` 方法根据配置和当前账户状态计算本次补仓的仓位大小，与首次开仓复用同一套仓位计算逻辑。

### 5.3 下单与记录更新

1. 日内风控检查（`preOpenCheck`）：检查当日是否达到风控限制
2. 调用 `suppOrder(params)` 执行补仓下单
3. 更新 `MultiPositionTradingRecord`，记录加仓时间、价格、数量

## 6. 出场处理

### 6.1 出场优先级

在 `processPositionExits` 中，出场规则有严格的优先级顺序：

| 优先级 | 规则 | 说明 |
|--------|------|------|
| 1（最高） | 订单级止盈止损 | `determineOrderPriceExit` — `gainPrice`/`lossPrice`触及整个订单出场 |
| 2 | **补仓项级止盈** | `determineOrderItemTakeProfitExit` — 单个补仓项达到`gainPrice` |
| 3 | 批量止盈 | `handleBatchTakeProfit` |
| 4 | 批量止损 | `handleBatchStopLoss` |
| 5 | 批量追踪止盈 | `handleBatchTrailingGain` |
| 6 | 批量追踪止损 | `handleBatchTrailingLoss` |
| 7（最低） | 策略统一出场信号 | `mpStrategy.shouldExitSignal` |

**关键设计**：补仓项级止盈（优先级2）高于批量止盈止损（优先级3-6），确保补仓项的独立止盈能够优先执行。

### 6.2 补仓项单独止盈出场

`determineOrderItemTakeProfitExit` 方法检查订单下每个 `TradeOrderItem` 的 `gainPrice`：

```
for each TradeOrderItem in order:
    if item状态 == DEAL (已成交未出场)
       && gainPrice > 0
       && 当前价格触及 gainPrice
       && 该item仍有未平仓位
    → 生成 ExitSignal(exitType=ORDER_ITEM_TAKE_PROFIT, price=gainPrice, orderItemSn=itemSn)
```

选择规则：
- 若有多个item同时触及止盈价，选择**最早开仓**的item出场
- 一次只处理一个item的出场

## 7. 配置参数说明

```yaml
supplementary-order:
  # 主开关
  enabled: true                           # 对应代码: AllowAddPosition

  # 幅度阈值（相对于首次开仓价）
  add-pos-on-profit-pct: 0.02             # 盈利加仓阈值 2%
  add-pos-on-loss-pct: 0.02               # 亏损补仓阈值 2%

  # 间隔阈值（相对于最后一次加仓价）
  add-pos-on-profit-gap-pct: 0.01         # 盈利加仓间隔 1%
  add-pos-on-loss-gap-pct: 0.01           # 亏损补仓间隔 1%

  # 仓位上限
  max-long-lots: 20                       # 多头最大加仓次数
  max-short-lots: 10                      # 空头最大加仓次数

  # EMA趋势过滤
  ema-trend:
    enabled: true                         # 盈利加仓是否启用EMA趋势过滤
    period: "1h"                          # EMA计算的K线周期
    min-consecutive-bars: 10              # 最少连续N根K线方向一致

  # 补仓项单独止盈
  supplemental-item-take-profit:
    enabled: true                         # 补仓项单独止盈开关
    take-profit-pct: 0.01                 # 固定止盈比例（优先级3，无信号和EMA144时使用）

  # EMA144参考止盈
  ema144-take-profit:
    min-price-gap-pct: 0.005              # 价格与EMA144的最小差距比例 0.5%
```

## 9. 完整调用链路

```
createLongOrder / createShortOrder
  │
  ├─ queryPositionOrders(params)                    # 查询当前持仓
  │
  ├─ shouldTriggerSupplementaryOrder(...)           # 加仓判断
  │    ├─ 基础校验（AllowAddPosition、持仓非空、无重复）
  │    ├─ 计算 pnlFromFirst / pnlFromLast
  │    ├─ 检查盈利加仓场景
  │    │    ├─ pnlFromFirst >= addPosOnProfitPct
  │    │    ├─ Gap检查：pnlFromLast >= addPosOnProfitGapPct
  │    │    └─ EMA趋势检查（可选）
  │    │
  │    ├─ 检查亏损补仓场景
  │    │    ├─ pnlFromFirst <= -addPosOnLossPct
  │    │    └─ Gap检查：pnlFromLast <= -addPosOnLossGapPct
  │    │
  │    └─ 检查EMA趋势补仓场景
  │         ├─ pnlFromFirst < 0（总体亏损）
  │         ├─ pnlFromLast >= addPosOnProfitGapPct
  │         └─ EMA趋势检查
  │
  ├─ applyLossSupplementItemTakeProfit(order)       # 设置补仓项止盈（按优先级）
  │
  ├─ calculateOrderAmount(params)                   # 计算仓位
  │
  ├─ preOpenCheck(params)                           # 日内风控检查
  │
  ├─ suppOrder(params)                              # 执行补仓下单
  │
  └─ updateMultiPositionRecord(...)                 # 更新交易记录
```

### 出场调用链路

```
processPositionExits
  │
  ├─ determineOrderPriceExit                        # 订单级止盈止损（最高优先级）
  │    └─ 命中 → 执行出场，跳过后续
  │
  ├─ determineOrderItemTakeProfitExit               # 补仓项级止盈（次高优先级）
  │    └─ 检查每个TradeOrderItem的gainPrice
  │    └─ 选择最早开仓的item
  │    └─ 命中 → 执行出场，跳过后续
  │
  ├─ handleBatchTakeProfit                          # 批量止盈
  ├─ handleBatchStopLoss                            # 批量止损
  ├─ handleBatchTrailingGain                        # 批量追踪止盈
  ├─ handleBatchTrailingLoss                        # 批量追踪止损
  │
  └─ shouldExitSignal（策略统一信号）               # 策略统一出场（最低优先级）
```
