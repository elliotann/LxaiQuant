# 交易机器人多策略模式设计文档

## 1. 背景与现状

### 1.1 当前架构

```
TradingBot (1) → strategyId → Strategy (1) → className → Spring Bean → SignType → ISignService (1)
```

- 一个 `TradingBot` 只能绑定一个 `Strategy`
- 一个 `Strategy` 只能映射一个信号服务（`ISignService`）
- 止盈止损（`ExitRulesConfig`）配置在策略级别
- 资金（`allocatedCapital`）为机器人整体分配，不分仓

### 1.2 关键实体

| 实体 | 关键字段 | 说明 |
|------|---------|------|
| `TradingBot` | `strategyId`, `allocatedCapital`, `currentCapital`, `configuration` | 交易机器人 |
| `Strategy` | `strategyId`, `className`, `defaultParameters` | 策略定义（含 exit_rules_config） |
| `trading_bot_strategy` (关联表) | **不存在，需新建** | 机器人-策略 N:N 关联 |

### 1.3 核心矛盾

业务上需要**一个机器人运行多个交易策略**（如同步运行 MACD 趋势策略、Range Filter 波动策略），但当前架构只支持 1:1 绑定。多策略带来的核心问题是：

> **一份资金，多套交易逻辑和止盈止损规则，怎么共存？**

---

## 2. 总体方案：两种模式并存

针对不同的使用场景，提供两种多策略模式：

| 模式 | 适用场景 | 核心理念 |
|------|---------|---------|
| **模式1：资金分仓** | 各策略方向独立、各自为战 | 资金按权重分割，各策略独立管理子仓位 |
| **模式2：投票聚合** | 多策略印证同一方向、统一执行 | 统一仓位，策略只出信号，聚合后执行 |

两种模式由用户在创建/编辑机器人时选择，**同一个机器人只能选择一种模式**。

---

## 3. 模式1：资金分仓

### 3.1 原理

```
TradingBot.allocatedCapital = 10000 USDT
  多策略模式 = 资金分仓
  ├─ 策略A (权重50%) → 5000 USDT → 独立子仓位A → TP/SL来自策略A
  ├─ 策略B (权重30%) → 3000 USDT → 独立子仓位B → TP/SL来自策略B
  └─ 策略C (权重20%) → 2000 USDT → 独立子仓位C → TP/SL来自策略C
```

### 3.2 数据结构

#### `trading_bot_strategy` 关联表

```sql
CREATE TABLE trading_bot_strategy (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    bot_id      VARCHAR(64)   NOT NULL COMMENT '机器人ID',
    strategy_id VARCHAR(64)   NOT NULL COMMENT '策略ID',
    weight      DECIMAL(5,2)  DEFAULT 0 COMMENT '资金权重(0~100)',
    params      JSON          COMMENT '策略参数覆盖（可覆盖 Strategy.defaultParameters）',
    enabled     TINYINT(1)    DEFAULT 1 COMMENT '是否启用',
    created_at  DATETIME      DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_bot_strategy (bot_id, strategy_id)
) COMMENT='机器人-策略关联表（资金分仓用）';
```

#### `TradingBot` 字段扩展

| 字段 | 变更 | 说明 |
|------|------|------|
| `strategyId` | 改为 **nullable** | 向后兼容：单策略时仍使用此字段 |
| `configuration` | 新增字段 `multiStrategyMode` | 指定模式：`SPLIT_FUND` 或 `VOTE_AGGREGATE` |
| `configuration` | 新增字段 `aggregationConfig` | 投票聚合模式的配置 |

`configuration` JSON 结构扩展：

```json
{
  "multiStrategyMode": "SPLIT_FUND",
  "aggregationConfig": {}
}
```

#### 订单/仓位维度扩展

```sql
-- orders 表新增字段（或通过扩展字段承载）
ALTER TABLE trading_order ADD COLUMN strategy_id VARCHAR(64) COMMENT '归属策略ID（资金分仓模式）';
```

### 3.3 执行流程

```
LiveTradingServiceImpl.execute(robotId)
  ├─ 查询 TradingBot
  │   ├─ configuration.multiStrategyMode == "SPLIT_FUND"
  │   └─ 查询 trading_bot_strategy → [策略A(50%), 策略B(30%), 策略C(20%)]
  │
  ├─ 计算各策略资金配额
  │   ├─ 策略A: allocatedCapital * 50% = 5000 USDT
  │   ├─ 策略B: allocatedCapital * 30% = 3000 USDT
  │   └─ 策略C: allocatedCapital * 20% = 2000 USDT
  │
  ├─ 为每个策略创建独立执行上下文
  │   ├─ TradingStrategyParams 传入 subCapital、strategyId
  │   └─ 每个策略实例持有独立的 MultiPositionTradingRecord
  │
  ├─ 并行执行各策略
  │   ├─ DefaultDealStrategyTrade.execute(策略A, 资金=5000)
  │   ├─ DefaultDealStrategyTrade.execute(策略B, 资金=3000)
  │   └─ DefaultDealStrategyTrade.execute(策略C, 资金=2000)
  │
  └─ 汇总执行结果并落库
```

### 3.4 资金管理

| 场景 | 逻辑 |
|------|------|
| **初始分配** | 按权重分配 `allocatedCapital`，各子策略拿到独立资金池 |
| **盈利再分配** | 子策略盈利后，资金回到该策略资金池，不影响其他策略 |
| **亏损处理** | 子策略亏损到 `maxDrawdown` 则自动暂停该策略，不影响其他策略 |
| **追加/减资** | 调整机器人总资金时，按权重比例重新分配 |
| **权重调整** | 调整后，下次触发时按新权重重新计算资金配额 |

### 3.5 优点与约束

**优点：**
- 策略完全解耦，不互相干扰
- 现有策略逻辑无需修改（含 TP/SL、分批、加仓等）
- 可单独查看各子策略的盈亏表现

**约束：**
- 资金碎片化，整体资金利用率可能低于 100%（取决于权重分配）
- 需要前端展示子仓位维度
- 已有持仓时调整权重需处理边界（持仓如何处理？）

## 4. 模式2：投票聚合

### 4.1 原理

```
TradingBot → 统一仓位 (100% capital)
  ├─ 策略A: 出信号 (BUY / SELL / HOLD + 置信度)
  ├─ 策略B: 出信号 (BUY / SELL / HOLD + 置信度)
  └─ 策略C: 出信号 (BUY / SELL / HOLD + 置信度)
       ↓
  信号聚合层 (SignalAggregator)
       ↓
  聚合结果: BUY(置信度0.7) → 统一开仓
  止盈止损 → 走聚合后的规则
```

**关键区别：** 策略在此模式下只负责**产出交易信号**，不管理仓位和退出规则。仓位管理和止盈止损由**聚合层**统一控制。

### 4.2 数据结构

复用 `trading_bot_strategy` 关联表，增加聚合配置：

```sql
-- 复用同一张关联表，使用 mode 字段区分
ALTER TABLE trading_bot_strategy 
  ADD COLUMN mode VARCHAR(20) DEFAULT 'SPLIT' COMMENT '模式: SPLIT-分仓, VOTE-投票',
  ADD COLUMN vote_weight DECIMAL(5,2) DEFAULT 1.0 COMMENT '投票权重(投票模式用)',
  ADD COLUMN priority INT DEFAULT 0 COMMENT '优先级(备用)';
```

`TradingBot.configuration` 扩展：

```json
{
  "multiStrategyMode": "VOTE_AGGREGATE",
  "aggregationConfig": {
    "strategy": "WEIGHTED_AVG",
    "threshold": 0.6,
    "consensus": "MAJORITY_VOTE"
  },
  "exitRules": {
    "stopLoss": { "enabled": true, "percent": 5 },
    "takeProfit": { "enabled": true, "percent": 15 }
  }
}
```

### 4.3 聚合策略

| 聚合策略 | 说明 | 使用场景 |
|---------|------|---------|
| **加权平均** (WEIGHTED_AVG) | 按 `vote_weight` 加权计算买卖强度值，超过阈值则执行 | 多个指标互补 |
| **多数投票** (MAJORITY_VOTE) | 统计 BUY/SELL 票数（按权重），取多数 | 多维度印证 |
| **共识制** (CONSENSUS) | 所有策略一致才操作，否则 HOLD | 风控优先 |
| **优先级制** (PRIORITY) | 按优先级排序，高优先级策略先判断，优先采用其结果 | 主次策略 |

### 4.4 接口设计

```java
/**
 * 信号聚合接口 - 模式2专用
 */
public interface SignalAggregator {

    /**
     * 聚合多个策略的输出信号
     *
     * @param signals  各策略的信号结果列表
     * @param config   聚合配置（策略、阈值等）
     * @return 聚合后的最终交易决策
     */
    AggregatedDecision aggregate(List<StrategySignal> signals, AggregationConfig config);
}

/**
 * 策略输出信号
 */
@Data
public class StrategySignal {
    private String strategyId;
    private SignalAction action;    // BUY / SELL / HOLD
    private double confidence;      // 0~1
    private double weight;          // 投票权重
}

/**
 * 聚合决策
 */
@Data
public class AggregatedDecision {
    private SignalAction finalAction;       // BUY / SELL / HOLD
    private double confidence;              // 聚合置信度
    private List<StrategySignal> details;   // 各策略明细
    private boolean actionable;             // 是否达到执行阈值
}
```

### 4.5 执行流程

```
LiveTradingServiceImpl.execute(robotId)
  ├─ 查询 TradingBot
  │   └─ configuration.multiStrategyMode == "VOTE_AGGREGATE"
  │
  ├─ 执行各策略获取信号（不涉及下单）
  │   ├─ 策略A: buildStrategy() → shouldEnter/shouldExit → 返回 SignalAction
  │   ├─ 策略B: buildStrategy() → shouldEnter/shouldExit → 返回 SignalAction
  │   └─ 策略C: buildStrategy() → shouldEnter/shouldExit → 返回 SignalAction
  │
  ├─ SignalAggregator.aggregate(signals, config)
  │   └─ 根据 WEIGHTED_AVG / MAJORITY_VOTE 等策略聚合
  │
  ├─ 如果 actionable == true
  │   ├─ 统一仓位开仓/平仓
  │   └─ 止盈止损走机器人级别配置（aggregationConfig.exitRules）
  │
  └─ 如果 actionable == false
      └─ 不做操作，记录日志
```

### 4.6 策略执行改造

在投票聚合模式下，策略的 `execStrategy()` 需要改造为**只出信号不下单**的轻量模式：

```java
// 当前: 直接执行
strategy.execStrategy(params);  // 包含开仓/平仓/TP/SL

// 投票模式: 只返回信号
StrategySignal signal = strategy.evaluate(params);  // 只判断方向，不下单
```

需要新增 `evaluate()` 方法或在现有 `execStrategy()` 中通过参数控制：

```java
// IDealStrategyBasic 新增默认方法
default StrategySignal evaluate(TradingStrategyParams params) {
    // 默认实现：走原有逻辑但不实际下单
    // 子类可覆盖
    throw new UnsupportedOperationException("此策略不支持 evaluate 模式");
}
```

### 4.7 止盈止损统一管理

投票聚合模式下，退出规则**从策略级别剥离到机器人级别**：

```
机器人级别配置 (TradingBot.configuration.aggregationConfig.exitRules)
  ├─ stopLoss: { enabled: true, percent: 5, type: "fixed_percent" }
  ├─ takeProfit: { enabled: true, percent: 15, type: "fixed_percent" }
  └─ trailingStop: { enabled: true, percent: 3, barCount: 5 }
        ↓
  StrategyFactory.buildStrategy(series, exitRulesConfig)
        ↓
  exitRule 使用机器人级别的退出规则
```

### 4.8 优点与约束

**优点：**
- 资金利用率 100%
- 多策略互补，提高信号准确率
- 退出规则统一，避免多套 TP/SL 互相干扰

**约束：**
- 策略的退出规则被剥离（策略本身的 exit rule 不生效）
- 每个策略需要支持 `evaluate()` 轻量模式（只出信号不下单）
- 现有 `DefaultDealStrategyTrade` 需要适配改造

## 5. 两种模式共存设计

### 5.1 模式选择

| 维度 | 资金分仓 (SPLIT_FUND) | 投票聚合 (VOTE_AGGREGATE) |
|------|----------------------|--------------------------|
| **仓位** | 多子仓位（各策略独立） | 统一仓位 |
| **止盈止损** | 各策略独立配置 | 机器人统一配置 |
| **资金利用率** | 按权重分配（可能<100%） | 100% |
| **策略干扰** | 互不影响 | 互相印证 |
| **前端展示** | 需展示子仓位维度 | 单仓位维度 |
| **适用策略** | 不同方向/不同周期 | 相同方向/互补指标 |

### 5.2 兼容性设计

- **向后兼容：** 如果 `TradingBot.configuration` 中没有 `multiStrategyMode` 字段，且 `trading_bot_strategy` 表中无关联记录，则保持原有单策略行为（走 `strategyId` 字段）
- **迁移路径：**
  - 原有单策略机器人 → 自动视为单策略模式，不受影响
  - 启用多策略 → 前端配置模式后生效

### 5.3 DB 变更汇总

| 变更 | 说明 |
|------|------|
| 新建 `trading_bot_strategy` 表 | 机器人-策略 N:N 关联 |
| `TradingBot.strategyId` 改为 nullable | 单策略兼容 |
| `TradingBot.configuration` 增加 multStrategyMode, aggregationConfig | 模式选择 + 聚合配置 |
| `trading_order` 增加 `strategy_id` 字段 | 标识订单归属哪个子策略 |

- ta4j 相关代码 — 不变

## 7. 可选后续扩展

1. **动态权重调整**：根据子策略的历史表现自动调整资金权重或投票权重
2. **策略热切换**：机器人运行中动态启用/禁用某个子策略
3. **混合模式**：部分策略资金分仓 + 部分策略投票聚合（复杂度高，暂不纳入）
4. **独立回测**：支持对多策略组合进行整体回测
5. **风险熔断**：当整体仓位亏损达到阈值时，暂停所有子策略
