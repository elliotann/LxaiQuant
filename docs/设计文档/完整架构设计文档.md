## 1. 项目概述

LxAiQuant 是一个 **AI 原生、自托管** 的量化交易操作系统，允许用户通过 AI Agent 自然语言交互完成策略开发、回测、实盘交易及市场分析。

Java 实现版本保留原有 Python 版本的核心设计理念，并充分利用 Java 生态的企业级稳定性、高性能及分布式能力。

### 已实现模块

- 用户与认证（JWT、API Key、RBAC）
- 策略管理（策略模板、JAVA_CLASS 类型、参数配置、信号ID）
- 风控设置（仓位管理、止损止盈、加仓/减仓规则）
- 交易机器人（创建机器人、选择策略、分配资金、启用/禁用、日盈亏目标）
- 市场数据（基于 XChange 的实时/历史行情，MySQL 持久化）
- AI 雷达（多市场机会扫描、技术指标计算、信号生成）
- AI 分析（批量定时分析任务、自然语言生成策略）
- 机器学习增强（方向预测、波动率预测、市场状态识别，基于 Smile 6.1.0）

### 新增设计（v10.0）

- **因子自动挖掘**：基于遗传规划的智能特征发现，与现有特征池协同工作

## 5. 详细模块设计与业务功能实现

### 5.1 用户与认证模块（已实现 + 会员计费体系扩展）

#### 5.1.1 功能概述

用户与认证模块不仅提供基础的账户管理、JWT 认证、RBAC 权限控制，还扩展了完整的会员与积分计费体系，支撑商业化的 AI 量化服务。具体功能包括：

- 用户注册、登录、注销
- JWT Access/Refresh Token 认证
- API Key 生成与吊销（用于自动化脚本调用）
- 角色管理（ADMIN, PREMIUM, BASIC）
- 用户状态管理（ACTIVE, INACTIVE, SUSPENDED）
- 会员套餐订阅（月度/年度，支持 USDT 支付）
- 积分（Credits）系统：充值、消耗、过期管理
- 按量计费：API 调用（AI 策略生成、高级回测、因子挖掘等）根据消耗积分实时扣费
- 配额检查与拦截：AOP 切面自动校验积分余额
- 支付回调与链上交易确认（TRC20 USDT）
- 管理员后台：动态配置会员等级、积分单价、充值套餐

```java
        User user = userMapper.selectById(userId);
        int newBalance = user.getCreditsBalance() + amount;
        userMapper.updateCreditsBalance(userId, newBalance);
        creditsLogMapper.insert(new CreditsLog(userId, amount, newBalance, type, refId, desc));
    }

    /**
     * 扣减积分，如果余额不足抛出异常
     */
    public void deductCredits(String userId, int required, String type, String refId, String desc) {
        User user = userMapper.selectById(userId);
        if (user.getCreditsBalance() < required) {
            throw new InsufficientCreditsException("积分不足，需要 " + required + "，当前 " + user.getCreditsBalance());
        }
        int newBalance = user.getCreditsBalance() - required;
        userMapper.updateCreditsBalance(userId, newBalance);
        creditsLogMapper.insert(new CreditsLog(userId, -required, newBalance, type, refId, desc));
    }

    public int getBalance(String userId) {
        return userMapper.selectById(userId).getCreditsBalance();
    }
}
```

```java
    public ResponseEntity<?> handleCallback(@RequestBody TronWebhookPayload payload) {
```

**配额检查 AOP 切面**

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface QuotaCheck {
    String apiName();   // 对应 api_cost_config 中的 api_name
}

@Aspect
@Component
public class QuotaCheckAspect {
    @Autowired private CreditsService creditsService;
    @Autowired private ApiCostConfigMapper costConfigMapper;

    @Before("@annotation(quotaCheck)")
    public void checkQuota(JoinPoint joinPoint, QuotaCheck quotaCheck) {
        String apiName = quotaCheck.apiName();
        ApiCostConfig config = costConfigMapper.selectByApiName(apiName);
        if (config == null || !config.isEnabled()) {
            return; // 未配置计费则跳过
        }
        String userId = SecurityUtils.getCurrentUserId();
        int required = config.getCostCredits();
        int balance = creditsService.getBalance(userId);
        if (balance < required) {
            throw new InsufficientCreditsException(
                String.format("调用 %s 需要 %d 积分，当前仅剩 %d 积分", apiName, required, balance));
        }
    }

    @AfterReturning("@annotation(quotaCheck)")
    public void deductAfterSuccess(JoinPoint joinPoint, QuotaCheck quotaCheck) {
        String apiName = quotaCheck.apiName();
        ApiCostConfig config = costConfigMapper.selectByApiName(apiName);
        if (config != null && config.isEnabled()) {
            String userId = SecurityUtils.getCurrentUserId();
            creditsService.deductCredits(userId, config.getCostCredits(), "API_COST", apiName,
                "调用接口：" + apiName);
        }
    }
}
```

## 6. 因子自动挖掘功能（已实现）

### 6.1 设计目标

在现有机器学习增强模块基础上，新增因子自动挖掘能力，使用户能够：

- 通过交互式界面配置挖掘任务（标的、算子集、终端集、进化代数等）

### 6.3 后端实现（遗传规划引擎）

#### 6.3.1 包结构

```text
ai-quant/src/main/java/com/chain/ai/trade/engine/service/ml/factor/

├── Operator.java                      # 算子枚举（18个）

├── GeneticProgrammingEngine.java      # 遗传规划引擎
├── FactorExpressionParser.java        # 表达式解析器（序列化/反序列化）
└── FactorMiningTaskService.java       # 挖掘任务编排服务
```

#### 6.3.2 核心组件

**表达式树节点体系（组合模式）：**

```java
public abstract class Node {
    public abstract double eval(int index, Map<String, double[]> data);
    public abstract String toExpression();
    public abstract String toLatex();
    public abstract int depth();
    public abstract int nodeCount();
    public abstract Node cloneTree();
    public abstract List<String> usedTerminals();
}

public class TerminalNode extends Node {    // 特征叶子节点，eval从data Map按索引取值
    private final String name;
}

public class ConstantNode extends Node {    // 常量叶子节点
    private final double value;
}

public class FuncNode extends Node {        // 函数节点，通过Operator.apply()计算
    private final Operator operator;
    private final List<Node> children;
}
```

**算子库（Operator 枚举，共 18 个算子）：**

- **算术（5个）**：ADD(+), SUB(-), MUL(*), DIV(/), NEG(neg)
- **数学函数（4个）**：SQRT(sqrt), LOG(log), ABS(abs), SIGN(sign)
- **比较函数（2个）**：MAX(max), MIN(min)
- **时间序列（7个）**：TS_SUM(ts_sum), TS_MEAN(ts_mean), TS_STD(ts_std), TS_MAX(ts_max), TS_MIN(ts_min), TS_MEDIAN(ts_median)

时间序列算子为二阶算子：第一个参数为序列特征（TerminalNode），第二个参数为窗口大小（ConstantNode），eval时在滑动窗口上计算统计量。

**遗传规划引擎（GeneticProgrammingEngine）：**

核心演化流程：

```java
public EvolutionResult evolve(List<String> terminalNames, List<Operator> operators,
                              Map<String, double[]> data, double[] labels,
                              int populationSize, int generations, ...) {
    // 1. 初始化种群：Ramped Half-and-Half（混合生长法+满树法）
    // 2. 评估适应度 → FactorEvaluator.evaluate()
    // 3. 精英保留 + 锦标赛选择（Tournament Selection）
    // 4. 子树交叉（Subtree Crossover）
    // 5. 点变异（Point Mutation）：替换节点/子树
    // 6. 重复 2-5 直到达到代数或早停条件
    // 7. 返回最优个体及候选列表
}
```

**关键参数**：种群大小(默认500)、进化代数(默认20)、锦标赛大小(默认5)、交叉概率(默认0.8)、变异概率(默认0.1)、简约系数(默认0.001)

**早停机制**：连续5代适应度提升 < 0.001 时提前终止

**适应度评估（FactorEvaluator）：**

```java
public enum FitnessMetric { RANK_IC, SHARPE, IC_SHARPE_COMBO }
```

支持三种适应度指标：

- **RANK_IC**：因子值与未来收益的Spearman秩相关系数，评价因子排序预测能力
- **SHARPE**：因子值序列的夏普比率，评价因子信号稳定性
- **IC_SHARPE_COMBO**：IC + 夏普加权组合：0.6 * |IC| + 0.4 * min(Sharpe / 3, 1)

评估结果中包含：rankIc, sharpe, turnover, corrWithLabel, topRet 等详细指标

### 6.6 与现有特征池的整合策略

- **原则**：基础特征池（4维标准特征）与挖掘出的候选因子协同使用，而非替代。
- **训练阶段**：使用 4 + M 维特征（M为已选中的自定义因子数量）
- **推理阶段**：通过 `toDynamicFeatures()` 方法将已选表达式树解析为 DynamicFeature 实例，与基础特征并行计算
- **注册机制**：`FeatureFactory.createFromExpression(name, expression, data)` 动态创建特征计算实例
- **更新流程**：因子挖掘 → 选中候选 → 注册为 DynamicFeature → 训练/推理时自动包含

### 6.7 性能优化与调度

- **并行适应度评估**：ForkJoinPool 并行流计算个体适应度
- **表达式缓存**：基于表达式字符串哈希的评估结果缓存
- **早停机制**：连续5代适应度提升 < 0.001 时提前终止
- **向下取整保护**：因子值计算后取整，避免产生极小交易量
- **异步任务队列**：CompletableFuture 异步执行，ConcurrentHashMap 管理取消标志
- **XXL-JOB 定时调度**（FactorMiningJobHandler）：扫描 PENDING 状态任务并逐个执行
- **WebSocket 进度推送**候选（前端通过 2s 轮询获取任务状态）
