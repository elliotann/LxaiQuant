1. 引言
   1.1 背景
   量化交易系统涉及大量的业务事件，如订单委托、成交、风控触发、账户资金变动、策略状态变化等。这些事件需要被完整记录，用于事后审计、策略回测、实时监控和问题排查。传统的同步日志写入会阻塞核心交易流程，且难以同时满足持久化存储和实时推送的需求。因此，需要一个高性能、可扩展、解耦的业务日志系统。

1.2 目标
可靠记录：所有关键业务事件持久化到数据库，保证数据不丢失。

实时通知：支持通过 WebSocket 将日志实时推送到前端监控或其他系统。

高性能：异步处理，不阻塞主交易线程。

可扩展：易于添加新的日志类型和存储后端。

可观测：提供日志查询接口，便于分析。

1.3 适用范围
本模块适用于量化交易系统中所有需要记录的业务事件，包括但不限于：

订单生命周期事件（创建、撤销、拒绝）

成交事件

账户资金变更（入金、出金、冻结、解冻）

风控规则触发

策略启动/停止

系统异常

2. 需求分析
   2.1 功能需求
   需求 ID	描述
   F01	系统应能记录任意业务事件，每个事件包含时间戳、类型、详细内容。
   F02	日志应异步写入数据库，支持批量插入以提高吞吐量。
   F03	日志应能实时推送到 WebSocket 客户端，客户端可订阅感兴趣的日志类型。
   F04	提供日志查询 API，支持按时间范围、日志类型、关键字检索。
   F05	系统应支持日志级别（INFO、WARN、ERROR）过滤和告警。
   F06	日志格式应为结构化数据（如 JSON），便于解析和索引。
   2.2 非功能需求
   需求 ID	描述
   NF01	性能：单节点日志写入吞吐量 ≥ 10,000 TPS，99% 写入延迟 < 10ms。
   NF02	可用性：日志模块故障不应影响核心交易流程。
   NF03	可靠性：数据库写入失败应有重试和降级机制，保证数据最终一致。
   NF04	可扩展性：支持水平扩展，日志采集和推送可分布式部署。
   NF05	安全性：敏感信息（如密钥、密码）应脱敏处理。

   3.2 核心组件
   组件	职责
   业务模块	产生业务事件，通过事件总线发布。
   事件总线	负责将事件分发给所有注册的监听器，可同步或异步。
   业务日志监听器	订阅所有业务事件，转换为统一的 BusinessLog 对象，并分发给下游日志器。
   异步数据库日志器	将日志对象放入内存队列，批量异步写入数据库。
   异步 WebSocket 日志器	将日志对象通过 WebSocket 推送给订阅的客户端。
   数据库	持久化存储所有业务日志，支持按需查询。
   WebSocket 服务	维护客户端连接，实现实时推送。

4.2.2 业务日志监听器
java
@Component
public class BusinessLogListener implements Consumer<BusinessEvent> {
@Autowired
private DatabaseLogger databaseLogger;
@Autowired
private WebSocketLogger webSocketLogger;

    @Override
    public void accept(BusinessEvent event) {
        BusinessLog log = convert(event);
        if (log != null) {
            databaseLogger.log(log);
            webSocketLogger.log(log);
        }
    }

    private BusinessLog convert(BusinessEvent event) {
        // 使用工厂模式或策略模式转换
        if (event instanceof OrderPlacedEvent) {
            return new OrderLog((OrderPlacedEvent) event);
        }
        // ... 其他转换
        return null;
    }
}
4.2.3 异步数据库日志器
java
@Component
public class AsyncDatabaseLogger implements TradeLogger {
private final BlockingQueue<BusinessLog> queue = new LinkedBlockingQueue<>(10000);
private final ExecutorService executor = Executors.newSingleThreadExecutor();
private final JdbcTemplate jdbcTemplate;
private final int batchSize = 100;
private final long flushIntervalMs = 1000;
private volatile boolean running = true;

    public AsyncDatabaseLogger(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
        executor.submit(this::flushLoop);
    }

    @Override
    public void log(BusinessLog entry) {
        if (!queue.offer(entry)) {
            // 队列满：可记录到本地文件或丢弃（根据业务重要性）
            logError("Log queue full, dropping log: " + entry);
        }
    }

    private void flushLoop() {
        List<BusinessLog> batch = new ArrayList<>(batchSize);
        while (running) {
            try {
                queue.drainTo(batch, batchSize);
                if (!batch.isEmpty()) {
                    batchInsert(batch);
                    batch.clear();
                }
                Thread.sleep(flushIntervalMs);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
        }
        // 最后插入剩余日志
        queue.drainTo(batch);
        if (!batch.isEmpty()) {
            batchInsert(batch);
        }
    }

    private void batchInsert(List<BusinessLog> logs) {
        String sql = "INSERT INTO business_log (timestamp, log_type, level, trace_id, content) VALUES (?, ?, ?, ?, ?)";
        jdbcTemplate.batchUpdate(sql, logs, logs.size(), (ps, log) -> {
            ps.setLong(1, log.getTimestamp());
            ps.setString(2, log.getLogType());
            ps.setString(3, log.getLevel());
            ps.setString(4, extractTraceId(log)); // 从log中提取traceId
            ps.setString(5, log.toJson());
        });
    }

    private String extractTraceId(BusinessLog log) {
        // 若log对象实现了Traceable接口，则可获取traceId
        return log instanceof Traceable ? ((Traceable) log).getTraceId() : null;
    }

    @PreDestroy
    public void close() {
        running = false;
        executor.shutdown();
        try {
            executor.awaitTermination(5, TimeUnit.SECONDS);
        } catch (InterruptedException ignored) {}
    }
}

会话管理器：

java
@Component
public class WebSocketSessionManager {
private final ConcurrentMap<String, SessionInfo> sessions = new ConcurrentHashMap<>();

    public void register(String sessionId, SimpMessagingTemplate template, List<String> interests) {
        sessions.put(sessionId, new SessionInfo(sessionId, template, interests));
    }

    public void unregister(String sessionId) {
        sessions.remove(sessionId);
    }

    public void broadcast(BusinessLog log) {
        sessions.values().parallelStream().forEach(session -> {
            if (session.isInterestedIn(log)) {
                session.getTemplate().convertAndSend("/topic/logs", log);
            }
        });
    }
}

private String sessionId;
private SimpMessagingTemplate template;
private List<String> interests; // 感兴趣的类型列表，null表示全部

@Component
public class AsyncWebSocketLogger {

private WebSocketSessionManager sessionManager;

    public void log(BusinessLog entry) {
        executor.submit(() -> {

4.4 性能与可靠性设计
4.4.1 异步批量
数据库写入采用批量 + 定时刷新，避免频繁网络 IO。

队列大小可配置，超过容量时采用降级策略（如写入本地文件或丢弃）。

4.4.2 降级与容错
数据库连接失败时，日志可暂存本地磁盘（如使用 RocksDB 或本地文件队列），待恢复后重传。

WebSocket 推送失败不影响主流程，仅记录错误。

4.4.3 线程隔离
每个日志器使用独立的线程池，避免相互干扰。

主业务线程仅将日志放入内存队列，几乎无阻塞。

4.4.4 监控与告警
暴露指标：队列大小、处理速率、失败次数（可通过 Micrometer 集成 Prometheus）。

队列堆积超过阈值时触发告警。

4.5 安全设计
敏感信息脱敏：在 toJson() 方法中对密码、密钥等字段进行掩码处理。

WebSocket 连接可增加认证（如 JWT 令牌）。

5. 部署与运维
   5.1 部署架构
   日志模块作为交易系统的一部分，嵌入在交易进程中。

数据库可选用 MySQL（主从架构）或 TiDB 以支持水平扩展。

WebSocket 服务可独立部署或与交易进程同进程，若客户端量大可前置 Nginx 负载均衡。

6. 扩展性说明
   6.1 新增日志类型
   定义新的 BusinessEvent 子类。

定义对应的 BusinessLog 实现类，并在 BusinessLogListener 的 convert 方法中添加转换逻辑。

数据库 content 字段为 JSON，无需修改表结构。

6.2 新增日志输出端
实现 TradeLogger 接口，例如 KafkaLogger、ElasticsearchLogger。

在 BusinessLogListener 中注入新的 logger 并调用其 log 方法。

6.3 日志采样
可在监听器中根据日志级别、事件类型等条件进行采样，对高频率日志只记录部分，减少存储压力。

7. 总结
   本文档设计了一个高性能、可扩展的量化交易系统业务日志模块。通过事件驱动、异步处理、批量写入和 WebSocket 实时推送，满足了业务日志持久化和实时监控的双重需求。该设计遵循松耦合原则，易于集成到现有系统中，并可根据未来需求灵活扩展。
