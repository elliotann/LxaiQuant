1. 背景与目标
   1.1 背景
   当前量化交易系统包含两条核心执行路径：

实盘/传统回测路径：DefaultDealStrategyTrade.execStrategy，支持 testMode 切换，用于实盘定时任务和传统回测。

快速回测路径：BacktestEngine.runBacktest / BacktestEngine.runMultipleStrategies，基于 MultiPositionBacktestManager 执行。

由于系统频繁迭代（如修改持仓匹配逻辑、数据库优化、规则引擎升级），需要建立自动化测试体系确保两条路径的行为一致性及正确性。

1.2 目标
验证 execStrategy 与回测引擎在相同输入下产生相同的 TradingRecord 和绩效指标。

保证核心算法（多空双向、加减仓、部分平仓、移动止损等）的正确性。

提供快速反馈机制，防止修改引入回归错误。

支持持续集成，每次代码提交自动运行测试。

2. 测试分层策略
   层次	测试范围	依赖隔离	执行速度	运行频率
   单元测试	核心类/算法（MultiPositionTradingRecord、规则类、工具类）	完全 Mock 或纯内存	毫秒级	每次编译
   集成测试	数据库访问、仓位持久化、TradeOrderServiceAdapter	嵌入式数据库（H2）	秒级	每次提交
   一致性验证测试	execStrategy vs BacktestEngine	Mock 外部服务，固定 K 线	秒级~分钟级	每日/合并前
   实盘模拟测试	定时任务全流程（含限价单、幂等、并发）	Mock 交易所 API + 内存 DB	秒级	每日

@Test
void testFifoExitPartial() {
MultiPositionTradingRecord record = new MultiPositionTradingRecord(
TradeType.BUY, ExecutionMatchPolicy.FIFO, new ZeroCostModel(), new ZeroCostModel(), 0, 10);

    record.enter(createBuyFill(0, 100, 2));

}

5. 一致性验证测试（核心）
   5.1 设计思路
   相同输入：同一段固定 K 线序列、同一策略配置、同一成本/执行模型。

两条路径：

路径 A：BacktestEngine.runBacktest（快速回测引擎）

路径 B：DefaultDealStrategyTrade.execStrategy（testMode=true）

对比输出：

TradingRecord（所有交易、已平仓仓位、未平仓仓位）

PerformanceMetrics（总盈亏、最大回撤、交易次数等）

（可选）数据库最终状态

5.2 Mock 依赖
为了隔离外部影响，需要 Mock 以下组件：

依赖	Mock 方式	理由
TradeOrderServiceAdapter	InMemoryOrderServiceAdapter（内存实现）	避免真实数据库，加快测试
KlineDataProviderFactory	返回固定的 BarSeries	确保输入确定
RedisCache	ConcurrentHashMap 内存缓存	无网络依赖
IntradayRiskManager	Mock 总是放行	避免风控逻辑干扰
EventBus	Mock 空实现	无需关心事件发布
5.3 实现示例
java
@Test
void testExecStrategyMatchesBacktestEngine() {
// 1. 固定输入
BarSeries series = TestDataLoader.loadSeriesFromCsv("/test-data/eth-3m-500.csv");
TradingStrategyParams params = createSharedParams();
Strategy strategy = new MyTestStrategy(series); // 确定性策略

    // 2. 执行快速回测
    BacktestEngine backtestEngine = new BacktestEngine(createBacktestConfig());
    BacktestResult backtestResult = backtestEngine.runBacktest(strategy, series);
    TradingRecord backtestRecord = backtestResult.getTradingRecord();

    // 3. 执行 execStrategy（testMode）
    DefaultDealStrategyTrade executor = createExecutorWithMocks();
    executor.setCurrentParams(params);
    executor.execStrategy(params);
    MultiPositionTradingRecord execRecord = executor.getMultiPositionRecord();

    // 4. 对比
    TradingRecordComparator.assertRecordsEqual(backtestRecord, execRecord);
    // 可选：对比绩效指标
    PerformanceMetrics metricsBacktest = backtestResult.getPerformanceMetrics();
    PerformanceMetrics metricsExec = executor.calculateMetrics(...);
    assertThat(metricsExec.getTotalReturn()).isCloseTo(metricsBacktest.getTotalReturn(), offset(1e-8));
}

9. 测试数据管理
   K线数据：存放于 src/test/resources/test-data/*.csv，通过 TestDataLoader 加载。

数据库初始化脚本：schema.sql 和 data.sql 用于 H2。

10. 总结
    本设计文档提供了覆盖系统核心路径的完整测试方案，重点保证了 DefaultDealStrategyTrade.execStrategy 与回测引擎的逻辑一致性。通过分层测试、Mock 隔离和自动化 CI，可以显著降低修改带来的风险，并为后续重构提供安全网。

关键收益：

✅ 验证算法正确性（多空双向、加减仓、部分平仓）

✅ 确保回测与实盘执行一致

✅ 快速定位回归错误

✅ 支持持续交付
