# 三阶段功能验证操作手册

## 前置环境准备

### 1. 数据库初始化
执行以下 SQL 脚本（按顺序）：

```sql
-- 阶段二：RBAC 权限表 + 预置数据
source docs/db/create_rbac_tables.sql;

-- 阶段三：用户表扩展字段
source docs/db/alter_user_add_credits.sql;

-- 阶段三：积分/支付相关表
source docs/db/create_credits_tables.sql;
source docs/db/create_payment_tables.sql;
```

### 2. 启动后端服务
```bash
cd ai-member
mvn spring-boot:run
```
> 服务默认端口：`8080`

### 3. 启动前端开发服务器
```bash
cd ai-frontend-web
npm run dev
```
> 服务默认端口：`5173`

## 阶段一：JWT 安全加固验证

### TC-01：用户注册
**验证目标**：新用户能通过注册接口创建账号，并自动获取 JWT Token

**操作步骤（后端 API）**：
```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "testuser",
    "password": "Test123456",
    "email": "testuser@example.com"
  }'
```

**预期结果**：
```json
{
  "success": true,
  "message": "ok",
  "data": {
    "user": { "id": "...", "username": "testuser", "role": "user" },
    "token": "eyJhbGciOiJIUzM4NCJ9...",
    "refreshToken": "eyJhbGciOiJIUzM4NCJ9..."
  }
}
```

**前端操作**：
1. 浏览器打开 `http://localhost:5173`
2. 点击「注册」链接
3. 输入用户名 `testuser`、密码 `Test123456`、邮箱 `testuser@example.com`
4. 点击注册按钮
5. ✓ 验证：注册成功后自动登录，跳转至首页仪表板

---

### TC-02：用户登录
**验证目标**：已注册用户能用用户名或邮箱登录，获得 JWT Token

**操作步骤（后端 API）**：
```bash
# 用用户名登录
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "testuser", "password": "Test123456"}'

# 用邮箱登录
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "testuser@example.com", "password": "Test123456"}'
```

**预期结果**：两种方式均返回 success=true，带 token / refreshToken

**前端操作**：
1. 退出当前登录 → 回到登录页
2. 输入用户名 `testuser` 和密码 `Test123456`
3. 点击「记住我」复选框
4. 点击登录按钮
5. ✓ 验证：登录成功，跳转至首页

---

### TC-03：获取当前用户信息
**验证目标**：携带 JWT Token 可获取当前登录用户信息

**操作步骤**：
```bash
# 将 <TOKEN> 替换为 TC-02 返回的 token
curl -X GET http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer <TOKEN>"
```

**预期结果**：返回当前用户 JSON（包含 id/username/email/role）

---

### TC-04：无 Token 访问受保护接口被拒绝
**验证目标**：不带 Token 调用受保护 API 应返回 403

**操作步骤**：
```bash
curl -X GET http://localhost:8080/api/auth/me
```

**预期结果**：HTTP 403 或 `{"success": false, "message": ...}`

---

### TC-05：Token 过期自动拒绝
**验证目标**：Access Token（30分钟）过期后，使用过期 Token 应被拒绝

> **注意**：该测试需等 30 分钟，或手动修改 JwtUtil 中的过期时间为短时间后快速验证

**操作步骤**：
```bash
# 使用已过期的 Token
curl -X GET http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer <EXPIRED_TOKEN>"
```

**预期结果**：返回 401/403，提示 Token 无效

---

### TC-06：Refresh Token 续期
**验证目标**：使用 Refresh Token 获取新的 Access Token

**操作步骤**：
```bash
# 将 <REFRESH_TOKEN> 替换为登录时获得的 refreshToken
curl -X POST http://localhost:8080/api/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "<REFRESH_TOKEN>"}'
```

**预期结果**：返回新的 token + refreshToken

---

### TC-07：登出（Token 黑名单）
**验证目标**：登出后，原 Token 被加入黑名单，无法继续使用

**操作步骤**：
```bash
# 1. 登出
curl -X POST http://localhost:8080/api/auth/logout \
  -H "Authorization: Bearer <TOKEN>"

# 2. 尝试用原 Token 调用 me
curl -X GET http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer <TOKEN>"
```

**预期结果**：
- 登出返回 `{"success": true}`
- 再次调用 me 返回 `{"success": false, "message": "登录状态已失效"}`

**前端操作**：
1. 点击导航栏右侧「退出」按钮
2. ✓ 验证：退出后跳转至登录页
3. 尝试直接访问 `http://localhost:5173/users`
4. ✓ 验证：被重定向到登录页（未登录状态无法访问受保护页面）

### TC-15：权限不足保护（@PreAuthorize 测试）
**验证目标**：普通用户越权调用管理 API 应被拒绝

**操作步骤**：
```bash
# 1. 先用 testuser 登录获取 TOKEN
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "testuser", "password": "Test123456"}'

# 2. 用 testuser 的 token 调用管理 API（越权）
curl -X GET http://localhost:8080/api/admin/roles \
  -H "Authorization: Bearer <USER_TOKEN>"
```

**预期结果**：返回 HTTP 403 Forbidden，拒绝访问（`"accessDenied"`）

**前端操作**：
1. 在测试浏览器中以 `testuser` 身份登录
2. 在地址栏输入 `http://localhost:5173/users`
3. ✓ 验证：被重定向到 `/403` 权限不足页面（因为 `requiresPermission: "user:read"` 且 testuser 无此权限）

## 出错排查指引

| 现象 | 可能原因 | 排查方法 |
|------|---------|---------|
| `{"message":"Full authentication is required..."}` | Token 未携带或过期 | 检查 `Authorization: Bearer xxx` 头 |
| `403 Forbidden` | 无此权限 | 确认用户角色已分配对应权限 |
| `{"success":false,"message":"登录状态已失效"}` | Token 在黑名单中 | 重新登录获取新 Token |
| 前端跳转 `/403` | 用户无 `requiresPermission` 对应的权限 | 联系管理员分配角色/权限 |
| `积分不足` 异常 | 余额不够 | 购买积分包 → 充值 → 重试 |
| 回调后积分未增加 | paymentId 不存在或状态错误 | 确认 paymentId 和 status="SUCCESS" |
