# 交易机器人手续费率配置设计方案

## 1. 背景

当前系统中手续费率的获取方式存在两个问题：

| 模式 | 当前实现 | 问题 |
|------|----------|------|
| 回测模式 | 前端创建回测时传入 `commissionRate`，通过 `ThreadLocal` 透传给 `TradeOrderServiceImpl` | 每个回测任务都要手动传入，且与机器人配置脱钩 |
| 实盘模式 | 硬编码在 `TradeOrderEnum` 枚举中（OKX/HUOBI 均为 0.0009），兜底值 `ProfitCalcUtils.DEFAULT_FEE_RATE = 0.00045` | 无法按机器人独立配置，不支持不同机器人的差异化费率 |

**目标**：在编辑交易机器人时，于"交易配置"下增加手续费率字段，将费率与机器人绑定。实盘和回测均通过 `botId` 从统一的存储位置获取该费率。

## 2. 数据存储方案

### 方案选择

存入 `bot_parameter` 表的 `config` 分组中（无需改表结构）。

**理由：**
- `bot_parameter` 表已用于存储 `config` / `positionRisk` / `exitRules` 等机器人参数
- `config` 分组已有 `daily_profit_target_pct` / `daily_loss_limit_pct`，与费率同属交易配置
- 无需新增数据库字段或建表，复用已有的保存/读取接口

### 存储结构

```sql
-- bot_parameter 表新增一条记录
bot_id    = 'BOT-xxx'
group_name = 'config'
name      = 'config'
value     = '{
    "daily_profit_target_pct": 5,
    "daily_loss_limit_pct": 3,
    "commission_rate": 0.0006      -- 新增字段，单位：小数，如 0.0006 = 万分之6
}'
```

**费率格式：** 小数格式，例如 `0.0006` 表示万分之6（即0.06%）。

### 默认值

- 新建机器人时，默认费率为 `0.0006`（万分之6）
- 后端加载时若该字段不存在，兜底使用 `0.00045`（与 `ProfitCalcUtils.DEFAULT_FEE_RATE` 一致）

## 3. 涉及改造清单

### 3.1 后端改造

#### 3.1.1 新增费率工具类 `CommissionRateHelper`

**文件：** `ai-order/.../utils/CommissionRateHelper.java`（新建）

```java
// 职责：封装从 bot_parameter 表读取费率的逻辑
// 提供静态方法供 TradeOrderServiceImpl 调用
public class CommissionRateHelper {
    // 从 bot_parameter 读取
    // 若不存在，返回 null（由调用方决定兜底值）
    public static BigDecimal getCommissionRate(String botId, IBotParameterService paramService);
    
    // 兜底默认值
    public static final BigDecimal DEFAULT_COMMISSION_RATE = new BigDecimal("0.00045");
}
```

#### 3.1.2 修改 `TradeOrderServiceImpl.getFeeRateByPlatform`

**文件：** `ai-order/.../service/impl/TradeOrderServiceImpl.java`

改动：
- `getFeeRateByPlatform(String platformName)` → `getFeeRateByPlatform(String platformName, String botId)`
- 增加 `botId` 参数
- 优先级改为：**bot_parameter 费率 > ThreadLocal（回测传入）> 枚举兜底（0.00045）**

```mermaid
flowchart TD
    A[getFeeRateByPlatform(platformName, botId)] --> B{botId 不为空？}
    B -->|是| C[从 bot_parameter 读取 commission_rate]
    C --> D{存在？}
    D -->|是| E[返回 bot_parameter 中的费率]
    D -->|否| F{ThreadLocal 有值？}
    B -->|否| F
    F -->|是| G[返回 ThreadLocal 回测费率]
    F -->|否| H[返回兜底费率 0.00045]
```

注意：
- 需在 `TradeOrderServiceImpl` 中注入 `IBotParameterService`（或其 Feign 客户端）
- 枚举中的 `PLATFORM_FEE_RATE_OKX` / `PLATFORM_FEE_RATE_HUOBI`（原 0.0009）不再使用，统一走兜底 0.00045

#### 3.1.3 修改回测入口 `BacktestController`

**文件：** `ai-quant/.../controller/test/BacktestController.java`

改动：
- `executeStrategyWithCommission()` 中，不需要再从 `commissionRate` 参数设置 `ThreadLocal`
- 改为将 `botId` 传给策略参数，让 `getFeeRateByPlatform` 直接从 `bot_parameter` 读取
- `BacktestRequest.commissionRate` 字段保留作为备用（当 `bot_parameter` 中不存在时，仍可用回测时传入的值）

#### 3.1.4 修改实盘入口 `LiveTradingServiceImpl`

- 启动机器人时，将 `botId` 透传给策略执行上下文
- 确保 `DefaultDealStrategyTrade` 能获取到 `botId`，并传给 `TradeOrderServiceImpl` 的订单执行方法

#### 3.1.5 新增读取机器人配置接口

**文件：** `TradingBotController.java`

新增 `GET /api/trading-bots/{botId}/config` 接口，返回 `config` 分组的完整 JSON（包含 `commission_rate`）。

**原因：** 前端编辑对话框打开时，需要加载已保存的费率值。

### 3.2 PC前端改造（ai-frontend-web）

#### 3.2.1 EditTradingBot.vue — 新增"手续费率"输入框

**文件：** `ai-frontend-web/.../trading/EditTradingBot.vue`

在"交易配置"区域新增：

```html
<el-form-item label="手续费率" prop="commissionRate">
  <el-input-number
    v-model="configForm.commissionRate"
    :min="0"
    :max="1"
    :step="0.0001"
    :precision="4"
    placeholder="0.0006"
    style="width: 100%"
  />
  <span class="form-item-hint">小数格式，如 0.0006 = 万分之6</span>
</el-form-item>
```

- 默认值：`0.0006`
- 添加校验规则：`required + 正值`

#### 3.2.2 初始化与加载

- **新建机器人：** `configForm.commissionRate` 默认为 `0.0006`
- **编辑已有机器人：** 加载 `bot_parameter` 的 `config` 分组数据，回填 `commissionRate`
- **提交保存：** 在 `saveBotParameters` 的 `config` 分组中，加入 `commission_rate` 字段

### 3.3 H5前端改造（lxaiquant-mobile）

#### 3.3.1 BotFromIndicator.vue — 新增"手续费率"输入框

**文件：** `lxaiquant-mobile/src/views/trading/BotFromIndicator.vue`

**步骤1：表单数据中新增 `commissionRate` 字段**

在 `data()` 中的 `form` 对象内新增字段（第275-294行）：

```javascript
form: {
    // ... 现有字段 ...
    commission: 0.05,
    slippage: 0.02,
    commissionRate: 0.00045,   // 新增：手续费率，小数格式，如 0.00045 = 万分之4.5
    enableAiFilter: false
},
```

**步骤2：模板中新增输入框**

在"风险参数"折叠面板的"基础风险"区域（第186-196行）新增，放在 `slippage` 字段之后、`enableAiFilter` 之前：

```html
<van-field v-model.number="form.commissionRate" type="number" :label="$t('indicator_bot.commission_rate')" />
```

需要新增 i18n 翻译条目（如 H5 使用 i18n）：

```javascript
// 在对应的语言包中新增
commission_rate: '手续费率'
```

或如果 H5 不使用 i18n，直接使用中文 label。

**步骤3：编辑回填逻辑**

在 `mounted()` 中加载 `bot_parameter.config` 后回填（第396-447行），在现有的 `applyProps` 函数中新增：

```javascript
const applyProps = (data) => {
    // ... 现有字段 ...
    if (data.slippage != null) this.form.slippage = Number(data.slippage)
    if (data.commission_rate != null) this.form.commissionRate = Number(data.commission_rate)  // 新增
    if (data.enable_ai_filter != null) this.form.enableAiFilter = !!data.enable_ai_filter
}
```

**步骤4：提交保存逻辑**

在 `submit()` 方法的 `configData` 中新增（第712-720行）：

```javascript
const configData = {
    entry_pct: Number(this.form.entryPct) || 0,
    trailing_enabled: !!this.form.trailingEnabled,
    // ... 现有字段 ...
    commission: Number(this.form.commission) || 0,
    slippage: Number(this.form.slippage) || 0,
    commission_rate: Number(this.form.commissionRate) || 0.0006,  // 新增
    enable_ai_filter: !!this.form.enableAiFilter
}
```

**步骤5：只读模式处理**

如果机器人非本人创建（只读模式），手续费率字段应与其他参数一同灰选，无需额外处理（已在只读模式下整体禁用交互）。

#### 3.3.2 提示文字（可选）

可在手续费率输入框下方添加说明文字，类似于 PC 端的"小数格式，如 0.0006 = 万分之6"。H5 的 `van-field` 支持 `extra` 插槽或使用紧随的 `div` 实现。

## 4. 影响范围

| 模块 | 影响 | 改动量 |
|------|------|--------|
| ai-order | TradeOrderServiceImpl.getFeeRateByPlatform 新增参数，新增 CommissionRateHelper | 中等 |
| ai-quant | BacktestController 调用链路调整，LiveTradingServiceImpl 透传 botId | 小 |
| ai-strategy | TradingBotController 新增读取 config 接口 | 小 |
| ai-frontend-web | EditTradingBot.vue 新增输入框 + 保存/加载逻辑 | 中等 |
| lxaiquant-mobile | BotFromIndicator.vue 新增手续费率字段 + 保存/加载逻辑 | 小 |

**不涉及：**
- 数据库表结构变更（复用 `bot_parameter`）
- ta4j、XChange 等第三方库
- `vdr-h5` 项目（不改代码）

## 5. 兼容性

| 场景 | 行为 |
|------|------|
| 旧机器人无 `commission_rate` | 后端使用 ThreadLocal（回测）或兜底 0.00045（实盘），行为不变 |
| 回测页面未传 `commissionRate` | 优先读 `bot_parameter`，次之使用兜底 0.00045 |
| 新建机器人未设置费率 | 默认 `0.0006`，保存到 `bot_parameter` |
| H5 保存的费率与 PC 端共用 `bot_parameter.config` 分组 | 两端编辑同一机器人时，费率字段互相覆盖，保持一致 |
