## 五、Phase 5：权重增强接入（ai-signal）（已完成）

> 方案（V4.0 + 三决策定稿）：
> - 复用现有 `WeightRuleEngine` + SPI 指标 + 运算符扩展，**放弃硬编码 5+1 因子**
> - 权重语义：**加法评分**（VETO/SCORING）+ STEP 映射回 `[0, 2.0]`，不做乘法放大
> - 分位数运算符拆两组：`*_ABS_PERCENTILE`（比 abs_space 分位）、`*_RATIO_PERCENTILE`（比 space/cumRatio 分位）
> - 时间上下文：`WeightRuleContext` 增加 `currentTimeMs`，`waitMinutes` 由 getter 动态计算；回测由 `BacktestContextHolder` 注入，实盘用 `System.currentTimeMillis()`

## 七、Phase 7：回测接入（ai-engine）（方案已定：离线重算）

> 方案A：回测不实时调 `WeightRuleEngine`（现状 `SignalScriptStrategy` 读 `technical_signal` 存量权重）。改为回测前离线重放历史信号，用 `BacktestFeatureProvider` + `WeightRuleEngine` 重算 `signal_strength`，再喂给 `SignalCacheManager`。

| 任务 | 说明 | 优先级 |
|------|------|--------|
| 7.1.1 时间上下文 | 复用 Phase 5 的 `BacktestContextHolder`，离线重算时逐笔 setCurrentTime | P0 |
| 7.1.2 离线重算器 | 新增历史权重重算逻辑：`BacktestFeatureProvider.loadHistory` 预计算特征，按时间重放历史信号，逐笔用 `WeightRuleEngine`（注入历史时间）重算 `signal_strength` | P0 |
| 7.1.3 权重写回 | 重算结果写入回测内存缓存，供 `SignalCacheManager`/`SignalScriptStrategy` 读取（不回写 `technical_signal` 表，避免污染实盘数据） | P0 |
| 7.1.4 回测入口接入 | `ai-engine` 的 `BacktestService` 回测开始前触发重算 | P0 |
| 7.1.5 依赖确认 | ai-engine 已依赖 ai-signal（pom 已确认） | P1 |
