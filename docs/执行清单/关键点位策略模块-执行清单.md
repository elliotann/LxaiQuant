## 待办：后续优化项（当前保持旧逻辑，后续改造）

> 以下功能在[关键点位策略模块设计文档](../设计文档/市场行情菜单指标/关键点位策略模块设计文档.md)中已规划，但**当前实现仍使用旧逻辑**，待后续改造：

### T1：关键点位计算接入新 21 种复合状态

| 当前状态 | 目标 |
|---------|------|
| `DefaultIndicatorCriticalLevelsStrategy.resolveDirection()` / `resolveEntryObFilter()` 使用 7 种旧 `trendState` 做精确匹配（`equals("强下降")` 等） | 改为基于 `CompositeState` 枚举判断，更精确地识别趋势阶段，调整入场 OB 过滤和方向推导 |
| `SmcCriticalLevelsCalculator.buildByDirection()` 中基于 `swingTrend` 和价格位置做固定规则入场/止损/止盈 | 可结合 `CompositeState` 微调入场 OB 过滤策略（如 `STRONG_BULLISH_HEALTHY` 用 `INTERNAL_ONLY`，`BULLISH_PULLBACK_BOTTOMING` 用 `SWING_ONLY`） |

**涉及文件**：
- [ ] `DefaultIndicatorCriticalLevelsStrategy.java` — 改为接收 `CompositeState` 做判断
- [ ] `DefaultSignalCriticalLevelsStrategy.java` — 同理
- [ ] 设计文档中 `CriticalLevelsConfig` 可扩展复合状态相关配置字段

### T2：新增移动止损管理器（SmcTrailingStopManager）

| 文档规划 | 当前实现 |
|---------|---------|
| 基于 ATR + 关键点位的动态移动止损管理器 | ❌ 尚未实现 |
| 支持按 `CompositeState` 切换止损模式（健康趋势用宽松止损，回调/末端用紧止损） | ❌ 尚未实现 |

**涉及文件**（规划中的新模块）：
- [ ] `ai-extension/.../SmcTrailingStopManager.java` — 移动止损核心管理器
- [ ] `InitialStopOffsetConfig.java` — 初始止损偏移配置（文档中已有定义但未实现）

### T3：关键点位策略可配置化（CriticalLevelsConfig 扩展）

| 当前 | 目标 |
|-----|------|
| `SmcCriticalLevelsCalculator` 中参数为硬编码常量 | 通过 `CriticalLevelsConfig` POJO 可由不同策略注入不同参数 |
| 所有策略共用同一套参数 | 支持按 robotId 配置不同的 `entryObTypeFilter`、`maxEntryDistancePct`、`stopLossFactor` 等 |

**涉及文件**：
- [ ] `CriticalLevelsConfig.java` — 已有 POJO 但未实际被策略读取使用
- [ ] `IndicatorStrategyRouter` / `SignalStrategyRouter` — 支持传入配置

### 时间线建议

```
短期（当前）:  保持旧逻辑，新增 compositeState 只看板展示，互不影响 ✅
中期（下一轮）: T1 关键点位接入 CompositeState
长期（后续）:  T2 移动止损管理器 + T3 可配置化
```
