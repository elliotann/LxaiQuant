量化交易系统日内风控模块完整设计文档

## 0. 现状与范围（重要）

这份文档的主体内容描述的是“会员级日内净值监控 + 状态机 + 订单前置拦截 + 熔断强平 + 权益曲线记录”的完整方案，但当前 `ai-risk` 模块代码实现的核心是“通用信号质量评估与仓位调节系统”，并不包含：

- 会员级总权益/当日盈亏的实时汇总与 Redis 状态持久化
- 订单执行链路的前置拦截（在发往交易所前拦截 TradingStrategyParams）
- 熔断后的撤单/强平执行（依赖订单服务与持仓查询）
- 回测/实盘的权益曲线落库（回测结果/净值曲线表）

也就是说：本文档当前更像是“会员级日内风控总体设计草案”，而不是 `ai-risk` 代码的实现说明文档。若团队目标是将这套会员级日内风控能力沉淀到 `ai-risk` 并被其他模块调用，则需要在 `ai-risk` 内补齐相应实现，并通过接口（Port/SPI）与订单/账户/行情等模块解耦对接。

下面先给出“基于 `ai-risk` 代码的对齐版实现架构”，以及“为了让会员级日内风控也落到 `ai-risk` 需要补齐的要点清单”；原文档主体内容保留在后续章节作为“目标能力说明”，但需要按实际接口与数据结构进行改写。

### 0.2 需要修改/补齐的关键点（基于代码核对）

1. **模块边界需要改写**：本文档中“会员级权益监控、订单前置拦截、强平执行、权益曲线表”均未在 `ai-risk` 实现；若目标是统一沉淀到 `ai-risk`，需要在 `ai-risk` 内实现这些能力，并用接口与外部系统交互（避免 `ai-risk` 直接依赖 `ai-engine/ai-order` 的具体实现细节）。
2. **TradingStrategyParams 字段表需要纠正**：文档提到的 `memberId`、`stopProfitPrice`、`initBalance`、`taskId` 在当前对象中并不存在或命名不同。实际对象请以 [TradingStrategyParams](file:///f:/project/lenzeto/ai-common/src/main/java/com/chain/ai/trade/common/entity/param/TradingStrategyParams.java) 为准：  
   - `memberId`：无（当前是 `accountId`、`memberPlatform` 等）  
   - 止盈：`takeProfitPrice`（不是 `stopProfitPrice/stopProfitPrice`）  
   - 测试模式：`testMode`  
3. **熔断语义需要区分**：本文档的 STOP 是“亏损熔断并强平”；而 `ai-risk` 的熔断器是“失败率熔断”，用于保护系统调用链稳定性，两者不是同一概念。
4. **状态机与存储需要重写**：本文档的 `MemberRiskState`/Redis 持久化在 `ai-risk` 不存在；`ai-risk` 主要用 `RiskControlContext` 进行一次性决策，不维护会员日内状态。
5. **“权益曲线记录”章节需要实现或改写为 Port**：净值曲线表 `backtest_equity_curve` 目前由 `ai-backtest` 模块维护（含建表 SQL 与 MyBatis-Plus Service），`ai-risk` 本身尚未实现落库与查询逻辑。若要将权益曲线能力收敛到 `ai-risk`，建议在 `ai-risk` 定义 `EquityCurveRepositoryPort` 接口（Port），由外部模块提供具体实现（MyBatis/消息队列/异步批量等），或将现有 `ai-backtest` 的表与服务迁移到 `ai-risk`。

### 0.3 目标架构：会员级日内风控落到 ai-risk（推荐落地方式）

为了把“会员级日内风控（净值监控/状态机/拦截/强平/曲线记录）”统一沉淀在 `ai-risk`，同时避免 `ai-risk` 和 `ai-engine/ai-order/ai-member/ai-xchange-extends` 产生循环依赖，建议采用 Port/SPI 解耦：

- `ai-risk` 负责：
  - 会员级风控状态机与状态转移
  - 订单前置风控校验（入参可继续使用 TradingStrategyParams，但需补齐 memberId 或提供解析器）
  - 熔断决策与“强平指令编排”（撤单/平仓的编排逻辑）
  - 权益曲线采样逻辑（何时采样、如何计算、如何批量写入）
- `ai-risk` 通过 Port 与外部交互（由 `ai-engine/ai-order/ai-member` 提供 Bean 实现）：
  - `MemberResolverPort`：通过 `accountId/robotId` 解析 `memberId`
  - `AccountSnapshotPort`：获取账号权益/余额/持仓快照（含当日已实现/浮动盈亏的必要字段）
  - `OrderExecutionPort`：撤单、查询持仓、平仓（强平执行的具体动作）
  - `RiskConfigPort`：加载会员风控配置（DB/缓存/后台配置系统）
  - `RiskStateStorePort`：保存/读取会员日内状态（Redis/内存）
  - `EquityCurveRepositoryPort`：权益曲线落库（同步/异步/批量）

这样其他模块“只依赖 ai-risk 的接口和实现”，但不需要把数据库表、交易所细节、订单服务细节硬编码进 ai-risk。

## 1. 目标能力说明（需要按 ai-risk 代码与 Port 结构改写）

以下为会员级日内风控的目标能力正文。落地到 `ai-risk` 时，需要用 0.3 的 Port 结构替换其中对具体系统/表/服务的直接依赖描述。
1. 引言
   1.1 背景
   量化交易系统运行过程中，可能因极端行情、策略逻辑缺陷或外部异常导致单日亏损超限，危及会员整体资金安全。为防范此类风险，并完整记录策略表现（包括回测与实盘），需要建立多层次的风控体系与净值记录机制。其中，交易引擎内控层作为第一道防线，负责实时监控会员整体权益、管理交易权限，并在订单发出前进行合规校验；同时，系统需要能够记录净值曲线，供策略分析、绩效评估与风险回溯使用。

1.2 目标
会员级风险控制：以会员为单位，实时监控所有关联账号的总体权益，确保会员整体当日亏损不超过预设阈值。

实时监控：毫秒级感知会员总权益与当日盈亏变化。

状态控制：根据预设阈值自动切换交易状态（正常/预警/熔断/止盈锁定），精准控制交易权限。

事前拦截：在订单发出前评估新订单带来的风险敞口，防止风险累积。

净值曲线记录：在回测和模拟实盘测试中，按K线粒度记录权益曲线，支持后续绩效分析。

高性能：风控逻辑对主交易流程的延迟影响控制在微秒级。

可配置：风控参数通过后台系统动态配置，支持热更新，无需重启服务。

1.3 范围
本设计文档覆盖以下内容：

会员级风控参数配置与管理

实时净值监控器（多账号汇总）

权限状态机

订单前置拦截器

熔断执行（强制平仓与锁定）

权益曲线记录（回测与测试模式）

与现有交易引擎（IDealStrategyBasic/DefaultDealStrategyTrade）的集成方案

复用现有 TradingStrategyParams 作为订单请求对象

2.1 组件职责
2.1.1 实时净值监控器
职责：持续计算会员所有账号的总权益、当日已实现盈亏、浮动盈亏。

触发方式：

实盘模式：定时器触发（默认 1~5 秒可配置），主动获取账户数据。

测试模式：不启用独立定时器，权益计算在策略循环中同步完成。

数据来源：

通过交易服务适配器获取会员下各账号的资产快照（余额、保证金、持仓市值）。

实时行情（用于计算浮动盈亏）。

2.1.2 状态机管理器
职责：维护会员当前交易状态，并根据净值监控器的输出驱动状态转移。

状态定义：

ACTIVE：正常交易，可开仓、平仓。

WARNING：预警状态，仅允许平仓，拒绝所有新开仓请求。

STOP：熔断状态，强制平掉所有持仓后，拒绝所有交易指令（包括平仓），并锁定交易接口。

PROFIT_LOCKED：止盈锁定状态，仅允许平仓，拒绝新开仓（由盈利目标触发）。

2.1.3 订单前置拦截器
职责：在策略生成的订单被发送至交易所之前，执行一系列校验。

校验项目：

状态检查：当前会员交易状态是否允许该类型操作（开仓/平仓）。
潜在亏损检查：对于开仓订单，预估该笔订单在立即止损情况下可能导致的最大亏损，并校验该亏损是否会使当日总亏损突破硬止损阈值。
敞口检查：当前持仓总风险敞口是否超过基于剩余亏损额度计算出的允许敞口上限。
2.1.4 风控参数管理器
职责：加载并热更新会员级风控配置，提供配置查询接口。

2.1.5 权益曲线记录器
职责：在回测或模拟实盘测试模式下，记录每个K线结束时的净值，用于后续绩效分析。

记录时机：每个Bar处理完成后（即每次execStrategy循环迭代结束）。

数据来源：根据当前持仓和市场价格计算总权益（按市值计价）。

4.3 状态机转移规则
java
private void maybeTransitionState(Long memberId, MemberRiskState state, MemberRiskConfig config) {
RiskStatus oldStatus = state.getStatus();
double lossRatio = state.getDailyTotalPnlRatio().doubleValue();
double profitRatio = lossRatio; // 正数为盈利

    RiskStatus newStatus = oldStatus;
    switch (oldStatus) {
        case ACTIVE:
            if (lossRatio <= -config.getStopRatio().doubleValue()) {
                newStatus = RiskStatus.STOP;
                forceStop(memberId);
            } else if (lossRatio <= -config.getWarningRatio().doubleValue()) {
                newStatus = RiskStatus.WARNING;
            } else if (profitRatio >= config.getProfitTargetRatio().doubleValue()) {
                newStatus = RiskStatus.PROFIT_LOCKED;
            }
            break;
        case WARNING:
            if (lossRatio <= -config.getStopRatio().doubleValue()) {
                newStatus = RiskStatus.STOP;
                forceStop(memberId);
            } else if (profitRatio >= config.getProfitTargetRatio().doubleValue()) {
                newStatus = RiskStatus.PROFIT_LOCKED;
            }
            break;
        case PROFIT_LOCKED:
            // 如果从盈利回撤到亏损预警线以下，可选择转为WARNING或保持锁定
            // 默认保持锁定直至收盘
            break;
        case STOP:
            // 不会自动转移，需每日结算时重置
            break;
    }

    if (newStatus != oldStatus) {
        state.setStatus(newStatus);
        saveToRedis(state);
        log.info("风控状态变更: {} -> {}, member={}, lossRatio={}", oldStatus, newStatus, memberId, lossRatio);
    }
}

实时净值监控器通过 ITradeOrderServiceAdapter 获取各账号的快照，汇总计算。

5.2 计算逻辑
获取会员下所有账号列表（可从会员服务获取）。

遍历账号，调用交易所API或本地缓存获取账户资产和持仓。

计算每个账号的浮动盈亏：持仓市值 - 持仓成本。

汇总总权益 = 各账号余额 + 持仓市值。

当日已实现盈亏 = 从结算后累计的平仓盈亏（可通过数据库或本地累计）。

当日总盈亏 = (当前总权益 - 初始权益) + 当日已实现盈亏（注意避免重复）。

更准确：当日总盈亏 = 当前总权益 - 初始权益（因为初始权益已包含资金和历史持仓的昨日盈亏）。

5.3 初始化与定时器
实盘模式：系统启动后，启动一个定时器（默认 1~5 秒，可配置），周期性调用净值监控器更新风控状态。

测试模式：不启动定时器。权益计算与记录在策略循环中完成。

public RiskCheckResult preOrderCheck(TradingStrategyParams params) {
// 1. 获取会员风控状态和配置
MemberRiskState state = getRiskState(params.getMemberId());
MemberRiskConfig config = getRiskConfig(params.getMemberId());

    // 2. 状态检查（开仓/平仓判断）
    boolean isOpen = isOpenOrder(params); // 根据上下文或参数标志判断
    RiskStatus status = state.getStatus();
    if (status == RiskStatus.STOP) {
        return RiskCheckResult.reject("系统已熔断，禁止任何交易");
    }
    if (status == RiskStatus.WARNING && isOpen) {
        return RiskCheckResult.reject("预警状态，禁止开仓");
    }
    if (status == RiskStatus.PROFIT_LOCKED && isOpen) {
        return RiskCheckResult.reject("已达盈利目标，禁止开仓");
    }

    // 3. 潜在亏损检查（仅开仓）
    if (isOpen) {
        BigDecimal estLoss = estimateMaxLoss(params, config);
        BigDecimal stopLossAmount = state.getInitialEquity().multiply(config.getStopRatio());
        if (state.getDailyTotalPnl().add(estLoss).compareTo(stopLossAmount.negate()) < 0) {
            return RiskCheckResult.reject("该订单预估亏损将导致突破硬止损线");
        }
    }

    // 4. 敞口检查（可选，根据剩余亏损预算限制总敞口）
    if (isOpen) {
        BigDecimal currentExposure = calculateTotalExposure(params.getMemberId(), params.getSymbol());
        BigDecimal maxAllowedExposure = state.getRemainingLossBudget()
                .divide(config.getRiskPerExposure(), 6, RoundingMode.HALF_UP);
        BigDecimal newExposure = currentExposure.add(estimateOrderExposure(params));
        if (newExposure.compareTo(maxAllowedExposure) > 0) {
            return RiskCheckResult.reject("新订单将超过允许的风险敞口上限");
        }
    }

    return RiskCheckResult.pass();
}
6.3 预估亏损计算
从 TradingStrategyParams 中提取止损信息：优先使用 stopLossPrice，若为 null 则使用配置的默认止损百分比。

java
private BigDecimal estimateMaxLoss(TradingStrategyParams params, MemberRiskConfig config) {
BigDecimal price = params.getPrice();
BigDecimal quantity = params.getAmount();
BigDecimal contractMultiplier = getContractMultiplier(params.getSymbol());

    BigDecimal stopLossPercent;
    if (params.getStopLossPrice() != null && price != null) {
        // 根据止损价计算百分比
        if ("BUY".equals(params.getSide())) {
            stopLossPercent = price.subtract(params.getStopLossPrice())
                    .divide(price, 6, RoundingMode.HALF_UP);
        } else {
            stopLossPercent = params.getStopLossPrice().subtract(price)
                    .divide(price, 6, RoundingMode.HALF_UP);
        }
    } else {
        stopLossPercent = config.getDefaultStopLossPercent();
    }

    BigDecimal loss = quantity.multiply(price)
            .multiply(stopLossPercent.add(config.getSlippagePercent()))
            .multiply(contractMultiplier);
    return loss;
}

public void forceStop(Long memberId) {
MemberRiskState state = getRiskState(memberId);
if (state.getStatus() == RiskStatus.STOP) return; // 已熔断

    state.setStatus(RiskStatus.STOP);
    saveToRedis(state);

    // 获取会员所有账号
    List<String> accountIds = getMemberAccounts(memberId);
    for (String accountId : accountIds) {
        try {
            // 撤销所有未成交订单
            tradeOrderServiceAdapter.cancelAllOrders(accountId, null);
            // 平仓所有持仓
            List<OrderVO> positions = tradeOrderServiceAdapter.getPositionOrders(accountId, null);
            for (OrderVO order : positions) {
                tradeOrderServiceAdapter.closeOrderByVolume(order.getOrderSn(), order.getVolume(), null, null, null);
            }
            log.info("会员 {} 账号 {} 强制平仓完成", memberId, accountId);
        } catch (Exception e) {
            log.error("会员 {} 账号 {} 强制平仓失败", memberId, accountId, e);
            // 持续重试或告警
        }
    }
    // 发送紧急告警
    sendAlert(memberId, "强制熔断已触发，所有持仓已平仓");
}

8.3 权益计算方法
在测试模式下，权益基于策略的 TradingRecord 和当前价格计算，公式为：

text
当前净值 = 初始资金 + 已实现盈亏 + 浮动盈亏
初始资金：从 TradingStrategyParams.getInitBalance() 获取。

已实现盈亏：从 TradingRecord.getTotalProfit() 获取。

浮动盈亏：遍历 TradingRecord 中未平仓持仓，按当前收盘价计算盈亏。

java
private BigDecimal calculateEquity(BarSeries series, int endIndex, TradingRecord record, BigDecimal initialCapital) {
Bar bar = series.getBar(endIndex);
BigDecimal currentPrice = BigDecimal.valueOf(bar.getClosePrice().doubleValue());
BigDecimal realizedPnl = BigDecimal.valueOf(record.getTotalProfit().doubleValue());
BigDecimal unrealizedPnl = BigDecimal.ZERO;

    for (Position pos : record.getPositions()) {
        if (pos.isOpened()) {
            BigDecimal entryPrice = BigDecimal.valueOf(pos.getEntry().getPrice().doubleValue());
            BigDecimal quantity = BigDecimal.valueOf(pos.getEntry().getAmount().doubleValue());
            if (pos.getEntry().getSide() == ExecutionSide.BUY) {
                unrealizedPnl = unrealizedPnl.add(currentPrice.subtract(entryPrice).multiply(quantity));
            } else {
                unrealizedPnl = unrealizedPnl.add(entryPrice.subtract(currentPrice).multiply(quantity));
            }
        }
    }
    return initialCapital.add(realizedPnl).add(unrealizedPnl);
}

10. ta4j 0.22.2 的权益曲线能力评估
    ta4j 0.22.2 引入了 OpenPositionHandling 和 PerformanceIndicator 标准化，可在回测中计算包含浮动盈亏的净值曲线。但该功能仅限于回测分析，不负责实时监控或数据库写入。因此：

回测场景：可以利用 PerformanceIndicator 获取每个K线的净值，然后自行写入 backtest_equity_curve 表。这比手动计算更便捷，但需注意 PerformanceIndicator 的 getValue(i) 返回的是累计收益率，需要转换为净值。

实盘场景：仍需通过 NetValueMonitor 从交易所获取真实账户数据，ta4j 的功能不适用。

我们决定在回测中优先使用自定义权益计算方法，因为这样可以与风控模块的 MemberRiskState 保持一致逻辑，且不依赖 ta4j 的内部实现细节。但也可保留使用 PerformanceIndicator 作为备选方案。

12. 异常处理与容错
    账户数据获取失败：净值监控器重试3次，仍失败则使用上次缓存状态，记录告警。

Redis 不可用：使用内存缓存，但状态无法持久化，重启后需人工确认。

强制平仓部分失败：记录失败订单，持续重试，并发送紧急告警。

分布式锁：在熔断时使用分布式锁防止并发平仓。

数据库写入失败：权益曲线记录采用异步写入，失败时记录日志，不影响策略执行。

15. 总结
    本设计文档描述了基于会员级的量化交易系统日内风控模块，以及权益曲线记录机制。通过实时监控会员整体权益、管理状态机、订单前置拦截、熔断执行，有效防范了单日亏损超限风险；同时在回测和模拟测试中完整记录净值曲线，为策略分析提供数据支持。风控参数通过后台动态配置，支持热更新，且与现有交易引擎低耦合集成。该设计既满足了风控的严格要求，又保证了系统的灵活性和高性能。
