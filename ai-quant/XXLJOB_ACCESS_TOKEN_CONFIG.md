# XXLJOB 访问令牌配置指南

## 🔐 问题描述

当执行 XXLJOB 任务时遇到错误：`The access token is wrong.`

这是因为 XXLJOB 管理后台和执行器之间的访问令牌不匹配导致的。

## ⚙️ 解决方案

### 1. 配置执行器访问令牌

已在 `application.yml` 中配置：

```yaml
xxl:
  job:
    accessToken: ai-quant-token
```

### 2. 配置管理后台访问令牌

#### 方法一：通过管理后台界面配置

1. 登录 XXLJOB 管理后台：http://localhost:9002/xxl-job-admin
2. 点击左侧菜单 **"执行器管理"**
3. 找到 `ai-quant-executor` 执行器
4. 点击 **"编辑"** 按钮
5. 在 **"AppName"** 字段后找到 **"Access Token"** 字段
6. 输入令牌：`ai-quant-token`
7. 点击 **"保存"**

#### 方法二：通过数据库配置

如果无法通过界面配置，可以直接修改数据库：

```sql
UPDATE xxl_job_group
SET access_token = 'ai-quant-token'
WHERE app_name = 'ai-quant-executor';
```

## 🔍 验证配置

### 1. 检查执行器注册状态

1. 在管理后台的 **"执行器管理"** 页面
2. 查看 `ai-quant-executor` 的状态
3. 应该显示注册成功，地址列表不为空

### 2. 测试任务执行

1. 进入 **"任务管理"** 页面
2. 选择任一任务，点击 **"执行一次"**
3. 如果成功，会看到执行日志

## 📋 配置说明

### 令牌匹配规则

- **管理后台令牌**: 在执行器配置中设置的 Access Token
- **执行器令牌**: 在 `application.yml` 中配置的 `xxl.job.accessToken`
- **匹配条件**: 两个令牌必须完全一致（包括大小写）

### 安全建议

1. **生产环境**: 使用复杂的随机字符串作为令牌
2. **定期更换**: 定期更换访问令牌以增强安全性
3. **不同环境**: 为不同环境使用不同的令牌

## 🚨 常见问题

### Q: 配置了令牌还是报错？
**A**: 检查以下几点：
1. 确保重启了应用使配置生效
2. 确认管理后台和执行器的令牌完全一致
3. 检查是否有特殊字符或空格

### Q: 如何禁用令牌验证？
**A**: 将令牌设置为空字符串：
```yaml
xxl:
  job:
    accessToken:  # 留空禁用验证
```

### Q: 令牌的作用是什么？
**A**: 访问令牌用于验证执行器的合法性，防止未授权的执行器注册到管理后台，提供基本的安全保障。

## ✅ 配置完成

按照上述步骤配置后，XXLJOB 任务应该能够正常执行，不再出现访问令牌错误。
