# 市场数据菜单前后端逻辑文档

## 一、概述

市场数据菜单是交易系统的核心功能模块，提供K线图表展示、技术指标分析、交易信号显示、回测功能等。本文档详细描述了前后端的交互逻辑、数据流程和API接口。

## 三、后端API接口

### 3.1 K线数据接口

#### 3.1.1 获取K线数据

**接口路径**: `POST /api/kline/data`

**控制器**: `KLineDataController.getKlineData()`

**请求参数**:
```json
{
  "symbol": "ETH-USDT-SWAP",
  "interval": "OKXMIN3",
  "size": 200,
  "memberId": "",
  "thirdAccountId": "",
  "memberPlatform": "OKX",
  "indicatorType": "OKX-ETH-USDT202405121789571050845601792",
  "pageNumber": 1,
  "pageSize": 200
}
```

**响应格式**:
```json
{
  "success": true,
  "data": {
    "klineDatas": [
      {
        "id": 1704067200000,
        "openPrice": 2500.0,
        "highPrice": 2510.0,
        "lowPrice": 2495.0,
        "closePrice": 2505.0,
        "volume": 1000.0,
        "timeStr": "2024-01-01 00:00:00"
      }
    ],
    "count": 200,
    "symbol": "ETH-USDT-SWAP",
    "interval": "OKXMIN3"
  },
  "message": "查询成功"
}
```

**业务逻辑**:
1. 解析前端参数，构建 `KlineParam` 查询对象
2. 转换时间间隔枚举值（如 `OKXMIN3`）
3. 调用 `candlestickService.getKlines4KChart()` 查询K线数据
4. 返回符合前端期望格式的数据

#### 3.1.2 获取增量K线数据

**接口路径**: `GET /api/kline/unshift`

**控制器**: `KLineDataController.getUnshiftData()`

**请求参数**:
```
memberId: (可选)
thirdAccountId: (可选)
symbol: ETH-USDT-SWAP
interval: OKXMIN3
dataInterval: 3m
memberPlatform: OKX
indicatorType: (可选)
pageNumber: 1
pageSize: 200
size: 1000
direction: LEFT (向左加载历史数据) / RIGHT (向右加载未来数据)
from: 1704067200 (秒级时间戳，可选)
to: 1704153600 (秒级时间戳，可选)
toTime: false
```

**响应格式**: 同 `getKlineData`

**业务逻辑**:
1. 前端发送的 `from` 和 `to` 是秒级时间戳
2. 后端转换为毫秒级时间戳（`from*1000`, `to*1000`）传递给服务层
3. 构建 `CandlestickRequest` 查询对象
4. 调用 `candlestickService.getByQry()` 查询数据
5. 返回增量K线数据

#### 3.1.3 获取最新K线数据

**接口路径**: `POST /api/kline/latest-data`

**控制器**: `KLineDataController.getLatestKlineData()`

**请求参数**: 同 `getKlineData`，但 `size` 通常为 1

**响应格式**: 同 `getKlineData`

**业务逻辑**: 用于实时刷新，获取最新一条K线数据

### 3.2 信号数据接口

#### 3.2.1 获取信号数据

**接口路径**: `GET /api/member/signals`

**控制器**: `SignalController.getSignalsData()`

**请求参数**:
```
memberId: (可选)
thirdAccountId: (可选)
symbol: ETH-USDT-SWAP
interval: OKXMIN3
dataInterval: 3m
indicatorType: 机器人ID (用于筛选技术信号)
memberPlatform: OKX
pageNumber: 1
pageSize: 50
from: 1704067200 (秒级时间戳，可选)
to: 1704153600 (秒级时间戳，可选)
```

**响应格式**:
```json
{
  "success": true,
  "result": [
    {
      "id": 1,
      "symbol": "ETH-USDT-SWAP",
      "signalType": "LB",
      "price": 2505.0,
      "description": "LB(80,0.85) (2490.0-2520.0)",
      "timestamp": 1704067200,
      "position": "overlay",
      "signalStrength": 80,
      "confidence": 0.85
    }
  ],
  "message": "查询成功"
}
```

**业务逻辑**:
1. 构建 `TechnicalSignalQuery` 查询对象
2. 调用 `technicalSignalService.pageTechnicalSignals()` 查询技术信号
3. 调用 `tradeSignalService.queryTradeSignalsByTimeRange()` 查询业务信号
4. 合并技术信号和业务信号
5. 转换为前端期望的格式（包含时间戳、信号类型、描述等）

**信号类型映射**:
- `LB` - Long Buy (多头开仓)
- `SB` - Short Buy (空头开仓)
- `LS` - Long Sell (多头平仓)
- `SS` - Short Sell (空头平仓)

## 四、数据流程

### 4.1 初始化流程

```
1. 组件挂载 (mounted)
   ↓
2. 加载机器人列表 (fetchRobots)
   ↓
3. 初始化 DataManager 和 SignalManager
   ↓
4. 加载初始K线数据 (loadInitialData)
   - 调用 POST /api/kline/data
   - 转换数据格式（时间戳、价格字段）
   - 设置 chartData
   ↓
5. 加载信号数据 (loadSignals)
   - 调用 GET /api/member/signals
   - 设置 signals
   ↓
6. 启动实时刷新 (startRealTimeUpdate)
   - 每2秒调用 getLatestKLineData()
   - 更新最新K线数据
```

### 4.2 K线数据加载流程

#### 4.2.1 初始加载

**触发时机**: 组件挂载后、交易对/周期切换时

**流程**:
```
1. loadInitialData()
   ↓
2. 构建请求参数
   - symbol: 当前选择的交易对
   - interval: 当前选择的周期（如 OKXMIN3）
   - size: 200 (初始加载200条)
   ↓
3. 调用 getklineData(params)
   ↓
4. 处理响应数据
   - 转换时间戳（毫秒 -> 秒）
   - 映射价格字段（openPrice -> open）
   - 按时间排序
   ↓
5. 更新 chartData
   ↓
6. 更新 DataManager 缓存
   ↓
7. 更新价格显示和最新K线信息
```

#### 4.2.2 按需加载（时间范围变化）

**触发时机**: 用户拖动图表、缩放图表时

**流程**:
```
1. 图表组件触发 time-range-change 事件
   ↓
2. onTimeRangeChange(from, to)
   ↓
3. loadMoreKlineDataIfNeeded(timeRange)
   ↓
4. DataManager.getBarsByTimeRange(from, to)
   - 检查缓存中是否已有数据
   - 计算缺失的时间范围
   - 调用 loadFromBackend() 加载缺失数据
   ↓
5. loadFromBackend(from, to)
   - 判断是历史数据还是最新数据
   - 历史数据: 调用 getUnshiftData()
   - 最新数据: 调用 getklineData()
   ↓
6. 合并数据并更新缓存
   ↓
7. 更新图表显示
```

#### 4.2.3 实时更新

**触发时机**: 每2秒定时刷新

**流程**:
```
1. startRealTimeUpdate() 启动定时器
   ↓
2. 每2秒调用 getLatestKLineData()
   ↓
3. 调用 POST /api/kline/latest-data (size=1)
   ↓
4. updateLatestKLine(newKLineData)
   - 如果时间相同: 更新最后一条K线
   - 如果时间更新: 添加新K线
   - 检查时间间隔，加载中间缺失数据
   ↓
5. 更新价格显示和图表
```

### 4.3 信号数据加载流程

**触发时机**: 
- 初始加载
- 机器人选择变化
- 时间范围变化（延迟加载，使用 requestIdleCallback）

**流程**:
```
1. SignalManager.loadSignals()
   ↓
2. 检查是否选择了机器人
   - 未选择: 返回空数组
   ↓
3. 构建请求参数
   - indicatorType: 机器人ID
   - symbol: 当前交易对
   - interval: 当前周期
   ↓
4. 调用 getSignalsData(params)
   ↓
5. 处理响应数据
   - 转换时间戳格式
   - 映射字段（description -> lable, technicalDirection -> signal）
   - 过滤时间范围外的信号（1年前到现在）
   - 按时间排序
   ↓
6. 更新 signals 缓存
   ↓
7. 通知图表组件更新信号显示
```

### 4.4 技术指标计算流程

**触发时机**: 用户切换指标开关时

**流程**:
```
1. 用户点击指标开关（如 onMacdToggle）
   ↓
2. 更新指标配置（macdConfig.enabled = true/false）
   ↓
3. 图表组件接收配置变化
   ↓
4. LightweightChart 组件内部计算指标
   - 使用 chartData 作为输入
   - 计算指标值（MACD、RSI、BOLL等）
   - 渲染到图表上
```

**指标类型**:
- **主图指标**: BOLL、反转确认、趋势强度信号、均线（EMA9/21/55/144）、超级趋势、SMC Lite、Range Filter
- **副图指标**: MACD、RSI、趋势强度表、反转后趋势强度、安第斯振荡器、多时间框架趋势

## 五、核心工具类

### 5.1 DataManager (数据管理器)

**文件位置**: `src/utils/kline/DataManager.js`

**职责**:
- K线数据的加载、缓存和管理
- 时间范围计算和缺失数据检测
- 数据去重和排序
- 性能优化（防抖、并发控制）

**核心方法**:
- `getBarsByTimeRange(from, to, forceLoad)`: 获取指定时间范围的数据
- `loadFromBackend(from, to)`: 从后端加载数据
- `getCachedData(from, to)`: 获取缓存中的数据
- `calculateMissingRanges(from, to, cachedData)`: 计算缺失的时间范围
- `updateCache(newData)`: 更新缓存

**数据缓存策略**:
- 使用滑动窗口，最多保留 2000 条数据
- 自动清理超出范围的数据
- 支持数据合并和去重

### 5.2 SignalManager (信号管理器)

**文件位置**: `src/utils/kline/SignalManager.js`

**职责**:
- 交易信号的加载和管理
- 信号时间戳转换和格式化
- 信号过滤和排序

**核心方法**:
- `loadSignals()`: 加载信号数据
- `loadSignalsByTimeRange(from, to)`: 按时间范围加载信号
- `getIntervalCode(interval)`: 转换周期代码

## 六、用户交互功能

```
1. 用户选择交易对 (onSymbolChange)
```

- 1小时 (OKXMIN60)
- 4小时 (OKX4HOUR)

**功能**: 选择机器人，用于筛选和显示对应的交易信号

**交互流程**:
```
1. 用户选择机器人 (onRobotChange)
   ↓
2. 加载该机器人的会员配置列表 (fetchMemberConfigs)
   ↓
3. 更新 SignalManager 的 robotId
   ↓
4. 重新加载信号数据 (loadSignals)
```

**API调用**:
- `getTradingBots()`: 获取机器人列表

### 6.3 时间跳转

**功能**: 跳转到指定时间点

**交互流程**:
```
1. 用户选择时间并点击跳转 (handleTimeJump)
   ↓
2. 转换时间为时间戳
   ↓
3. 调用图表组件的 jumpToTime() 方法
   ↓
```

**功能**: 图表右键菜单，支持开多、开空、添加警报等操作

**菜单项**:
- 开多 (handleBuyOrder)
- 开空 (handleSellOrder)
- 添加警报 (handleAddAlert)
- 查看详情 (handleViewDetails)

### 6.5 手动开单

**功能**: 通过右键菜单或按钮触发手动开单

**交互流程**:
```
1. 用户点击"开多"或"开空"
   ↓
2. 打开开单弹窗 (orderModalVisible = true)
   ↓
3. 用户填写订单信息
```

## 九、性能优化策略

### 9.1 数据加载优化

1. **滑动窗口**: 最多保留 2000 条K线数据，超出范围自动清理
2. **防抖机制**: 数据加载和信号加载使用防抖，避免频繁请求
3. **并发控制**: DataManager 限制最大并发加载数为 2
4. **缓存策略**: 已加载的数据缓存在 DataManager 中，避免重复请求
5. **按需加载**: 只在需要时加载缺失的数据，不一次性加载所有数据

### 9.2 信号加载优化

1. **延迟加载**: 使用 `requestIdleCallback` 在浏览器空闲时加载信号
2. **分页加载**: 初始加载 50 条信号，按需加载更多
3. **时间过滤**: 只加载合理时间范围内的信号（1年前到现在）

### 9.3 图表渲染优化

1. **数据验证**: 更新图表前验证数据有效性
2. **批量更新**: 合并多次数据更新，减少重绘次数
3. **拖动检测**: 用户拖动时暂停自动加载，拖动结束后再加载

## 十、错误处理

### 10.1 数据加载失败

**处理策略**:
- 显示错误提示
- 保留已有数据，不清空
- 记录错误日志

### 10.2 时间戳异常

**处理策略**:
- 检测并过滤未来时间的数据（超过当前时间30天）
- 自动清理异常数据
- 输出警告日志

### 10.3 API调用失败

**处理策略**:
- 重试机制（使用备用API）
- 降级处理（使用缓存数据）
- 用户提示

## 十一、时间戳处理

### 11.1 时间戳格式

- **后端存储**: 毫秒级时间戳（Long类型）
- **API传输**: 
  - K线数据: 毫秒级时间戳（`id` 字段）
  - 信号数据: 秒级时间戳（`klineTimestamp` 字段）
- **前端使用**: 秒级时间戳（TradingView标准）

### 11.2 时区处理

- **数据库存储**: UTC时间

- **前端显示**: 转换为 UTC+8（北京时间）显示
- **图表组件**: 使用 UTC 时间戳，显示时自动转换

### 11.3 时间戳转换工具

**文件位置**: `src/utils/TimezoneHelper.js`

**方法**:
- `normalizeTimestamp(timestamp)`: 标准化时间戳（统一转换为秒级）

## 十四、注意事项

### 14.1 时间戳处理

1. **统一使用秒级时间戳**: 前端统一使用秒级时间戳，与 TradingView 标准一致
2. **时区转换**: 显示时转换为 UTC+8（北京时间），但存储和传输使用 UTC
3. **异常数据检测**: 自动检测并清理未来时间的数据（超过当前时间30天）

### 14.2 数据同步

1. **实时更新**: 最新K线数据每2秒更新一次
2. **数据合并**: 新数据与已有数据自动合并，避免重复
3. **时间间隔检测**: 检测新K线与旧K线之间的时间间隔，自动加载中间缺失数据

### 14.3 性能考虑

1. **防抖机制**: 数据加载和信号加载使用防抖，避免频繁请求
2. **滑动窗口**: 限制最大数据量，自动清理超出范围的数据
3. **延迟加载**: 信号数据使用 `requestIdleCallback` 延迟加载
4. **拖动优化**: 用户拖动时暂停自动加载，拖动结束后再加载

### 14.4 错误处理

1. **API失败重试**: 使用备用API重试
2. **数据验证**: 更新前验证数据有效性
3. **异常数据清理**: 自动检测并清理异常数据
4. **用户提示**: 关键错误向用户显示提示信息
